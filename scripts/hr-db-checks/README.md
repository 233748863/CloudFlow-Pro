HR09 独立数据库事务检查

在工作区运行 `pwsh -NoProfile -File scripts/verify-batch-h-hr-db.ps1`。默认每类竞争执行 3 次，共 18 次；`-RaceRounds` 允许 1 至 10，`-KeepArtifacts` 保留独立编译文件。

- 7 组故障：SWAP 第二条排班及完成状态写入；调休台账、额度及完成状态写入；PAY 工资变动及完成状态写入。临时库的 AFTER 触发器主动返回 MySQL 1644 / SQLState 45000，观察真实 Mapper 执行，再用另一条只读连接检查整体回滚及已有成功结果不变。
- 6 组竞争：SWAP、调休、PAY 各覆盖重复消费者和过期失败记录。每次必须在 `performance_schema.data_lock_waits` 观察到指定临时库、指定表和两个不同连接之间的真实行锁等待；单纯同时启动线程不计数。
- 3 组来源保护：H 排班及班次/规则、待执行快照与普通无 H 排班对照；H 调休手工冲正；H 工资变动的普通新增、更新、改状态和删除。

隔离与编译

只加载既有连接文件，不输出或落盘密码、连接内容、令牌及工资。固定源为 `192.168.1.173:3306/cloud_flow_db`，前后要求 323 张表；只读取源库结构元数据。临时库名严格匹配 `hr09_verify_[a-f0-9]{32}`，不使用 `IF NOT EXISTS` 接管已存在库；复制空表结构，不复制数据，不省略原有触发器或外键后仍声称等价。

只读既有 HR 依赖清单，并使用本机已存在、同版本的 Spring WebSocket 编译期依赖。所有项目内部 JAR 和 `target/classes` 均从编译/运行路径排除。复制最新 HR/所需共享 Java 源码和 Mapper XML，逐文件核对 SHA256，在 `scripts/hr-db-checks/artifacts/hr09-db-[32hex]/` 独立编译。新增、删除或内容变化均使当前源码验证失败，须重新运行。无 Maven、服务重启、运行库导入或项目源码修改。

证据保存在每次运行的 `artifacts/hr09-db-[32hex]/`：`source-fingerprints.json`、`source.sha256`、`dependency-fingerprints.json`、`database-report.json`、`source-stability.json` 及摘要 `console.txt`。默认通过后删除该次编译目录和源码副本，保留证据；失败记录不会冒充通过。报告分别统计业务断言、隔离/接线断言、各组真实竞争数及脱敏 SQL 故障。

清理前核对独立库的随机所有权标记，删除后只读查询库、表、触发器数量均为 0，并比较源库结构指纹。任一清理或指纹核验失败都会返回非零退出状态。中止 Java 进程等异常终止不能视为已清理，须以实际报告中的清理结果为准。

明确边界

业务 Mapper、HR 服务、数据库锁、Spring 事务、加解密、审计及通知待发送记录均执行当前源码。已批准申请、规则、排班和加密的测试薪资由临时库业务夹具提供；调班快照由真实规划方法生成。这些夹具不计为在线提交、审批、核价或真实工资补正。

Redis = 外部缓存与协调锁服务；本检查仅以本地实现替代该外部边缘，配置值仍来自临时库。竞争时刻意让两个消费者使用不同的本地锁域，验证数据库本身能维持结果唯一，不能据此宣称真实 Redis 协调已经通过。通知实际写入临时库待发送表，不执行远程投递；远程工作流/业务规则接口一旦意外被调用立即失败。HTTP 登录权限、在线工作流、核价、工资补正、后台任务和真实 Redis 均不在本脚本验收范围内。
