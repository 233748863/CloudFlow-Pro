## 四、可移植条目

### [OA-01] 资产全生命周期（折旧 / 保险 / 维保 / 维修）
- **参考来源**：`frappe/erpnext` → `erpnext/assets/doctype/` 共 26 个 doctype（GPL-3.0，仅借鉴设计）。实测 `asset` 主体 52 字段
- **参考实现怎么做的**：
  - **折旧**：`calculate_depreciation(Check), depreciation_method, total_number_of_depreciations, frequency_of_depreciation, next_depreciation_date, opening_accumulated_depreciation, value_after_depreciation`，明细在 `asset_depreciation_schedule` + `depreciation_schedule`（逐期计划表），`finance_books` 支持一物多账（税务账 vs 会计账不同折旧法），`asset_value_adjustment` 处理价值调整
  - **保险**：`policy_number, insurer, insured_value, insurance_start_date, insurance_end_date, comprehensive_insurance`
  - **维保**：`maintenance_required(Check)` + `asset_maintenance`（挂 `maintenance_team` / `maintenance_manager`）+ `asset_maintenance_task`（周期性任务）+ `asset_maintenance_log`
  - **维修**：`asset_repair` 实测 20 字段，关键是 `downtime`（停机时长）、`repair_cost`、`increase_in_asset_life`（维修延长寿命）、`capitalize_repair_cost`（是否资本化）、`consumed_items`
  - **调拨**：`asset_movement` 带 `purpose`（Issue/Receipt/Transfer）+ 明细
  - **归属**：`custodian`（保管人）与 `asset_owner` 分离，`location` 独立主数据（`location` doctype 支持树形）
- **我们现状**：`oa_asset` 仅 18 列（`asset_code, name, category, model, status, price, purchase_date, owner_id, location, remark`）。资产买入后就是一条静态记录：不折旧、无保险、无维保计划、无维修记录、无停机统计。`oa_asset_log` 是通用日志，承担了调拨与状态变更但无结构化字段。`oa_consumable` 独立处理耗材。
- **落地改动**：
  - `oa_asset` 增：`asset_category_id, custodian_id/custodian_name（保管人，与 owner 分离）, dept_id, purchase_amount, salvage_value, useful_life_months, available_from_date, disposal_date, depreciation_flag, depreciation_method(STRAIGHT_LINE/DOUBLE_DECLINING/UNITS_OF_PRODUCTION), depreciation_frequency(MONTHLY/QUARTERLY/YEARLY), accumulated_depreciation, net_book_value, next_depreciation_date, insurance_policy_no, insurer_name, insured_value, insurance_start, insurance_end, maintenance_required_flag`
  - 新增 `oa_asset_category`（`category_code, category_name, parent_id, default_useful_life_months, default_depreciation_method, default_salvage_rate`）—— 分类主数据带折旧默认值
  - 新增 `oa_asset_depreciation_schedule`：`asset_id, period_no, period_date, depreciation_amount, accumulated_amount, net_value, status(PLANNED/POSTED), post_time`
  - 新增 `oa_asset_maintenance_plan` + `oa_asset_maintenance_task`（`plan_id, task_name, frequency(MONTHLY/QUARTERLY/YEARLY), next_due_date, assignee_id, last_completed_date`）
  - 新增 `oa_asset_repair`：`asset_id, repair_no, failure_date, completion_date, repair_status, description, actions_performed, downtime_hours, repair_cost, capitalize_flag, life_extension_months, supplier_id, instance_id`
  - 新增 `oa_asset_movement`：`asset_id, movement_no, purpose(ISSUE/RETURN/TRANSFER/SCRAP), from_custodian_id, to_custodian_id, from_location, to_location, movement_date, instance_id`（`oa_asset_log` 保留做通用变更日志）
  - 折旧过账定时任务；到期提醒复用现有 `oa_risk_alert` 与到期提醒机制（印章证照已有成熟模式，直接照搬）
  - API：`/oa/asset/depreciation/schedule|post`、`/oa/asset/maintenance-plan`、`/oa/asset/repair`、`/oa/asset/movement`
- **工作量**：L（1 表扩字段 + 5 新表 + 折旧引擎 + 定时任务）
- **优先级**：P0 —— 资产是 OA 里"表面有实际空"最严重的一块（18 列 vs 52 字段），且折旧是财务刚需

### [OA-02] 供应商评分与准入拦截
- **参考来源**：`frappe/erpnext` → `buying/doctype/supplier_scorecard` 及 8 个配套 doctype（`_criteria`、`_period`、`_scoring_criteria`、`_scoring_standing`、`_scoring_variable`、`_standing`、`_variable`）（GPL-3.0，仅借鉴）
- **参考实现怎么做的**：实测 `supplier_scorecard` 16 字段的关键设计：
  - `criteria`（评分标准表）+ `weighting_function`（加权公式）+ `supplier_score`（算出的分）+ `indicator_color`（红黄绿）
  - `standings`（分档，如"优秀/合格/观察/淘汰"）
  - **关键**：`warn_rfqs, warn_pos, prevent_rfqs, prevent_pos` —— 分数低时**警告或直接阻止**给该供应商发询价/下采购单，评分不是摆设而是真拦截
  - `notify_supplier, notify_employee` 分数变动通知
  - `period` 按周期重算（`supplier_scorecard_period`）
- **我们现状**：`oa_supplier` 仅 14 列（`supplier_name, contact_name, contact_phone, bank_name, bank_account, status`）。没有资质、没有分类、没有评分、没有黑名单。采购申请（`biz_purchase_request` 33 列，已有 supplier 快照字段）可以选任意状态正常的供应商。
- **落地改动**：
  - `oa_supplier` 增：`supplier_code, supplier_type, category_id, credit_code(统一社会信用代码), legal_person, register_capital, address, business_scope, qualification_expire_date, cooperation_start_date, level_code, score DECIMAL(5,2), standing(EXCELLENT/QUALIFIED/WATCH/BLACKLIST), blacklist_flag, blacklist_reason, prevent_purchase_flag`
  - 新增 `oa_supplier_qualification`：`supplier_id, qualification_type(BUSINESS_LICENSE/TAX/ISO/INDUSTRY_PERMIT), cert_no, issue_date, expire_date, file_url, verify_status` —— 到期提醒复用现有证照到期提醒机制（`oa_license_expiry_reminder_log` 的模式）
  - 新增 `oa_supplier_scorecard`：`supplier_id, period_type, period_start, period_end, total_score, standing, indicator_color, warn_flag, prevent_flag, calc_time`
  - 新增 `oa_supplier_score_criteria`：`scorecard_id, criteria_name, weight, score, max_score, remark`（评分维度：交付及时率/质量/价格/服务）
  - 采购申请提交时校验供应商 standing 与 prevent 标记，走 `sys_business_rule`（新增规则码 `oa.supplier.standing.limit`，命中写 `sys_business_rule_hit_record`）
- **工作量**：M（1 表扩字段 + 3 新表 + 规则接入）
- **优先级**：P0 —— 供应商 14 列是明显短板，且与采购合规直接相关

### [OA-03] 询价比价（RFQ）
- **参考来源**：`frappe/erpnext` → `buying/doctype/{request_for_quotation,request_for_quotation_item,request_for_quotation_supplier,supplier_quotation,supplier_quotation_item}`（GPL-3.0，仅借鉴）。实测 RFQ 主体 30 字段
- **参考实现怎么做的**：一次询价（`request_for_quotation`）发给多个供应商（`_supplier` 明细），每家回一份报价（`supplier_quotation`），系统横向比价选定。RFQ 带 `email_template, message_for_supplier, send_attached_files, schedule_date, terms/tc_name(条款模板)`，可关联 `opportunity`。
- **我们现状**：`biz_purchase_request` 直接填一个 supplier_id 及其快照字段（supplier_contact/phone/bank/account），**没有比价环节**——采购申请时供应商已定，采购合规性缺一环。
- **落地改动**：
  - 新增 `oa_purchase_rfq`：`rfq_id, rfq_no, title, purchase_request_id, dept_id, owner_id, deadline_date, terms, status(DRAFT/SENT/QUOTING/COMPARING/AWARDED/CANCELLED), awarded_supplier_id, award_reason, instance_id`
  - 新增 `oa_purchase_rfq_item`：`rfq_id, item_name, spec, unit, quantity, expected_price, remark`
  - 新增 `oa_purchase_rfq_supplier`：`rfq_id, supplier_id, supplier_name, invite_time, respond_time, quote_status(INVITED/RESPONDED/DECLINED/NO_RESPONSE)`
  - 新增 `oa_supplier_quotation` + `oa_supplier_quotation_item`（供应商报价与明细，可由采购员代录）
  - `biz_purchase_request` 增 `rfq_id`，走 RFQ 定标后带出供应商
  - 比价视图：`GET /oa/rfq/{id}/comparison`（按物料横向对比各家报价）
  - 邀请通知依赖消息中心（07 文档 INT-01），初版可先只支持内部代录
- **工作量**：L（5 新表）
- **优先级**：P1（依赖 OA-02 供应商主数据先补齐）

### [OA-04] 项目工时与成本双轨
- **参考来源**：`frappe/erpnext` → `projects/doctype/{timesheet,timesheet_detail,activity_type,activity_cost}`（GPL-3.0，仅借鉴）。实测 `timesheet` 28 字段
- **参考实现怎么做的**：
  - `timesheet` 主体：`employee, start_date, end_date, time_logs(明细), total_hours, total_billable_hours, total_billed_hours, total_costing_amount, total_billable_amount, total_billed_amount, per_billed, parent_project, customer, sales_invoice`
  - 关键设计：**成本与计费双轨** —— 同一份工时既算内部成本（costing，按 `activity_cost` 里该员工/该活动类型的成本单价）又算对客计费（billable，按计费单价），差额就是毛利
  - `activity_type` + `activity_cost`：活动类型主数据 + 按员工/角色配单价
  - `project` 主体（43 字段）汇总：`estimated_costing, total_costing_amount, total_purchase_cost, total_sales_amount, total_billable_amount, total_billed_amount, gross_margin, per_gross_margin, actual_time, percent_complete_method`
- **我们现状**：`oa_project`（36 列）有 `budget_amount, actual_cost_amount, progress, baseline_version`，但**没有工时表**。实际成本从哪来？只能手工填。项目毛利、人力投入、人均产出都算不出来。`oa_work_task` 是通用任务不带工时。
- **落地改动**：
  - 新增 `oa_activity_type`（`type_code, type_name, billable_default_flag`）+ `oa_activity_cost`（`activity_type_id, employee_id, job_level_id, costing_rate, billing_rate, currency, effective_start, effective_end`）—— 单价可按人或按职级配
  - 新增 `oa_timesheet`：`timesheet_id, timesheet_no, employee_id, employee_name, dept_id, start_date, end_date, total_hours, billable_hours, costing_amount, billing_amount, status(DRAFT/SUBMITTED/APPROVED/REJECTED), instance_id`
  - 新增 `oa_timesheet_detail`：`timesheet_id, project_id, task_id, activity_type_id, work_date, from_time, to_time, hours DECIMAL(6,2), billable_flag, costing_rate, costing_amount, billing_rate, billing_amount, description`
  - `oa_project` 增：`estimated_cost, labor_cost_amount, purchase_cost_amount, billable_amount, billed_amount, gross_margin, gross_margin_rate, actual_hours, percent_complete_mode(MANUAL/TASK_COMPLETION/TASK_PROGRESS)`
  - 工时提交走审批（复用工作流）；审批通过后回写项目汇总
  - 与 HR 联动：工时数据可作为 HR 考勤/绩效的输入（HR 侧 `hr_attendance_monthly` 可交叉校验）
  - API：`/oa/timesheet` CRUD + `/oa/timesheet/{id}/submit` + `/oa/project/{id}/cost-analysis`
- **工作量**：L（4 新表 + 项目汇总回写 + 审批集成）
- **优先级**：P0 —— 项目模块有 5 张表但成本是手填的，工时是补上"项目可核算"的关键一环

### [OA-05] 项目任务树与依赖
- **参考来源**：`frappe/erpnext` → `projects/doctype/{task,task_depends_on,dependent_task,project_template,project_template_task,task_type}`（GPL-3.0，仅借鉴）。实测 `task` 36 字段
- **参考实现怎么做的**：
  - 树形：`parent_task, is_group, lft, rgt, old_parent`（嵌套集合模型，支持任意层级 WBS）
  - 依赖：`depends_on(Table) + depends_on_tasks`，前置任务未完成时阻止开始
  - 权重与进度：`task_weight`（任务权重）+ `progress` → 项目进度由子任务加权汇总（对应 `project.percent_complete_method`）
  - 里程碑：`is_milestone(Check)` —— 里程碑是任务的一个属性，不是独立实体
  - 模板：`project_template` + `project_template_task`，`is_template` 标记，新项目可一键套模板生成完整任务树
  - 时间：`exp_start_date, exp_end_date, expected_time, act_start_date, act_end_date, actual_time`（计划 vs 实际双轨）
- **我们现状**：`oa_project_milestone`（20 列，平铺无层级）+ `oa_project_dependency`（有依赖表）+ `oa_work_task`（通用任务，不挂项目 WBS）。里程碑是独立实体而非任务属性，没有任务树，进度（`oa_project.progress`）靠手填。无项目模板。
- **落地改动**：
  - 新增 `oa_project_task`：`task_id, project_id, parent_task_id, task_no, subject, task_type_id, is_group_flag, is_milestone_flag, status, priority, assignee_id, task_weight DECIMAL(6,2), progress, planned_start, planned_end, planned_hours, actual_start, actual_end, actual_hours, sort_no, level_path VARCHAR(500)（物化路径，比 lft/rgt 好维护）, description`
  - `oa_project_dependency` 改挂 `oa_project_task`（当前挂里程碑）
  - `oa_project_milestone` 保留（对外汇报口径仍需里程碑视图），或收敛为 `oa_project_task.is_milestone_flag` 的视图——**建议后者，避免两套数据**
  - 新增 `oa_project_template` + `oa_project_template_task`（含相对天数偏移，套模板时按项目开始日期换算）
  - 项目进度由任务加权自动算：`oa_project.percent_complete_mode`
  - `oa_timesheet_detail.task_id` 指向本表（与 OA-04 联动）
- **工作量**：L（3 新表 + 树形维护 + 进度汇总）
- **优先级**：P1（与 OA-04 一起做，工时要挂到任务上才有意义）

### [OA-06] 合同履约清单与签署留痕
- **参考来源**：`frappe/erpnext` → `crm/doctype/{contract,contract_template,contract_fulfilment_checklist,contract_template_fulfilment_terms}`（GPL-3.0，仅借鉴）。实测 `contract` 22 字段
- **参考实现怎么做的**：
  - 签署留痕：`is_signed, signee, signed_on, **ip_address**, signee_company, signed_by_company` —— 记录签署人、时间和 **IP 地址**，是电子签署的取证要素
  - 履约：`requires_fulfilment(Check), fulfilment_status, fulfilment_deadline, fulfilment_terms(Table → contract_fulfilment_checklist)` —— 合同条款逐条打勾验收，`fulfilment_status` 由清单完成度推导
  - 模板：`contract_template` + `contract_template_fulfilment_terms`（模板自带履约条款）
  - 多态关联：`document_type` + `document_name` 挂到任意业务单据
- **我们现状**：`oa_contract`（37 列，字段已很丰富：含 `invoice_status, risk_level, seal_application_id, archive_attachment_url, template_id`）+ `oa_contract_template` + `oa_contract_milestone` + `oa_contract_payment_schedule` + `oa_contract_amount_threshold`。缺：① 无逐条履约清单（milestone 是节点不是条款验收）；② 无签署人/签署时间/IP 留痕（HR 侧有 `hr_contract_signature` 但 OA 合同没有）。
- **落地改动**：
  - `oa_contract` 增：`requires_fulfilment_flag, fulfilment_status(NOT_STARTED/ONGOING/FULFILLED/BREACHED), fulfilment_deadline, signed_flag, our_signee_id, our_signee_name, counterparty_signee, signed_time, sign_ip, sign_method(OFFLINE/ESIGN)`
  - 新增 `oa_contract_fulfilment_term`：`contract_id, term_no, term_content, requirement, deadline_date, responsible_id, fulfilled_flag, fulfilled_date, evidence_file_url, remark`
  - `oa_contract_template` 增模板履约条款子表 `oa_contract_template_term`
  - 履约超期写 `oa_risk_alert`（现有风险告警表，直接复用）
  - 时间线事件写 `oa_trace_event`（现有统一时间线，直接复用）
- **工作量**：M
- **优先级**：P1

### [OA-07] 会议室与会议深化
- **参考来源**：`frappe/erpnext` → `crm/doctype/{appointment,appointment_booking_slots,availability_of_slots}`（GPL-3.0，仅借鉴）；`espocrm` → `Meeting.json`（`joinUrl, externalService, acceptanceStatus, reminders`）
- **参考实现怎么做的**：预约槽位化（`availability_of_slots` 定义可预约时段，`appointment_booking_slots` 是具体槽位），避免冲突；会议带线上会议链接与外部服务标记、参会人接受状态、多提醒。
- **我们现状**：`oa_meeting_room` + `oa_meeting_minutes` + `oa_meeting_attendance` 三表，有会议纪要和签到（这两点比参考项目强）。缺：可预约时段配置（当前应是自由时段预约）、线上会议链接、参会人接受/拒绝、多提醒设置、周期性会议。
- **落地改动**：
  - `oa_meeting_room` 增：`open_time, close_time, bookable_weekdays, min_booking_minutes, max_booking_minutes, advance_booking_days, need_approval_flag, equipment_tags, capacity`
  - `oa_schedule_event`（现有日程表）增：`join_url, meeting_platform, recurrence_rule(RRULE 字符串), recurrence_end_date, parent_event_id, reminders(JSON)`
  - `oa_meeting_attendance` 增 `acceptance_status(NONE/ACCEPTED/DECLINED/TENTATIVE), response_time`（当前应只有签到）
  - 与 CRM 活动（CRM-01）字段口径保持一致，避免两套会议模型
- **工作量**：M
- **优先级**：P2

### [OA-08] 耗材库存出入库
- **参考来源**：`frappe/erpnext` → `stock` 模块（GPL-3.0，仅借鉴，**只取最简出入库语义，不引入整套库存体系**）
- **参考实现怎么做的**：物料有库存台账（stock_ledger_entry），每次出入库写流水，结存由流水推导；领用有申请单。
- **我们现状**：`oa_consumable` 单表（应是库存数量字段就地增减），无出入库流水，与 HR-01 假期余额同类问题——数量错了无法追溯。
- **落地改动**：
  - 新增 `oa_consumable_ledger`：`consumable_id, transaction_type(INBOUND/OUTBOUND/ADJUST/SCRAP), quantity（正负）, balance_after, unit_price, amount, source_biz_type, source_biz_id, warehouse_location, operator_id, operate_time, remark`
  - 新增 `oa_consumable_request`：领用申请（`applicant_id, dept_id, purpose, status, instance_id`）+ 明细
  - `oa_consumable` 的库存数量降级为物化值，由台账重算；增 `safety_stock`（安全库存）触发 `oa_risk_alert` 补货提醒
- **工作量**：M
- **优先级**：P2

## 五、不建议移植

| 项 | 原因 |
| --- | --- |
| ERPNext 完整会计体系（accounts 模块） | 我们无总账需求，资产折旧（OA-01）只需算折旧额不需过账到科目；`asset_category_account`、`journal_entry_for_scrap` 等一律不做 |
| ERPNext stock 完整库存（仓库/批次/序列号/盘点） | 我们是办公耗材不是仓储业务，OA-08 只取最简出入库流水 |
| ERPNext manufacturing / subcontracting / quality_management | 与办公协同无关 |
| o2oa 代码 | AGPL-3.0，只可看业务语义（其国产数据库适配思路可参考，但我们只用 MySQL） |
| ERPNext 的 `naming_series` 编号体系 | 我们各表已有 `*_no` 字段与生成规则，不需替换 |
| 项目模块的 `sales_invoice` / 计费开票联动 | OA 已有 `oa_invoice` + `oa_invoice_writeoff`，且 CRM 侧有回款；不引入 ERP 式开票 |
| ERPNext task 的 lft/rgt 嵌套集合 | 维护成本高，OA-05 改用 `parent_id` + `level_path` 物化路径，MySQL 下更好用 |

## 六、建议批次

**P0（补"表面有实际空"的三块）**

2. OA-02 供应商评分与准入拦截（14 列 → 资质/评分/黑名单，复用规则中心）

**P1（链路完整性）**

5. OA-06 合同履约清单与签署留痕
6. OA-03 询价比价（依赖 OA-02）
