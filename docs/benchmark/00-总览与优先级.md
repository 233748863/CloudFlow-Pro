## 三、核心结论

### 我们已经领先的地方（不要重复建设）

调研中反复出现的一个事实：**本项目的"治理与合规"深度普遍超过对标的开源项目**。以下能力在参考项目里基本找不到：

- 规则中心带草稿/版本/发布/回滚/命中记录（`sys_business_rule` 系列 3 表）
- 字典变更审批 + 孤儿字典告警（`sys_dict_change_approval`、`sys_dict_orphan_alert`）
- 审计归档策略（`sys_audit_archive_policy`）、统一业务时间线 + 快照 diff（`oa_trace_event` + `/oa/timeline/{id}/diff`）
- 法律协议版本与用户同意留痕（`sys_legal_*` 3 表）
- 角色互斥（`sys_role_mutex`）、API 限流规则表（21 字段可配）、IP 黑白名单、TOTP 双因素
- 事务发件箱（`outbox_event`，含分布式锁字段）
- 工作流的发布窗口/发布审批/回滚/影响分析/热更新/DLQ 重放/流程模拟
- OA 的印章证照全生命周期（含交接/续期/到期提醒）、车辆 6 表体系、预算 5 表体系
- HR 的工伤 4 阶段、劳动争议调解仲裁、积分商城、考试题库、人才盘点继任
- CRM 的客户公海与自动分配规则、离职交接自动化
- 离线同步（`oa_sync_device`）、PWA、Tauri 桌面端

### 真正的深度缺口（本次调研的产出重点）

缺口不是"功能没做"，而是**"做了但深度不够"**，集中在三类：

1. **规则精度不足**：假期规则 12 列 vs 参考 20 个规则字段；班次只有起止时间没有判定阈值；资产 18 列 vs 参考 52 字段；供应商 14 列
2. **缺少流水台账**：假期余额、耗材库存都是"就地改数"的快照，错了无法追溯（参考项目普遍用 ledger 模式）
3. **缺少批量与基础设施**：薪资无批次、无统一消息通道、无任务调度平台、无图表库

## 八、贯穿全系列的安全注意事项

调研中识别出的、落地时必须处理的安全点（详见各文档"安全注意事项"章节）：

| 项 | 涉及条目 | 说明 |
| --- | --- | --- |
| 凭据加密存储 | SYS-01/03/04/08、INT-02 | 消息通道 api_secret、OAuth2 client_secret、IM app_secret/aes_key、存储 AK/SK、数据源密码一律加密，日志不打印 |
| Token 与验证码存哈希 | SYS-01/03 | OAuth2 token、短信验证码存哈希不存明文 |
| 私有文件直链风险 | SYS-04、INT-05 | `sys_file.url` 若为直链存在越权面，改签名 URL |
| 敏感字段全链可见 | LC-04 | 当前表单在所有审批节点字段一致，薪资/成本价对全链审批人可见；需服务端过滤不可见字段 |
| 服务端表单校验 | LC-01 | 扩展字段类型后若只有前端校验可绕过 |
| 自助报表 | LC-06 | **已决策采用受限版，原风险点消除**：数据集 SQL 由开发写在 XML mapper，用户只能选预置数据集 + 配维度/度量/筛选（白名单校验 + `#{}` 绑定 + 强制租户隔离 + 行数上限）。不开放自由 SQL |
| 表达式求值 | LC-04、HR-13 | 用白名单变量 + 受限解析器，**不用 eval / 不用可执行代码字段** |
| 新增外网暴露面 | CRM-08、SYS-03、INT-02 | 客户门户、OAuth2 端点、IM 回调都是新暴露面，需独立鉴权域 + 限流（复用 `sys_api_ratelimit_rule`）+ 验签 + 审计 |
| 富文本 XSS | LC-01 | `RICH_TEXT` 必过 dompurify（已在依赖） |
| 批量高影响操作 | SYS-06 | 租户套餐变更会批量改权限，需二次确认或走审批 |
| 组织同步冲突 | INT-02 | 必须明确以 IM 为准还是本地为准，建议单向同步避免覆盖错乱 |
