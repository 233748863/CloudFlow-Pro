## 二、M0 是本批成败关键，不能跳

设计文档 §8 的实施顺序里 **M0 = 字段类型注册表 + `FormBuilder` 拆分**。

**先重构再加功能。** 不做这步就加 13 个新类型，会在 5 处各加 13 个分支（共 65 处改动），而且 C2 的子表列类型还要再改一遍。

判断标准：加第 23 个字段类型时，应该只需新增一个注册项 + 一个 preview 组件 + 一个 propertyEditor，**不改任何 switch/if 分支**。做完 M0 后拿这个标准自测。

`FormBuilder.tsx` 的内部结构见设计文档 §0（那是设计前补查的结果）。

## 三、表达式解析器：原设计配置是错的，用实测验证过的配置

C3 字段显隐用表达式解析器（H2 绩效公式共用）。已定决策是 **Aviator + 禁用函数调用**，但**原设计给的配置实测完全无效**。

原设计写：

```java
// ❌ 无效 —— Feature 枚举 17 个取值里没有任何一项管函数调用或属性访问
AviatorEvaluator.setOption(Options.FEATURE_SET,
    Feature.asSet(Feature.Assignment, Feature.If));
```

实测（Aviator 5.3.3）这个配置下：`sysdate()` 返回真实时间、`string.length('abc')` 可用、**`user.class.classLoader` 返回真实 `AppClassLoader` 对象**（RCE 入口）。

**必须用这份配置**（实测 20 项用例全通过）：

```java
AviatorEvaluatorInstance ins = AviatorEvaluator.newInstance();

// ① 关属性语法糖 —— 阻断 RCE 入口的关键，原设计遗漏
ins.setOption(Options.ENABLE_PROPERTY_SYNTAX_SUGAR, false);

// ② 限特性集（阻断 new / lambda / let 等）
ins.setOption(Options.FEATURE_SET, Feature.asSet(Feature.If));

// ③ 类白名单置空
ins.setOption(Options.ALLOWED_CLASS_SET, Collections.emptySet());

// ④ 移除全部内置函数 —— FEATURE_SET 管不到函数，必须显式移除，原设计遗漏
//    实测 Aviator 5.3.3 有 123 个内置函数
for (String name : new HashSet<>(ins.getFuncMap().keySet())) {
    ins.removeFunction(name);
}
```

⚠️ **`ENABLE_PROPERTY_SYNTAX_SUGAR=false` 后 `user.class.classLoader` 返回 `null` 而不抛异常** —— 这是"当成不存在的变量名"，实测穷举 5 种攻击路径（`.classLoader` / `.parent` / `.protectionDomain` / `.name.class` / `.name.bytes`）全部得 `null`，未触达真实对象。别因为"没抛异常"就以为没防住。

🔴 **应用层变量白名单是必需项，不是可选项**：实测 Aviator 对**未声明变量静默返回 `false` 而不报错**。

```
notExist > 10000    =>  false   ← 不报错
```

这意味着字段名写错的表达式会静默判 `false`，永远不显示某个字段，且没有任何错误提示。所以解析前必须校验表达式里引用的变量都在当前表单已声明字段内，引用未声明字段按 C3 的 FR-3.3 **判 `false` 并记日志**（保守失败），但要**记日志**，不能静默。

**自测这几条**（应全部被拒或得 null）：

```
sysdate()                      → FunctionNotFoundException
string.length('abc') > 1       → FunctionNotFoundException
user.getName()                 → 拒绝
new java.lang.String('x')      → 拒绝
user.class.classLoader         → null（不是真实对象）
lambda x -> x end              → UnsupportedFeatureException
```

同时基线必须仍可用：`amount > 10000 && type == 'SPECIAL'`、`!(amount < 100) || type != 'X'`、`amount >= 15000 && amount <= 20000`。

## 四、四项已定决策的落地细节

| # | 决策 | 落地要求 |
| --- | --- | --- |
| 1 | 属性编辑改**独立右侧面板** | 三栏布局与交互细节见 §1.2。理由：22 种类型的配置项差异极大（子表要配 N 列、上传要配 `accept`/`maxSize`/`maxCount`、`GRID` 要配列数与 span），内联会让卡片高度失控 |
| 2 | 子表合计**引入 `decimal.js`**（约 30KB gzip） | 后端用 `BigDecimal`。前端依赖 38 → 39 个。**不要用 `Number` 做金额合计** |
| 3 | `RICH_TEXT` **降级为 Markdown** | `TEXTAREA` 输入 + `marked`（已在依赖）渲染 + `dompurify` 净化。**不引入富文本编辑器**（避开 XSS 面与包体积） |
| 4 | 删 `lock_version` | 与 `version_lock` 语义重叠，实测生效的是后者。`wf_form_definition` 12 → **16** 列（+5 −1）。删前确认无引用 |
