## 二、打印模板：原决策的前提不成立，改用 Freemarker

原决策 G-3 是"**用现有 Hutool 模板引擎，不新增依赖**"。**实测这个前提是假的**：

`hutool-all-5.8.26.jar` 里 `cn/hutool/extra/template/engine/` 下的 beetl / enjoy / freemarker / jetbrick / rythm / thymeleaf / velocity / wit **全部是适配器**，每个都需要对应引擎的 jar 作为独立依赖。**Hutool 没有内置模板引擎**，而项目当前 `pom.xml` 里无任何模板引擎依赖。

**结论：无论如何都要引入一个引擎。已改为 Freemarker 2.3.32 + 3 项加固配置。**

### 2.1 必须用这三项加固（实测 18 项用例验证）

Freemarker **默认配置确认可 RCE** —— 实测 `${"freemarker.template.utility.Execute"?new()("whoami")}` 真的执行了命令并返回主机用户名。

```java
Configuration cfg = new Configuration(Configuration.VERSION_2_3_32);

// ① 禁 ?new —— 阻断经典 RCE 向量
cfg.setNewBuiltinClassResolver(TemplateClassResolver.ALLOWS_NOTHING_RESOLVER);

// ② 禁 ?api（默认已 false，显式声明以防未来版本变更）
cfg.setAPIBuiltinEnabled(false);

// ③ 用 SimpleObjectWrapper —— 拒绝包装任意 POJO，阻断属性与方法访问
cfg.setObjectWrapper(new SimpleObjectWrapper(Configuration.VERSION_2_3_32));
```

加固后三项打印必需能力**全部保留**：变量替换 `${name}`、子表循环 `<#list items as it>`、条件 `<#if amount gt 1000>`。

### 2.2 🔴 `SimpleObjectWrapper` 带来的硬约束

它**拒绝包装任意 POJO**（这正是阻断攻击的机制）。所以：

**模板数据必须是 `Map` / `List` / 基本类型 / `String` / 数字 / 日期，不能直接传实体对象。**

```java
// ❌ 渲染时会失败：SimpleObjectWrapper deliberately won't wrap this type
data.put("employee", employeeEntity);

// ✅ 必须转 Map
data.put("employee", Map.of(
    "name", emp.getName(),
    "empNo", emp.getEmployeeNo(),
    "deptName", emp.getDeptName()));
```

`PrintDataProvider.buildData()` 要统一做这个转换。**这个约束是安全收益的一部分** —— 模板作者拿不到实体对象就无法沿属性链攀爬。

### 2.3 原设计的黑名单可以删掉

设计文档原有的 `assertNoDangerousSyntax()`（禁 `?api` / `Class.forName` / `<%` 等字符串黑名单）**删掉**。加固配置从引擎层面阻断，比黑名单可靠得多 —— 黑名单可被大小写、Unicode 转义、字符串拼接绕过。

## 三、G3 的 17 个 `FileAccessChecker` 是本批最高价值项

摸排发现的真实问题（比 PRD 描述的更实）：**不是直链泄露**（有服务端 `/system/file/access` 端点），而是**只需 `system:file:list` 权限即可访问本租户任意文件**，无业务级校验。合同、工资条、身份证扫描件都在里面。

所以 M3 的 17 个校验器是核心交付。已定决策：**按设计建议先实现，上线前逐项 review**（§1.3 的清单即初始规则，review 时由各业务模块负责人确认自己那类文件的可见范围）。

**无 `biz_type` 的历史文件**：已定决策 —— **仅上传者本人可访问**（按 `create_by` 判定）。⚠️ 若历史文件需团队共享，会出现"本来能看现在看不了"的回归，上线前需评估历史文件量与共享需求。

### OSS 强制私有（决策 A-8）

已查明：`OssProperties.accessPolicy` 默认 `"1"`（公共读），但 `enabled=false` 且全仓无 OSS 配置 → **当前无直链泄露**（只用 LOCAL 存储，走服务端流式输出）。

**但一旦有人启用 OSS 而没改这个值，合同、工资条、身份证扫描件立刻公网可达。**

已定决策：**强制私有，配错启动失败** + 默认值从 `"1"` 改 `"0"` + `sys_file_config` 保存时也拦。

🔴 选"启动失败"而非"WARN 告警"是刻意的 —— WARN 日志大概率被忽略。实现时**不要**改成告警。

🔴 **三处必须先问再写**：

| # | 待定项 | 为什么不能猜 |
| --- | --- | --- |
| 1 | `sys_import_error.cell_value` 列宽 | Excel 单元格可能很长。`VARCHAR(500)` 还是 `TEXT`?选窄了导入报错信息被截断 |
