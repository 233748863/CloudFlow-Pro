# 借款冻结审批离职接续复核

状态：B53/F7下平台R21完整67项、116请求，相邻R23及14项汇总R2全部通过，包含普通审批离职接续及借款负责人首审/财务复核两阶段。平台R20在撤回后的即时观察失败保留；R21加入异步结束等待后通过，不扩大为全部H业务入口矩阵完成。

## 范围与依据

已批准的离职补充要求保留H业务原审批限制。借款由部门负责人先审、独立财务复核，服务端在提交时冻结名单；离职接任人不得因此替换原审批人。本轮沿用实际借款验证器准备专用身份、工资及已发布额度规则，通过借款创建、提交及负责人实际审批生成两个阶段的真实待办。

对每一阶段分别检查直接归属和账号停用释放后的任务，每种状态向旧独立消息入口投递三类目标：申请人、名单外人员、其他冻结审批参与人（负责人阶段为后续财务，财务阶段为同节点另一财务）。这些旧入口消息由验证器生成，不称为HR实际发布；比较任务、监控、转办历史以及借款状态和金额，确认拒绝替换后均不改变。

实际HR部分在真实管理入口停用并确认工作流释放后，创建、提交、审批、办理交接任务并完成两份离职申请，等待共享离职消费者完成；继续核对原冻结待办及金额、接任人读取权限、原停用和离职事件重复投递。通过申请人实际撤回借款收尾，不直接写业务终态。

## 实施边界

本轮只修改验证程序：`verify-hr-advance-approval-real.mjs`新增可选检查回调及身份收尾回调，普通验证分支保持原行为；新增`verify-workflow-h-advance-offboard.mjs`并接到离职实际验证之后。所有新会话凭据加入现有日志与审计扫描；运行器输入集合新增三份验证依赖。产品仍为B53/F7，正式结构和批准提案保持。

验证前置身份、员工及模型沿用既有自有库准备方式，工资通过真实加密薪资入口保存，额度规则通过真实版本发布入口确认。完整H范围仍包括加班、调班、内推、结算、录用、耗材、会议、退款和工资补正，不能从本轮借款两阶段推断其他实际业务入口均已完成。
