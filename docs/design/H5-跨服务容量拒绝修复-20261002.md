# H5跨服务容量拒绝修复

## 问题与范围

会议室照片经OA调用AUTH存储。附件R6在127项/172请求处遇到非容量提示409，脚本缺少默认5000毫秒防重复提交间隔。补5100毫秒等待后的R7同样在127项/172请求处失败，实际为HTTP503/业务503，容量提示和重复提交提示均为false，确认OA吞掉上游容量拒绝。两轮业务与文件清理、原套餐/角色恢复均成功；各自恢复原认证配置后默认停用18项/10请求通过，包装器退出1保留失败。

只读核对流程附件发现相同上游Feign错误被统一转换为存储不可用，外层NoFallbackAvailableException还会落入字段格式校验错误。本次一并修正这两条已批准附件入口的错误转换，无新增表、字段、菜单或依赖。

## 实现

公共`StorageCapacityError`统一已有额度拒绝的409和固定中文提示，容量服务沿用同一常量。跨服务调用仅在HTTP409、JSON数值code=409、固定msg完全匹配、data为空时返回容量拒绝；畸形/重复键/尾随JSON、其他409、其他状态及附带业务数据不转换。对外只使用固定提示，不转发上游诊断。照片既有400/413分类和其他存储失败503保持；流程异常包装统一解包后识别，其他传输错误仍返回原安全存储不可用说明。

照片验收增加实际绑定会议室、降额前后从房间入口读取原始PNG，清理先通过规则接口解除本轮绑定再删除自有文件和会议室。流程专项建立只用于发起前上传的隔离表单及START→END定义，验证降额拒绝和旧附件下载，不创建流程实例。包装器增加流程脚本输入摘要，两类新附件证据与清理分别记录。
