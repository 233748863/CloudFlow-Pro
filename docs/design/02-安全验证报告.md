## 2. Aviator 验证详情

### 2.1 原设计配置：验证失败

设计文档（C §5.3）原写：
```java
AviatorEvaluator.setOption(Options.FEATURE_SET,
    Feature.asSet(Feature.Assignment, Feature.If));
```

**实测结果（20 项用例，通过 7 失败 8）**：

| 类别 | 用例 | 结果 |
| --- | --- | --- |
| 基线 | `amount > 10000 && type == 'SPECIAL'` | ✅ 可用 |
| **内置函数** | `sysdate()` | ❌ **返回 `Tue Sep 01 13:06:44 CST 2026`** |
| **内置函数** | `string.length('abc') > 1` | ❌ **返回 true** |
| **内置函数** | `seq.list(1,2,3)` | ❌ **返回 [1, 2, 3]** |
| **属性导航** | `user.name` | ❌ **返回 `张三`** |
| **属性导航** | `user.class.name` | ❌ **返回 `AvTest$User`** |
| **属性导航** | **`user.class.classLoader`** | ❌ **返回真实 `AppClassLoader` 对象** |
| 方法调用 | `user.getName()` | ✅ 拒绝 |
| new | `new java.lang.String('x')` | ✅ 拒绝 |

### 2.2 根本原因

查 `Feature` 枚举的全部取值：
```
Assignment / Return / If / ForLoop / WhileLoop / Let / LexicalScope / Lambda / Fn /
InternalVars / Module / ExceptionHandle / NewInstance / StringInterpolation / Use /
StaticFields / StaticMethods
```

**其中没有任何一项与"函数调用"或"属性访问"相关** —— 所以 `FEATURE_SET` 从设计上就管不到这两类。这不是配置写错，是**选错了控制手段**。

### 2.3 反常现象

实测发现：**默认配置反而拒绝 `user.class.name`，受限配置却放行**。
```
默认配置-class导航: user.class.name  => 拒绝(ExpressionRuntimeException)
受限配置:          user.class.name  => 返回 AvTest$User
```
原因未深究，但足以说明：**"限制越多越安全"的直觉在这里不成立**，必须实测。

### 2.4 正确配置（实测有效）

```java
AviatorEvaluatorInstance ins = AviatorEvaluator.newInstance();

// ① 关属性语法糖 —— 这是阻断 RCE 入口的关键，原设计遗漏
ins.setOption(Options.ENABLE_PROPERTY_SYNTAX_SUGAR, false);

// ② 限特性集（阻断 new / lambda / let 等）
ins.setOption(Options.FEATURE_SET, Feature.asSet(Feature.If));

// ③ 类白名单置空
ins.setOption(Options.ALLOWED_CLASS_SET, Collections.emptySet());

// ④ 移除全部内置函数 —— FEATURE_SET 管不到函数，必须显式移除，原设计遗漏
//    实测 Aviator 5.3.3 有 123 个内置函数
for (String name : new HashSet<>(ins.getFuncMap().keySet())) {
    ins.removeFunction(name);
}
```

**验证结果（20 项用例）**：

| 类别 | 结果 |
| --- | --- |
| 基线 4 项（比较、逻辑与或非、范围判断） | ✅ 全部可用 |
| 内置函数 4 项 | ✅ 全部 `FunctionNotFoundException` |
| 方法调用 2 项 | ✅ 全部拒绝 |
| new / 静态 2 项 | ✅ 全部拒绝 |
| lambda / let 2 项 | ✅ 全部 `UnsupportedFeatureException` |
| **属性导航 5 项** | ✅ **全部返回 null，未触达任何真实对象**（见 2.5） |

### 2.5 属性导航的阻断机制（重要）

`ENABLE_PROPERTY_SYNTAX_SUGAR=false` 后，`user.class.classLoader` **不抛异常而是返回 null**。实测确认这是"当成不存在的变量名"而非真的导航：

```
sugar=true：
  user.name               => [String] 张三
  user.class.classLoader  => [AppClassLoader] jdk.internal.loader.ClassLoaders$AppClassLoader@4e25154f   ← RCE 入口

sugar=false：
  user                    => [User] AvTest3$User@e320068      ← 变量本身仍可取（正常）
  user.name               => [null] null
  user.class              => [null] null
  user.class.classLoader  => [null] null
```

**穷举 5 种攻击路径均返回 null**：`user.class.classLoader` / `.parent` / `user.class.protectionDomain` / `user.name.class` / `user.name.bytes`

**结论：sugar=false 下属性表达式一律得 null，未触达任何真实对象。**

### 2.6 ⚠️ 必须配合应用层白名单

实测发现未声明变量**静默返回 false 而非报错**：
```
notExist > 10000        => [Boolean] false      ← 不抛异常
notExist == nil         => [Boolean] true
amount > 10000 && notExist == nil  => [Boolean] true
```

**这意味着**：Aviator 不会因"引用了未声明字段"而拒绝表达式。**应用层的变量白名单校验是必需的**（不能依赖 Aviator 兜底）。这一点原设计（C §5.3 的 `assertOnlyAllowedVars`）已有，验证后确认它**不是可选项而是必需项**。

### 2.7 决策 A-7 的最终状态

**Aviator 可用，但必须用 2.4 的完整 4 项配置 + 应用层变量白名单。**

原设计的单项 `FEATURE_SET` 配置若按原样实现，**会留下完整的 RCE 通道**（`user.class.classLoader` → 反射 → 任意代码执行）。

## 3. Hutool 模板引擎验证详情

### 3.1 前提不成立

决策 G-3 的理由是"不新增依赖"。实测 `hutool-all-5.8.26.jar` 的模板引擎实现：

```
cn/hutool/extra/template/engine/beetl/BeetlEngine.class
cn/hutool/extra/template/engine/enjoy/EnjoyEngine.class
cn/hutool/extra/template/engine/freemarker/FreemarkerEngine.class
cn/hutool/extra/template/engine/jetbrick/JetbrickEngine.class
cn/hutool/extra/template/engine/rythm/RythmEngine.class
cn/hutool/extra/template/engine/thymeleaf/ThymeleafEngine.class
cn/hutool/extra/template/engine/velocity/VelocityEngine.class
cn/hutool/extra/template/engine/wit/WitEngine.class
```

**全部是适配器**（Adapter），每个都需要对应引擎的 jar 作为独立依赖。Hutool **没有内置模板引擎**。

项目当前 `pom.xml` 中**无任何模板引擎依赖**（grep `beetl|freemarker|velocity|thymeleaf|rythm|enjoy` 结果为空）。

**结论：Hutool 单独无法渲染模板。决策 G-3 的"不新增依赖"前提不成立 —— 无论如何都要引入一个引擎。**

### 3.2 Freemarker 验证（作为实际候选）

既然必须引入引擎，选 Freemarker（生态成熟、安全配置文档完备）并实测其加固可靠性。

**默认配置：确认 RCE**

| 用例 | 结果 |
| --- | --- |
| `${"freemarker.template.utility.Execute"?new()("whoami")}` | ❌ **实际执行命令，返回 `pc-20250523fymb\administrator`** |
| `${"freemarker.template.utility.ObjectConstructor"?new()("java.lang.ProcessBuilder","whoami")}` | ❌ **返回 `java.lang.ProcessBuilder@1460a8c0`** |
| `${user.class.name}` | ❌ 返回 `FmTest$User` |
| `${user.getName()}` | ❌ 返回 `李四` |
| `${user?api.class.classLoader}` | ✅ 拒绝（`api_builtin_enabled` 默认已 false） |

**加固配置（3 项）**

```java
Configuration cfg = new Configuration(Configuration.VERSION_2_3_32);

// ① 禁 ?new —— 阻断经典 RCE 向量
cfg.setNewBuiltinClassResolver(TemplateClassResolver.ALLOWS_NOTHING_RESOLVER);

// ② 禁 ?api（默认已 false，显式声明以防未来版本变更）
cfg.setAPIBuiltinEnabled(false);

// ③ 用 SimpleObjectWrapper —— 拒绝包装任意 POJO，阻断属性与方法访问
cfg.setObjectWrapper(new SimpleObjectWrapper(Configuration.VERSION_2_3_32));
```

**验证结果（18 项用例，通过 14 失败 4 —— 4 项失败全部来自"默认配置"对照组）**：

| 类别 | 加固后结果 |
| --- | --- |
| 基线：变量替换 `${name} 报销 ${amount} 元` | ✅ 输出 `张三 报销 1,200 元` |
| 基线：子表循环 `<#list items as it>${it.itemName}:${it.amount} </#list>` | ✅ 输出 `机票:800 住宿:400` |
| 基线：条件 `<#if amount gt 1000>大额<#else>小额</#if>` | ✅ 输出 `大额` |
| `?new()` 执行命令 | ✅ 拒绝：`Instantiating freemarker.template.utility.Execute is not allowed in the template for security reasons` |
| `?new()` 构造对象 | ✅ 拒绝（同上） |
| `?api` 取 class / ClassLoader | ✅ 拒绝：`Can't use ?api, because the "api_builtin_enabled" configuration setting is false` |
| `${user.class.name}` | ✅ 拒绝：`SimpleObjectWrapper deliberately won't wrap this type` |
| `${user.getName()}` | ✅ 拒绝（同上） |

**三项打印模板必需能力（变量、循环、条件）在加固后全部保留。**

### 3.3 ⚠️ SimpleObjectWrapper 带来的约束

`SimpleObjectWrapper` **拒绝包装任意 POJO**（这正是它阻断攻击的机制）。因此：

**模板数据必须是 `Map` / `List` / 基本类型 / `String` / 数字 / 日期，不能直接传实体对象。**

`PrintDataProvider.buildData()` 需要把实体转为 Map：
```java
// ❌ 不可行
data.put("employee", employeeEntity);

// ✅ 必须转 Map
data.put("employee", Map.of(
    "name", emp.getName(),
    "empNo", emp.getEmployeeNo(),
    "deptName", emp.getDeptName()));
```

**这个约束是安全收益的一部分**（模板作者拿不到实体对象就无法沿属性链攀爬），但需在 G5 的设计与实现中明确写清，否则开发会直接传实体然后发现渲染失败。

### 3.4 决策 G-3 的最终状态

**改为：引入 Freemarker 2.3.32 + 3 项加固配置 + 数据转 Map 约束。**

原设计的"用 Hutool 不新增依赖"不可行。原设计的 `assertNoDangerousSyntax()` 黑名单（禁 `?api` / `Class.forName` / `<%` 等字符串）**可以删掉** —— 加固配置从引擎层面阻断，比黑名单可靠得多（黑名单可被大小写、Unicode 转义、字符串拼接绕过）。
