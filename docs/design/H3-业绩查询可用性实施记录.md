## 问题及范围

当前HR调用CRM的四个降级方法都返回成功空列表，导致服务故障被当作零业绩。销售业绩页面在请求失败后仍保留上次榜单，首次加载或失败时也持续显示零值卡片；两个不同日期查询还可能由迟到响应覆盖新结果。

本阶段将四个降级响应改为明确不可用且不携带业绩数据；页面仅在员工和部门两份查询都成功后展示数据，失败或重新加载时清除旧数据，不把无效响应转换成空列表。切换查询或离开页面时取消旧请求，并阻止迟到结果更新当前视图。合法的成功空列表仍显示真实空态。

不新增表、字段、菜单、角色授权、依赖或Java类型推断；继续使用`hr:performance:view`和既有CRM内部接口。财务门户新增设计仍等待独立补充确认，不借本次修复修改财务公开范围。

## 界面方案

沿用现有绩效页面主题、字体和组件，日期与刷新触控区至少44px；采用现有150/200ms过渡，不增加动画或界面依赖。

```text
+--------------------------------------------------+
| 起始日期 / 结束日期                    [刷新]    |
+--------------------------------------------------+
| 读取中：显示正在加载，不显示零值或历史榜单        |
| 失败：说明销售业绩未加载，保留日期供手动刷新      |
| 成功：同时显示员工/部门榜单；真实空结果显示空态   |
+--------------------------------------------------+
```
