# C2电脑原生表格接续

原C2非功能要求及AC-12明确规定原生`table`和`th scope="col"`。F40的电脑端仍使用`div role="table"`、网格行和模拟表头；手机卡片专项不能覆盖该缺口。本项已在B74/F43完成原生结构、定位、双端实际流程、相邻R68及汇总R2；完整列尺寸、十类型及C2全项仍开放。

沿用现有主题色、字体、12px单元格间距和44px操作目标，保留原拖拽过渡，不增加动画或依赖。结构拟为：

```text
+--------------------------------------------------+
| 行数                                             |
| +----------------------------------------------+ |
| | 序号 | 费用说明 * | 金额 | 操作              | |
| |      | 输入框     | 输入 | 复制 / 删除       | |
| |      | ...        | ...  | ...               | |
| +----------------------------------------------+ |
| 合计                               [新增明细]    |
+--------------------------------------------------+
```

非虚拟模式使用`table/colgroup/thead/tbody/tr/td`，序号列与操作列也必须是单元格。拖拽上下文放在表格外，避免其辅助节点进入`tbody`；手机仍使用已有卡片。

已检查当前`react-window` 2.2.6源码：`List`会自动追加一个占位`div`，直接改`tagName="tbody"`会产生非法结构。拟继续使用其滚动范围和定位接口，通过`children`承载完整原生表格，行范围由`onRowsRendered`提供、空白区使用合法占位行；库的外层及占位`div`留在表格外。必须验证表头高度与定位索引、30/31行切换、最后一行可达、滚动及拖拽后的稳定行标识。方案实施时若不能保证这些行为，应继续调整实现，不以非法DOM或移除虚拟滚动降低要求。

实现中将表头作为滚动尺寸中的第0项，数据行为第1至N项，保留既有电脑虚拟行高116px、表头44px。`List`的行组件返回空值，仅提供可视范围；原生表格作为独立完整子节点，使用上/下占位`tr/td`保持总高度，表头在滚动视口顶部可见。电脑错误定位使用该已知尺寸直接滚动，避免库对未测项目平均高度的估算，手机维持原定位接口。行、单元格按设备选择`tr/td`或`div`，保留现有行级记忆化、回调及`_rowId`，只渲染一份实际表格。

验证需覆盖原生结构、表头关联、键盘拖拽/复制/删除、100×8列低于500ms、编辑单元格仅更新所在行、错误定位及手机操作回归；真实保存恢复审批沿用手机专项建立的独立模式和日志保护检查。最终结果须绑定新的前端构建，现有F40证据保留版本边界。
