# 离职待办接续与工作流姓名容量补充提案

状态：2026-10-03用户明确批准按本补充方案实施，授权范围包括保存停用前待办归属的四列、一个索引、仅接续释放后未变更待办的业务逻辑，以及下列11张表12列姓名扩大至100字符并完整保留。正式结构与业务已实施，B53完整构建、198项数据库、723项原工作流、实际平台67项/116请求、相邻R23及14项汇总通过，详见《A3-离职待办接续与姓名容量实施复核-20261003.md》。下文保留提案时的问题和实施范围；已有账号昵称100字符批准继续有效，不再就本提案重复请求确认。

## 已确认的缺陷

人事完成离职时，`HrLifecycleService`先调用账号停用，再发布离职事件；这两个服务的事务独立提交。工作流接到停用事件后正确清空原待办处理人，之后的离职转办只按原处理人查找，遗漏已经释放的待办。数据库R17/B41使用真实停用服务与转办服务、两个先后提交的事务复现：原待办已释放，指定接任人未得到待办，断言失败；临时库已删除，原业务库未修改。该检查没有调用实际HR接口或共享事件消费者。

数据库R16/B41同时确认，账号允许的100字符昵称写入`wf_task.assignee_name`时报长度错误，整个转办撤销；工作流中仍有12列人员姓名仅允许64字符。此前初步清点遗漏带反引号定义的`wf_process_copy.start_user_name`，本提案按正式02脚本逐表重新清点，最终为11张表、12列。

证据保存在`.cloudflow-runtime/full-prd-20260915/approved-runtime/a3-anomaly-scan-database-20261003-r16/`与`r17/`对应目录；只对外汇报异常类型、列名和代码位置，不输出SQL参数或姓名。

## 业务行为

账号停用后仍立即释放待办，并继续执行无人处理提醒；同时记录本次释放前的归属。之后收到离职交接时，仅将本租户、原属该离职员工、释放后未变更且仍未认领的待办交给已指定的有效接任人。

待办被认领、改派、处理或在释放后发生其他版本变更时，后来的离职通知不得覆盖现状；流程已经结束时不再转办。暂停或执行异常但尚未结束的流程仍允许交接待办，交接不会自动恢复流程执行。无接任人、接任人停用、跨租户或不满足现有H类审批回避规则时保持释放状态，沿用现有人工处理和异常提醒。

转办、转办历史、监控归属和释放来源清除在同一事务提交；失败后整体回滚，原事件可以重试。重复事件不重复转办。用户100字符以内的完整姓名在下面12列原样保存，既有姓名不截断、不改写。

## 具体结构

在`02.cloudflow-workflow.sql`的`wf_task`中新增四列及一个索引，不新增表：

```sql
disabled_from_user_id    BIGINT(20)   DEFAULT NULL COMMENT '账号停用释放前处理人ID',
disabled_from_user_name  VARCHAR(100) DEFAULT NULL COMMENT '账号停用释放前处理人姓名',
disabled_release_version INT         DEFAULT NULL COMMENT '账号停用释放后任务版本',
disabled_release_event_id VARCHAR(64) DEFAULT NULL COMMENT '账号停用释放来源事件ID',
KEY idx_disabled_handover (tenant_id, disabled_from_user_id, status)
```

这四列仅由工作流停用与交接服务维护，不作为客户端可写参数，不对任务外部接口暴露。它们记录最近一次有效释放来源，不代替事件记录或转办历史。

停用服务锁定当前任务并复核租户、状态和原处理人后，将原用户ID、原姓名、来源事件ID和本次更新后的`lock_version`与清空处理人一并保存。离职服务查询直接归属任务及释放来源匹配任务，锁定真实流程和任务后复核：`status=TODO`、处理人为空、释放原用户匹配、来源事件非空、`lock_version=disabled_release_version`，再转办；成功后清空四列。其他路径即便留下旧来源，只要版本已改变，就不得用于自动交接。

不向`execution_context`加入字段；该列已有固定的工作流执行结构。也不伪造接任人ID写入`wf_task_delegation`，后者要求真实且非空的目标用户ID。

以下12列统一由`VARCHAR(64)`扩大为`VARCHAR(100)`，保留原可空性、默认值和注释：

| 表 | 姓名列 |
| --- | --- |
| wf_process_instance | start_user_name |
| wf_task | assignee_name |
| wf_task_history | operator_name |
| wf_task_attachment | uploader_name |
| wf_task_delegation | from_user_name、to_user_name |
| wf_task_add_sign | initiator_name |
| wf_countersign_vote | voter_name |
| wf_node_record | executor_name |
| wf_deploy_record | deployer_name |
| wf_process_copy | start_user_name |
| wf_deploy_rollback_history | rollback_by_name |

流程名、节点名、标识列和已为100字符的监控姓名列保持原结构；不新增菜单、权限或依赖。
