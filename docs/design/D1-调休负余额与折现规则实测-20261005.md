# D1调休、负余额与折现规则实测

本阶段继续AC-4的规则业务效果，操作D盘固定自有集成环境。实际R5在B81/F52上退出0，76项检查、35次请求、5325份输入保持；相邻R86及汇总R3通过，不认定D1全17条完成。

## 已验证范围及修复

- 超额分配关闭时5天上限拒绝再加1天，启用时可分配至6天；负余额关闭时拒绝扣6天，启用时5天扣6天得到-1天。接口逐笔运行余额与物化余额一致，本阶段负余额验证的是手工台账入口。
- 禁止调休的假种拒绝转入，调休拒绝负数量；允许调休的小时假种转入8小时，超过5秒防重复提交保护期后重放同一来源返回原台账且内容不变。
- 允许折现的假种从5天扣2天后余额3天，生成唯一APPROVED追加薪酬123.45元、生效日期正确、beforeTotal=0及afterTotal=123.45，所选salaryComponentId完整保存。三项金额列加密保存，接口正常回显核定金额。重复同一来源不增加薪酬和台账；禁止折现、缺金额、额度不足、员工无权、薪酬项停用或不存在均正确拒绝；拒绝后台账、余额、薪酬记录摘要保持。

实测发现并修复：

| 问题 | 最终实现 |
| --- | --- |
| 正常折现缺少必填after_total而失败 | HrLeaveBusinessService沿用其他追加薪酬的现有方式写入变动前0、变动后核定金额、差额核定金额；不修改建表结构 |
| 所选折现薪酬项仅出现在备注 | 保存到已有salary_component_id；HrLeaveEncashmentComponentService统一验证本租户启用项目；配置及实际折现均使用该验证，工资计算明细保存项目ID、编码、名称和版本 |
| 薪酬项停用时将内部version清空而失败 | HrCompComponentController创建/修改经既有configurationPayload去除由系统维护的字段，保留现有租户、时间和版本；实际无版本入参的停用/恢复成功 |

未新增表、列或外部依赖。B80、B81后端完整构建均退出0，3828份输入保持；B80加入金额/项目修复，B81补齐薪酬项配置入口。前端继续F52，人事服务已加载B81。
