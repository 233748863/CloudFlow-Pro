# F4合同报表日期口径补充

状态：2026-10-02用户已批准“按当前履约情况实时汇总，隐藏日期筛选”。已开始实施，最终验证完成前不计本项交付；下方保留原问题和比较依据。

## 已核实的问题

`OperationsReportPage.tsx`共用页面对合同报表显示开始、结束日期，并传入`from/to`。`OaOperationsReportService.contracts`校验查询区间后调用看板、逾期及三维分组，但`OaOperationsReportMapper.xml`三个合同查询均未使用该区间；用户修改日期后仍得到同一范围的数据。

F4 PRD FR-7.1要求进行中合同履约看板及超期条款清单，FR-7.2要求按合同类型、负责人及对方统计履约率，没有约定创建日、合同开始日或条款期限作为报表筛选日期。《F-批次F技术设计.md》第4节及《09-批次F编码任务提示词.md》也未补足这一口径。

## 可实施方案

| 方案 | 用户看到的范围 | 实施与验证 |
| --- | --- | --- |
| 实时汇总（推荐） | 查看有权限合同的当前履约状态与统计，合同报表隐藏日期输入并说明“按当前履约情况统计” | 合同请求不携带日期；合同服务仅构造租户及当前账号范围，不再对未使用的日期作查询限制；其他业务报表保持原日期功能。验证合同页无日期输入、三维统计及切换其他报表日期正常 |
| 按合同开始日期筛选 | 所选区间内开始的合同，其当前履约情况纳入看板、超期清单及三维统计 | 三处合同查询统一按合同开始日期筛选，未填写开始日期的合同另列数量并提示补齐；清楚说明显示当前状态而非历史时点状态。需补验区间两端、缺日期、跨年、权限和三维统计 |

两方案均使用现有表和权限，不新增依赖、不修改履约率分子分母；合同状态范围按PRD进行独立核对，不能借日期方案变更取消、终止、归档等状态的业务含义。不会把当前R7已通过的三维分组结果记为日期筛选通过。

2026-10-02批准后，合同页隐藏日期并显示“按当前履约情况统计”，合同请求不再带日期，服务只构造当前租户及用户范围。其他报表继续使用原日期校验。实际R4完整45项/42请求及阶段14项通过，证据为`approved-runtime/f4-contract-review-20261002-http-r4.log`和同轮checklist；合同反向/超长日期参数均不影响实时结果，三维统计和1440/375/320页面通过，切换资产报表保留两个日期并传参，切回合同恢复隐藏。

本轮使用`a3-internal-auth-20261002`构建R2：29模块、10条静态规则零finding和前端类型/构建通过，3782/1469份产品输入保持。33份服务日志339301068字节、数据库日志120837714字节对11个本轮敏感值泄漏0，18份验证输入不变。验证码额度恢复100、计数198至200只增不写，角色菜单授权保持。已查看R4实际320像素截图，日期隐藏与实时统计提示正常。
