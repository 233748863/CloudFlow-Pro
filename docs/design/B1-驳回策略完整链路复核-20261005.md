## 业务场景

| 场景 | 实际入口与预期证据 |
| --- | --- |
| 回发起人 | 员工提交、实际审批人驳回，产生发起人可编辑待办；本人提交修改后再次审批至通过，原驳回记录保留 |
| 回上一步 | 先真实完成两个上游节点，再由当前审批人驳回；只恢复上一已执行节点，依次重审后通过 |
| 回指定节点 | 指定已执行的较早上游节点；重走后续审批至通过，历史与轨迹保存目标及REJECT_JUMP |
| 直接结束 | 当前审批人按TERMINATE策略拒绝，实例REJECTED、待办清空、历史及轨迹留痕 |
| 回父调用 | 等待子流程完成的父实例中，子审批人回退父调用；旧子实例REJECTED、形成新子实例，完成新子及父后续审批，旧结束事件不得覆盖新结果 |
| 指定非法目标 | 分别直调当前节点、下游节点和不存在节点，要求明确业务拒绝，原待办、实例版本、变量及历史完全保持 |
| 父实例已结束 | 使用既有`waitForCompletion=false`，父实例实际完成、子待办仍待审批；子审批人回退父调用时降级为结束，保留`PARENT_FINISHED_DEGRADE_TO_TERMINATE`，父终态保持 |
| 缺省驳回策略 | 按原FR-2.3及B技术设计，未提供策略和目标时，驳回入口默认退回发起人；重新提交再审批至通过 |
