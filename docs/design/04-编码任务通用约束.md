## 二、构建期静态扫描（10 条规则，违反直接构建失败）

`cloudflow-common-static-rules` 的 `StaticRuleScanner` 绑在 maven **`validate`** 阶段，发现任何 finding 抛 `IllegalStateException`，**构建直接失败**。它不是 lint 建议。

（`scripts/security-audit.mjs` 是另一套独立规则，其中 `@SaCheckLogin` 被当作合法保护 —— 与扫描器结论相反。**以扫描器为准**。）

### 2.1 `PERMISSION_GUARD`

Controller 里每个带 Mapping 注解的方法必须是以下四类之一：

- `@SaCheckPermission("...")`
- `@Inner`（内部接口，路径前缀 `/inner/{module}/{business}`）
- `@SaIgnore`（真正匿名，现仓仅 3 处：`LegalAgreementController` 2 + `SysAnnouncementController` 1）
- `@SaCheckRole("admin")`（平台运维级，极少）

**`@SaCheckLogin` 不算保护** —— 只写它会被阻断。

### 2.2 其余 9 条中最容易被无意触发的

| 规则 | 触发条件 | 怎么避开 |
| --- | --- | --- |
| `SQL_CONCAT` | 行内同时出现 `SELECT `/`UPDATE `/`DELETE `/`INSERT `（**带尾空格**）与 `+` | **无白名单豁免，且不判断是否真在拼 SQL**。`log.info("DELETE 完成 " + n)` 会误报。日志文案避免这四个大写词，或改用 `{}` 占位符 |
| `POST_NO_REPEAT` | `@PostMapping` + 方法名含写语义词 + 无 `@RepeatSubmit` | 写接口一律加 `@RepeatSubmit`；确实不需要的加 `@RepeatSubmit.Disabled` |
| `MP_SQL_LAST` / `MP_SQL_APPLY` | 出现 `.last(` 或 `.apply("` | 这两个 MyBatis-Plus 方法一律禁用，改写 XML |
| `MYBATIS_ANNOTATION_SQL` | 行首是 `@Select(`/`@Update(`/`@Insert(`/`@Delete(` 及对应 4 个 `*Provider` | 注解式 SQL 全禁，只能 XML |
| `TXN_WORKFLOW` | `@Transactional` 方法内调 `.startProcess(`/`.completeTask(`/`.cancelProcess(`/`.recallProcess(`/`startWorkflow(`（非 workflow 服务内） | 工作流调用移出事务 |
| `AUTH_NO_RATE` | 认证敏感 Controller 的 POST 或公开读接口无 `@RateLimiter` | 认证类接口加限流 |
| `HIGH_RISK_AUDIT_REQUIRED` | `@HighRiskAction` 无配套 `@Audit`/`@Auditable` | 成对使用 |
| `AUDIT_LOG_DELETE_CALL` | 对不可变日志表做删除 | 日志清理走 XML，且确认表不在不可变清单 |

`POST_NO_REPEAT` 的 29 个写语义词：
`add` `create` `submit` `approve` `reject` `publish` `cancel` `convert` `receive` `handover` `save` `update` `delete` `remove` `terminate` `pause` `resume` `archive` `restore` `rollback` `replay` `ignore` `deploy` `draft` `record` `bind` `unbind` `void` `writeoff` `invalidate`

⚠️ 方法名带 `record` 的**查询**接口也会命中。

### 2.3 白名单是行号精确匹配

`static-rules-whitelist.txt` 现有 14 行，格式为 `文件路径:行号`（源码里拼 `path + ":" + line` 后 `contains`）。其中 5 条指向 `AuthController.java:46` 与 `CaptchaController.java:33/44`。

**在这两个文件里增删行会让白名单错位**，导致构建失败且报错指向无关代码。改动后必须同步更新白名单行号。

## 三、编码硬性约束

Java变量必须显式声明类型，禁止使用`var`，范围包含业务源码、测试源码及`scripts`下的Java验证代码；增强for循环、try资源变量和显式类型的lambda参数同样适用。按真实类型保留泛型，不以无必要的`Object`或强制转换替代。

### 3.1 禁止 Java 拼接 SQL

```java
// ❌ 绝对禁止
String sql = "SELECT * FROM sys_job WHERE status = '" + status + "'";

// ✅ 标准 CRUD 用 MyBatis-Plus
LambdaQueryWrapper<SysJob> w = new LambdaQueryWrapper<>();
w.eq(SysJob::getStatus, status);

// ✅ 复杂查询写 XML mapper（resources/mapper/ 下）
```

### 3.2 权限码格式固定

`{module}:{resource}:{action}`，模块前缀**只允许** `system` / `oa` / `crm` / `hr` / `workflow` 五类。

```java
@SaCheckPermission("system:job:list")     // ✅
@SaCheckPermission("job:list")            // ❌ 缺模块前缀
@SaCheckPermission("sys:job:list")        // ❌ sys 不在五类内
```

### 3.3 实体的审计列与注解形态

代码生成器按各表已有字段输出实体及建表骨架，不强制添加不存在的审计列；用户于2026-09-16确认验证码表保持不变，仅生成已有的`create_time`。以下完整审计形态用于具有这些列的业务表。

严格照抄 `cloudflow-service-oa/.../domain/SysSupplier.java`：

```java
@Data
@TableName("sys_message_channel")
public class SysMessageChannel implements Serializable {
    private static final long serialVersionUID = 1L;

    @TableId(type = IdType.AUTO)
    private Long channelId;

    private Long tenantId;
    // ... 业务字段 ...

    @TableField(fill = FieldFill.INSERT)
    private Integer deleted;
    @Version
    private Integer version;
    @TableField(fill = FieldFill.INSERT)
    private String createBy;
    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")

    @TableField(fill = FieldFill.INSERT_UPDATE)

    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")
    @TableField(fill = FieldFill.INSERT_UPDATE)

```

### 3.4 Controller 的注解组合

照抄 `SupplierController`：

```java
@RestController
@RequestMapping("/system/job")
@RequiredArgsConstructor
public class SysJobController {

    private final ISysJobService jobService;

    @GetMapping("/list")
    @SaCheckPermission("system:job:list")
    public R<PageResult<SysJobVO>> list(SysJobQuery query,
            @RequestParam(value = "pageNum", defaultValue = "1") Integer pageNum,
            @RequestParam(value = "pageSize", defaultValue = "10") Integer pageSize) { ... }

    @SysLog("新增定时任务")        // 增删改必带
    @RepeatSubmit                  // 新增必带
    @PostMapping
    @SaCheckPermission("system:job:add")
    public R<Void> add(@RequestBody @Valid SysJobDTO dto) { ... }
}
```

返回类型：`R<T>` / `R<PageResult<T>>` / `R<Void>`。分页入参用 `PageQuery` 或 `pageNum`+`pageSize`，与所在模块保持一致。

启动期另有 `HighRiskAuditVerifier`：业务 `@Service` 的公开方法名含 `delete/remove/disable/reset/revoke/terminate/cancel`，或显式标注 `@HighRiskAction` 时，必须标注 `@Audit(highRisk=true)`。仅存在 `@Audit` 仍会阻止服务启动；编译通过后还需验证完整应用启动。

可复用的公共件（都已存在，勿重造）：

| 类 | 位置 |
| --- | --- |
| `R` / `PageResult` | `cloudflow-common-core/.../domain/` |
| `@SysLog` | `cloudflow-common-log/.../annotation/` |
| `@RepeatSubmit` | `cloudflow-common-idempotent/.../annotation/` |
| `@Inner` | `cloudflow-common-security/.../annotation/` |
| `@DistributedJob` | `cloudflow-common-job/.../annotation/` |
| `HrTypedCrudService` | `cloudflow-service-hr/.../service/`（泛型 CRUD，HR 配置类表用） |

### 3.5 DDL 规范按模块不同

| 脚本 | 主键 | `deleted` 列 | 实测 |
| --- | --- | --- | --- |
| `01.cloudflow-common.sql` | `BIGINT(20) AUTO_INCREMENT` | 配置表加，日志/流水表不加 | 32 表中 8 张有 |
| `02.cloudflow-workflow.sql` | **`VARCHAR(64)`** | **普遍不加**（流程数据靠归档） | 46 表中仅 2 张有 |
| `03` HR / `04` OA / `05` CRM | `BIGINT(20) AUTO_INCREMENT` | 配置表加 | — |

固定形态：

```sql
DROP TABLE IF EXISTS sys_job;
CREATE TABLE sys_job (
  job_id            BIGINT(20)      NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  tenant_id         BIGINT(20)      DEFAULT 100000 COMMENT '租户ID',
  -- 每列必带 COMMENT
  create_by         VARCHAR(64)     DEFAULT '' COMMENT '创建者',
  create_time       DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  update_by         VARCHAR(64)     DEFAULT '' COMMENT '更新者',
  update_time       DATETIME        DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (job_id),
  UNIQUE KEY uk_xxx (...),
  KEY idx_xxx (...)
) ENGINE=InnoDB AUTO_INCREMENT=100 DEFAULT CHARSET=utf8mb4 COMMENT='定时任务表';
```

**不加物理外键**（与项目现有风格一致）。`01` 脚本列名对齐 17 字符。

直接改建表 SQL 与种子脚本，**不写数据迁移脚本**，不留兼容层。

### 3.7 密钥一律加密存储

加密存列（列名带 `_cipher` 后缀）、接口返回脱敏（只回显后 4 位）、**日志不打印**。

**每批落库前必查**（返回非 0 行就停下报告，不要自行改段位）：

```sql
SELECT menu_id, menu_name, perms FROM cloud_flow_db.sys_menu
 WHERE menu_id BETWEEN {本批下界} AND {本批上界};
```

**每批执行后必验**：

```sql
-- 给全角色授权的菜单必须只包含本批预期的那几个
SELECT DISTINCT m.menu_id, m.perms FROM cloud_flow_db.sys_role_menu rm
  JOIN cloud_flow_db.sys_menu m ON m.menu_id = rm.menu_id
 WHERE rm.role_id = 5;   -- EMPLOYEE
```

种子约定：菜单 20 列手工指定 `menu_id`；`menu_type` = `M`目录/`C`菜单/`F`按钮；`visible`/`status` = `0`显示可用/`1`隐藏停用；租户 `100000`；10 个角色（1 ADMIN / 2 MANAGER / 3 FINANCE / 4 HR / 5 EMPLOYEE / 6 LEGAL / 7 OA_CLERK / 8 SALES_MANAGER / 9 SALES_REP / 10 CRM_OPS）。ADMIN 走 `SELECT 1, menu_id FROM sys_menu` 全量语句，自动含新菜单。
