# G4企业微信配置后端复核

日期：2026-09-29。本轮是配置后端检查点，不是G4或全量PRD交付；配置页面、正式菜单、组织同步、本人绑定登录、任务卡片和持久回调仍未完成。

## 1. 本轮实现及边界

- 接续已批准的企业微信首家接入。新增11份生产Java及1份Mapper XML，实现配置请求、独立密钥动作、租户内管理员验证、配置服务、事务审计和四个管理接口；不重复询问已获批准的19项套餐独立选择。
- 六张批准IM表已合入正式`01.cloudflow-common.sql`，逐列、索引、唯一键、CHECK与批准DDL比较通过。源码及本轮独立空库为366表，仍运行的自有集成库保持360表；没有向该运行库增表、重导或加入IM菜单。最终374表还差8张人事表，表数变化不代表业务完成。
- `ImConfigController`提供`GET /system/im/config/list`、`POST /system/im/config`、`PUT /system/im/config`、`POST /system/im/config/{configId}/test`，经过网关的外部路径前缀为`/api/auth`。本轮只做配置服务的真实数据库与协议调用验证，管理Controller的完整HTTP和页面验收待补。
- 权限来自有效内部会话、当前账号/租户状态、本租户有效管理员角色及数据库实时角色权限；每次服务操作和事务内重验均通过`TenantPermissionPolicy`重新查询套餐。IM没有H5平台名单绕过权，不要求额外的H5平台再认证；本人解绑的近期再认证继续在后续本人流程实施。
- `ImDatabase`清除传入的跳过租户过滤标记，在可信会话租户内执行，并在成功或异常后恢复原上下文。没有修改共用`TenantBroker`；所有IM SQL仍显式带租户条件。
- 四密钥均使用独立加密主密钥，`KEEP`不接受同时传新值，`REPLACE`重新加密，`CLEAR`将可选字段写为NULL。批准DDL要求`app_secret_encrypted`非空，因此该字段禁止CLEAR。普通结果只返回configured布尔值；请求与持久实体的字符串/JSON均不输出秘密。
- 新配置必须DISABLED，新增时不接受客户端编号、版本、回调地址或开启登录/卡片。取得真实ID后才能保存固定回调路径`/api/auth/im/callback/{configId}`；回调只允许部署HTTPS站点的精确路径，不能指定厂商API地址。部署关闭时允许有加密密钥的管理员保存停用草稿；测试或启用仍被阻断。
- 更新以版本控制；企业/应用已有任何绑定、同步、卡片或回调引用时不能换身份。同步范围包含本租户有效根部门、明确的远端部门及管理员指定主部门，尚未执行组织同步。
- 测试连接每次真实取令牌，网络请求置于数据库事务外；回写审计前重验会话、套餐、角色和配置版本。结果不返回令牌，不自动启用应用。审计与配置同事务，审计故障回滚配置和版本；审计保存安全配置变化和密钥动作，同步用户范围只记摘要。
- 生成器排除六张IM表，新增全租户已有IM事实保护；07由脚本重新生成。结构检查器有逐列/逐索引及删除保护变造测试。新建集成环境预期366表，旧357/360表环境验证保留显式历史口径；`--im-schema`仅用于实际366表环境，不自动接受任意表数。
