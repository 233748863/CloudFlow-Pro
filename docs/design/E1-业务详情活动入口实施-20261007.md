# E1 业务详情活动入口实施

按 E1 FR-4.1/AC-2 补齐业务详情中新建活动。客户工作台已有“安排活动”；商机、线索、工单、合同详情尚无对应入口。线索已存在按租户和数据权限读取的 `GET /crm/lead/{id}`，当前页面只有编辑窗口，本次复用该接口补充只读详情，不新增后端字段、表、权限或依赖。

界面结构先沿用现有详情与活动编辑器：

```text
+----------------------------------+
| 业务详情                    关闭 |
| 名称 / 客户 / 负责人 / 当前状态  |
| [安排活动]                       |
+----------------------------------+
               |
               v
+----------------------------------+
| 创建活动                         |
| 主题 / 时间 / 负责人             |
| 关联类型 / 关联对象 / 所属客户    |
| 说明 / 参与人 / 提醒             |
|                     [关闭] [保存]|
+----------------------------------+
```

使用 superdesign 的布局、可访问性与移动端约束，颜色、字体、间距、焦点及弹窗交互沿用项目公共组件，不引入新的主题和动画。操作按钮至少 44 像素高，线索查看按钮具备明确名称；业务详情只读字段与编辑表单分开，加载失败提供原地重试。活动编辑器继续使用原校验和保存逻辑，并显示已知关联对象名称。

新建时自动带入业务类型、编号以及已有客户；未转化线索或无客户合同保持客户为空，不虚构客户。负责人按原新建活动规则默认当前操作者，只有已有分配权限的人可改为他人。入口只向有新建活动权限的人显示；已保存的关联和跨客户、跨租户拒绝仍由原后端规则核验。商机及合同存在未保存业务修改时，入口随既有保护状态禁用。
