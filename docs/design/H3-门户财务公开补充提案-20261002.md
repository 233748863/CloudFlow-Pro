## 对用户的行为

管理员与财务在现有回款、发票详情中查看对外字段预览，逐条确认公开、选择票据附件或撤回。其他内部角色不能办理公开；客户仅查看本公司当前有效公开的记录。回款与销项发票各自确认，关联一方公开不会带出另一方未公开的记录。

公开确认针对当时的单据版本。金额、日期、状态、归属等业务更新导致版本变化后，旧确认失效，客户暂停看到该记录，财务核对后再次确认；撤回立即停止列表、详情及附件访问。操作结果未明时先读取当前状态核对，重复请求不得重复写业务审计。

两表目前均没有币种列。本次对外金额使用原字段的精确十进制值，不新增币种列、不推定人民币、不从关联合同臆测币种；去掉旧实施记录示意图中的“币种”占位。回款保留原`DECIMAL(16,2)`，发票保留原`DECIMAL(18,2)`，禁止经浮点数转换后输出。

## 最小持久化补充

`crm_receivable`和`oa_invoice`各增加下列4列，共8列，不新增表。版本号复用两表已有`version`，确认人从当前内部身份取得，确认时间取服务端时间，文件编号由服务器校验后保存。

```sql
portal_public_version INT DEFAULT NULL COMMENT '已确认公开的单据版本，NULL表示未公开或已撤回',
portal_published_by BIGINT(20) DEFAULT NULL COMMENT '财务公开确认人系统用户ID',
portal_published_time DATETIME DEFAULT NULL COMMENT '财务公开确认时间',
portal_file_ids JSON DEFAULT NULL COMMENT '财务明确允许对外读取的票据文件编号数组'
```

建表约束分别命名为`chk_crm_receivable_portal_publication`和`chk_oa_invoice_portal_publication`，内容为：

```sql
CHECK (
  (portal_public_version IS NULL AND portal_published_by IS NULL
    AND portal_published_time IS NULL AND portal_file_ids IS NULL)
  OR
  (portal_public_version IS NOT NULL AND portal_public_version >= 0
    AND portal_public_version <= version AND portal_published_by IS NOT NULL
    AND portal_published_time IS NOT NULL AND portal_file_ids IS NOT NULL
    AND JSON_TYPE(portal_file_ids) = 'ARRAY')
)
```

确认公开时按传入旧版本做条件更新：原`version`加1，`portal_public_version`设为同一个新版本，无附件保存空数组。普通新增、编辑、导入、回调拒绝写入这4列，原业务更新继续递增版本，`portal_public_version != version`时统一视为“待重新确认”。撤回同时清空4列并递增版本。修改归属、逻辑删除、客户或联系人停用也必须立即失去可读性。

拟索引为`idx_crm_receivable_portal (tenant_id, customer_id, deleted, receivable_id)`与`idx_oa_invoice_portal (tenant_id, customer_id, deleted, invoice_id)`。只合入两份正式建表定义与约束，不写旧数据迁移脚本。

## 独立入口与授权

当前只读核对确认财务已经拥有回款和发票的页面读取权限。沿用现有两类单据详情增加公开核对按钮，只补独立公开操作权限；不新增页面，也不授予完整回款维护能力。

| 菜单项 | 拟值 |
| --- | --- |
| 编号、所属段 | 1916，H3允许1900—1949；批准前核对当前正式目录和运行库占用 |
| 名称与父级 | 确认财务对外公开，父级回款管理803；现有发票详情按同一独立权限显示操作 |
| 类型与路径 | F操作，路径为空、组件NULL、隐藏菜单、启用 |
| 权限 | `crm:portal-finance:manage` |
| 授权 | ADMIN(1)、FINANCE(3)，按原租户种子规则授予；EMPLOYEE新增0 |

该权限仅允许读取公开核对所需的白名单预览、上传票据、确认或撤回公开，不授予编辑回款金额、确认到账、核销或发票作废。两类单据仍分别执行当前租户、数据范围及客户归属核验。独立门户读取权限沿用`crm:portal:finance:list`，只在`portal`登录域生效，不写入内部员工授权。

拟内部接口分别在CRM回款、OA发票域提供分页预览、详情、票据上传、`PUT /{id}/portal-publication`；请求只接受`version`、`publish`及已校验的`fileIds`。现有单据入口并不接收这些公开字段。门户沿用已批准的`GET /portal/crm/receivable/list`和`GET /portal/crm/invoice/list`，补对应受同样授权保护的详情及票据下载。

票据复用`sys_file`私有存储、容量规则及已存在的业务绑定列，分别标记`PORTAL_FINANCE_RECEIVABLE`或`PORTAL_FINANCE_INVOICE`。只允许本次核对单据下、当前有权操作者上传的票据进入公开清单；不接受任意URL、其他单据或门户用户私有文件。两表原有外部地址、影像地址及关联单据编号不作为公开依据。

## 对外字段与验收

| 来源 | 明确可对外字段 |
| --- | --- |
| 回款 | 回款编号、计划金额、已回款金额、未回款金额、应收日期、实收日期、回款状态、明确公开的票据 |
| 销项发票 | 发票代码、号码、类型、开票日期、含税金额、税额、状态、明确公开的票据 |

客户归属、租户、有效联系人、公开版本及文件绑定条件同时用于列表、总数、详情、下载和预览；不能读取内部备注、员工信息、团队分成、提成或未公开关联单据。文件撤回与单据变化后，已取得的预览凭据也必须重新核验当前权限。访问与公开/撤回使用既有审计记录，不新增日志表。

页面沿用项目控件与浅/深色主题，电脑列表、手机单列；金额完整展示、操作区至少44px，失败保留勾选，版本冲突要求重新读取。验收包括默认隐藏、真实财务公开/撤回、源单据更新失效、版本竞争、普通写入口防绕过、同公司多联系人、跨公司/租户、联系人停用、私有文件和精确金额，以及电脑/手机实际操作。最后执行通用14项检查、Java显式类型核对和相邻回款/发票业务回归。
