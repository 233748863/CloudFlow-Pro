## 已批准范围

2026-09-19用户明确批准“逐个勾选公开附件，保存所选清单；未勾选的仅内部可见”。原两列不能保存选择，按此批准补充 `external_attachment_file_ids JSON DEFAULT NULL COMMENT '明确对外公开的版本附件文件ID清单，未选择的不对外提供'`；同现有两列一起由专用发布入口维护，不新增表，不改动内部版本附件。默认不勾选；空清单代表仅正文；上限沿用内部知识附件5个。撤回同时清空公开版本与清单，审计记录前后清单。

候选附件必须来自所选不可变版本中的站内文件引用、同租户且由该文档原提交账号上传，文件状态有效、私有、未绑定其他业务；原始URL、无法核验的引用及其他业务专用文件均不可勾选。门户只返回选中的文件编号、名称、大小；正文链接和图片地址仍被移除。下载使用 `/portal/file/access` 和 `/portal/file/download` 两个受保护POST入口，颁发受众限定的60秒一次性随机凭据，仅在Redis保存摘要索引及可信业务上下文；下载时重新核验同一门户会话、文档公开版本、发布变更版本、所选文件关系和文件状态。直接通过存储组件流式返回附件，不重定向到存储地址，不把凭据放入URL；文件请求每用户每分钟20次。

## 读取边界

门户请求仍经过认证服务独立身份、30分钟空闲/8小时绝对期限及每用户每分钟60次限制；OA受保护内部入口再次验证真实门户令牌，并按租户、账号、会话版本、联系人版本及客户当前状态复核。列表、分页总数和详情共同连接指定版本；搜索仅匹配已对外版本标题，不搜索草稿、摘要或被净化掉的原始正文。

对外响应逐字段构造，不包含工作正文、摘要、内部人员、范围、审批、审计或原始附件地址；不会将门户用户写入内部阅读记录。响应禁止缓存，撤回后发起的新读取统一不可访问；已传到客户端的内容无法收回，页面在重新读取、切换版本、重新聚焦及定时核对失败时清空旧正文。

## 验证中发现的问题

演示生成器原先对新增公开控制字段使用通用假值，独立空库导入检测到2500条异常。现从生成器明确生成私有标记0及空版本/附件清单，并增加已存在门户账号或知识发布事实时禁止重导的保护；重新生成后的空库01—07通过，38项静态契约和37组反向自测通过，失败日志保留。

真实流程第1轮被既有5000毫秒上传防重复保护拒绝，测试改为间隔5100毫秒上传，未修改生产限制。第2轮发现隔离审批进程仍持有重建前的依赖，核验所有权后刷新D盘回环服务。第3轮实际启动审批后返回表单校验失败：既有知识业务只传title/category/scopeType，固定审批表单使用documentTitle/categoryName/publishScope。现按真实文档补齐三项映射，保留原变量和回调身份，不修改审批定义、不绕过表单校验；新增三种可见范围规则测试及真实实例断言，修复后仍须完整重验。

第4轮141项通过后，行政专员试图发布管理员文档被正确返回404；测试此前误将按钮权限等同于跨人员数据权限。现保留既有本人数据范围，补为跨范围拒绝及本人真实创建、审批、发布、撤回的正反检查，不扩大角色7权限。

第5轮214项通过，包含真实附件字节、同会话与跨客户隔离、一次性竞争、真实60秒过期、撤回/改清单/文件删除失效及20次限流；电脑发布和门户下载通过，手机因既有路由未接知识库而显示不支持。现仅补受`oa:knowledge:list`保护的手机入口及反向测试，不增加菜单授权。后续验证还将跨租户/跨文档边界输入补为具有有效发布时间的版本，避免404仅由未发布状态造成，并核对本次数据库操作/审计日志中的全部会话及下载凭据。

第6轮229项通过后，审计断言失败。只读检查确认发布与撤回已有字段日志，但前后JSON快照均为空；实际Spring异步接口代理使比较器的具体类判断失败，退回了不带快照的双参数调用。新增真实Spring代理及真实审计切面的专项测试，先复现“proxied audit handler must retain both snapshots and the JSON diff”失败，再将快照与来源类通过审计接口传递；同时覆盖接口代理、类代理、附件改选、撤回、无变化、失败操作及diff=false。真实集成断言新增前后附件清单、文档修订、操作人、模块和高风险标记核验；修复后仍须完整构建与实际数据库重验。
