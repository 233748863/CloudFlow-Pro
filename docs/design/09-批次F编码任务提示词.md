## 二、两处 PRD 判断错误（§0，会影响你的做法）

### 2.1 项目进度自动计算**已实现**，要扩展不要重写

F3 的 PRD 写"项目进度靠手填"，**这是错的**。`ProjectExecutionStateService.resolveProjectProgress()` 已有完整的 `TASK_COMPLETION` 模式（按完成数），且已同时考虑里程碑与任务。

**F3 的真实缺口只有 2 项**：

1. `TASK_PROGRESS` 模式（按 `task_weight` 加权，而非简单计数）
2. 进度来源从 `oa_work_task` 换到新的 `oa_project_task`（WBS 树）

`percent_complete_mode` 的三种模式里**已有一种**。改造时**扩展 `resolveProjectProgress` 而非重写**，加一个 `List<OaProjectTask> projectTasks` 参数 + `switch(mode)` 分支。

### 2.2 耗材出入库**已有日志**，H4 的判断要修正

H4 的 PRD 写耗材"无出入库流水"，**部分错误**：`ConsumableServiceImpl.addStock()` 确实是就地增减（这点判断对），**但已有 `saveStockLog()`** 写进 `oa_asset_log`（用 `refType="2"` 与资产区分），且 `getLowStockList()` 安全库存预警也已实现。

已定决策：**新建 `oa_consumable_ledger` 专用表**（含 `balance_after` 结存快照、`unit_price`、`amount`），原 `oa_asset_log` 保留作通用变更历史。理由：往共用日志表加 `balance_after` 对资产无意义，且两种语义混在一表难维护。

⚠️ 这张表**属于 H4 范围**（H 批若执行则 `04` 再 +1 表）。F 批不建，但 F 批做资产日志时要知道这个后续规划，不要把 `balance_after` 加进 `oa_asset_log`。

## 三、删 `oa_project_milestone` 有个重复计数的坑

已定决策：**删表**，里程碑收敛为 `oa_project_task.is_milestone_flag=1` 的任务。理由：两套里程碑数据必然不一致。

🔴 **现有公式在收敛后会重复计数**：

现有 `resolveProjectProgress` 在"任务与里程碑都有"时是：

```
(完成任务数 + 完成里程碑数) / (任务总数 + 里程碑总数)
```

里程碑在分母里**独立计一次**。收敛后里程碑成了任务的子集，**沿用原公式会让里程碑既算在 tasks 里又算在 milestones 里** —— 分母虚高、进度偏低。

设计文档 §3.6 给了修正后的公式（里程碑不再独立计入分母，改为给里程碑更高权重）与 6 步迁移顺序。**照那个改，不要自己想公式。**

改造后的取数方式：

```java
List<OaProjectTask> tasks = projectTaskMapper.selectByProject(projectId);
// 里程碑不再是独立集合，而是 tasks 的子集
List<OaProjectTask> milestones = tasks.stream()
        .filter(t -> Boolean.TRUE.equals(t.getIsMilestoneFlag())).toList();
```

**做法**：签署留痕功能照做，IP 取值处写成可配置的解析链（先 `X-Forwarded-For` 再 `X-Real-IP` 再 `remoteAddr`），并在**取到的是内网/网关 IP 时记一条警告日志**，不要假装取证有效。

## 五、F5 询价的邮件降级

F5 邀请供应商报价原本走邮件，但批次 A 未做邮件渠道。设计文档 §5 给了降级实现：

```java
if (StringUtils.hasText(s.getContactEmail()) && emailChannelAvailable()) {
    messageSender.send(...);     // 邮件渠道就绪时用
    channel = "EMAIL";
} else {
    channel = "OFFLINE";         // ★ 批次 A 未做邮件 → 走线下
}
```

`channel` 要落库（`rfq_supplier` 表），**这样邮件渠道就绪后能查出哪些是线下邀请的**。

同一段还有"最少家数校验走规则中心"：`businessRuleService.evaluateWarn("oa.rfq.min.suppliers", supplierIds.size(), 3)` —— 用 `evaluateWarn` 而非硬编码 `if (size < 3) throw`。

## 六、🛑 25 张新表全部没有 DDL，你要补

设计文档里 **`CREATE TABLE` 数量为 0**。25 张表全是这种形态：

```
oa_asset_depreciation_schedule  折旧计划（asset_id/period_no/period_date/depreciation_amount/
                                accumulated_amount/net_value/status(PLANNED/POSTED/CANCELLED)/post_time）
```

字段名和部分枚举值有了，**列类型、列宽、默认值、索引、COMMENT、可空性全部没有**。这是七批里 DDL 缺口最大的一批。

`04` 脚本规范：`BIGINT(20)` 自增主键、每列必带 `COMMENT`、配置表加 `deleted`、不加物理外键（通用约束 §3.5）。**照现有 `04.cloudflow-oa.sql` 同类表推**。

🔴 **四处必须先问再写**：

| # | 待定项 | 为什么不能猜 |
| --- | --- | --- |
| 1 | 折旧金额与净值精度 | 折旧要逐期累计，精度不足会累积舍入误差。**必须与 `oa_asset` 现有金额列一致**，否则算出来对不上 |
| 2 | 工时精度 | `DECIMAL(5,2)` 按小时还是按分钟存整数?影响双轨计算（costing/billing）的取整口径 |
| 3 | 单价锁定的存储方式 | 锁定是存快照值还是存版本引用?设计文档说"单价锁定"但没给结构 |
| 4 | 那"关联一"是哪张表 | 汇总 +25 里的"关联一"没有定义名称与字段 |
