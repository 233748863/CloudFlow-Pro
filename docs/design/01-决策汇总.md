### 11.3 构建期扫描规则的实测结论

原提示词只提了「仅 `@SaCheckLogin` 会被阻断」，实际情况更复杂，且**有一条比文档描述的更严**：

真正阻断构建的是 `cloudflow-common-static-rules` 的 `StaticRuleScanner`（绑在 maven **`validate`** 阶段，发现 finding 直接抛 `IllegalStateException`）。`scripts/security-audit.mjs` 是另一套独立规则，且**它认 `@SaCheckLogin` 为合法保护**（`:72` 的正则含 `Login`）—— 两套规则结论相反，以扫描器为准。

扫描器的 10 条规则里，这几条最容易被无意触发：

| 规则 | 触发条件 | 坑点 |
| --- | --- | --- |
| `SQL_CONCAT` | 行内同时出现 `SELECT `/`UPDATE `/`DELETE `/`INSERT `（**带尾空格**）与 `+` | **无白名单豁免**，且不区分是否真在拼 SQL。`log.info("DELETE 完成 " + n)` 会误报 |
| `PERMISSION_GUARD` | Controller 里有 Mapping 但无 `@SaCheckPermission`/`@Inner`/`@SaIgnore`/`@SaCheckRole("admin")` | `@SaCheckLogin` **不算**保护 |
| `POST_NO_REPEAT` | `@PostMapping` + 方法名含 29 个写语义词之一（`add`/`save`/`update`/`delete`/`approve`/`deploy`/`record`/`bind`/`void` 等）+ 无 `@RepeatSubmit` | 方法名带 `record` 的查询接口也会命中 |
| `MP_SQL_LAST` / `MP_SQL_APPLY` | 出现 `.last(` 或 `.apply("` | MyBatis-Plus 的这两个方法一律禁用 |
| `MYBATIS_ANNOTATION_SQL` | 行首是 `@Select(`/`@Update(` 等 8 种 | 注解式 SQL 全禁，只能用 XML |
| `TXN_WORKFLOW` | `@Transactional` 方法内调 `.startProcess(`/`.completeTask(` 等 5 个方法（非 workflow 服务内） | 事务里调工作流被禁 |
| `HIGH_RISK_AUDIT_REQUIRED` | `@HighRiskAction` 无配套 `@Audit`/`@Auditable` | — |

⚠️ **白名单是 `文件路径:行号` 精确匹配**（`isWhitelisted` 拼 `path + ":" + line` 后做 `contains`）。现有 14 行白名单里有 5 条指向 `AuthController.java:46`、`CaptchaController.java:33/44`。**在这两个文件里增删行会让白名单错位**，导致构建失败且报错指向无关代码行。改动这两个文件后必须同步更新 `static-rules-whitelist.txt` 的行号。
