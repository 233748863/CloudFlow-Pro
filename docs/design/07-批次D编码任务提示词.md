## 二、HR 模块的架构特点（与其他模块不同）

设计文档 §0 是设计前补查的结果，先读。两个关键约定：

**Controller 归属**：已定决策 —— **追加到现有 `*ResourceControllers.java`**，遵循 HR 惯例（一文件多 `@RestController`）。假期台账 → `HrAttendanceResourceControllers`，薪资批次 → `HrCompensationResourceControllers`。**不要为每张新表建独立 Controller 文件。**

**是否用 `HrTypedCrudService`**：已定决策 —— 分两类：

| 类型 | 用法 | 例子 |
| --- | --- | --- |
| 配置类表 | **用 `HrTypedCrudService`** 泛型 CRUD | 假期政策、周期、税率表、技能主数据 |
| 业务逻辑类 | **写独立 Service** | 台账扣减、薪资批次、考勤计算 |

理由：业务逻辑类需要事务 + 锁 + 并发控制，泛型 CRUD 会绕弯路。

`HrTypedCrudService` 在 `cloudflow-service-hr/.../service/HrTypedCrudService.java`，是个 `class`（不是接口），提供 `<T> list(Class<T>, Map)` / `<T> page(Class<T>, Map)` 等泛型方法。

## 三、三条算错就出事的计算链

### 3.1 请假天数（M3）

必须**服务端计算**，接批次 A 的日历三级回退：

```
① 员工当日排班的班次绑定日历（hr_shift.holiday_calendar_id）
② 员工所在部门的日历（sys_dept.holiday_calendar_id）
③ 租户默认日历（default_flag=1）
④ 三级全空 → 抛明确异常，绝不静默按自然日计算
```

🔴 第 ④ 条是红线。静默按自然日算会让跨节假日的请假多扣天数，且没人发现。

### 3.2 额度扣减（M2）

台账式：校验 → 冻结 → 扣减 → 释放，四个接线点 + Redisson 锁。

并发场景要自测：同一员工两个请假单同时提交，剩余额度只够一个 —— 必须一个成功一个失败，**不能都成功（超额）也不能都失败**。

### 3.3 累计预扣个税（M10）

⛔ **2026 年税率表待财务提供**（7 档税率 + 速算扣除数）。**可先用占位值实现，上线前替换** —— 但必须把占位值集中在一处（配置表或常量类），标注 `TODO: 待财务提供 2026 税率表`，不要散落在计算逻辑里。

已定决策：**本期税额为负时按 0 处理，不退税**（年度汇算清缴另处理）。⚠️ 这条需财务复核，实现时在代码注释里标明这是已定决策。

## 四、加班倍率依赖 A4 的 `triple_pay_flag`

⚠️ 批次 A 的 `sys_holiday_date.triple_pay_flag` 语义：**法定节假日当天 = 1（三倍工资），调休日 = 0（两倍）**。

D 批的薪资计算与 H 批的加班倍率都依赖这个字段。如果发现 A 批的种子数据填错了（比如把调休日也标成 1），**停下报告**，不要在 D 批的计算逻辑里做补偿。

## 六、🛑 15 张新表中 13 张没有完整 DDL，你要补

设计文档只给了 **2 张**完整 `CREATE TABLE`，其余 13 张是这种形态的字段清单：

```
hr_leave_ledger    假期台账（employee_id/leave_type_id/period_id/change_type/quantity/...）
```

**缺列类型、列宽、默认值、索引、COMMENT、AUTO_INCREMENT 起始值。**

本项目 DDL 规范很严（通用约束 §3.5）：`03` 脚本用 `BIGINT(20)` 自增主键、每列必带 `COMMENT`、配置表加 `deleted`、不加物理外键、`ENGINE=InnoDB DEFAULT CHARSET=utf8mb4`。**照现有 `03.cloudflow-hr.sql` 里同类表的形态推**，不要自创风格。

🔴 **但有三处必须先问再写，不要自己定**：

| # | 待定项 | 为什么不能猜 |
| --- | --- | --- |
| 1 | 金额列精度（薪资、扣款、补偿） | `DECIMAL(10,2)` 还是 `DECIMAL(12,2)`?薪资总额上限决定列宽,选窄了会溢出。**先查 `hr_salary_slip` 现有金额列的精度并沿用** |
| 2 | 假期数量精度 | 按天(`DECIMAL(5,1)`)还是按小时(`DECIMAL(6,2)`)?这决定半天假、小时假能否表达。**先查 `hr_leave_quota` 现有列** |
| 3 | 台账 `change_type` 取值集合 | 累积/结转/过期/扣减/释放/调整…设计文档没给全集。取值不全会导致后续加值要改表注释与字典 |

第 1、2 项能从现有表推出来就直接沿用并说明依据;推不出来或现有表本身不一致,**停下问**。第 3 项设计文档确实没写全,**必须问**。

DDL 写完后先给出来确认再往下写代码 —— 15 张表建错了,后面 13 个阶段全部白做。
