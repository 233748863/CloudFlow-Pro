## 2. SYS-06租户套餐

2026-09-28补充裁决：无独立页面的19项既有功能允许在套餐内独立勾选，未选中时禁止使用；仍须具有原角色权限及通过原业务/平台身份校验。固定保留仅900、901、906三项账号操作，不扩大为全部公共功能。19项为876—884、902—905、1206—1208、1762、1985、1986；登记时同时匹配菜单编号与权限码，不能自动放行其他无页面按钮。普通按钮仍必须明确选中最近的业务页面，父目录自动补齐。

套餐包含菜单/按钮、模块、用户数与MB存储配额；价格仅展示，不添加付费/扣款系统。菜单必须存在且模块合法，自动补父目录，功能按钮缺对应页面时拒绝。新租户从选定套餐初始化effective_menu_ids和配额，随后角色授权只能取有效菜单集合中的子集。

服务器权限=当前角色权限∩套餐/个别覆盖的功能上限；登录菜单、按钮权限、直接HTTP和报表/搜索均使用同一功能门禁。tenant ADMIN的通配权限不能绕过已配置套餐；只有平台控制面的管理操作按平台身份执行。package_id为空的现有租户不被本次升级暗改授权。套餐下线不自动删除租户或业务数据。

`package_override`存明确增加菜单、移除菜单及配额覆盖。同步时先套餐→加项→减项→合法父目录闭包；同一菜单同时增减视为冲突，移除父模块与子按钮冲突须用户确认，不静默还原。有效配额小于当前使用量时显示超额并阻止新增用户/文件，不删用户、不删文件，原读取可用。

批量同步先生成预览批次及逐租户before/proposed快照，展示精确租户数、权限增减、配额及覆盖冲突；预览有效期5分钟，二次确认携带syncId/previewHash，必须同一平台操作人。每租户短事务锁行核对version后应用；版本变动标CONFLICT，不覆盖并发个别调整。重试只处理未成功项，已APPLIED不可重复写。结果COMPLETED/PARTIAL/CANCELLED均逐项审计；更新权限版本并使旧会话权限缓存失效，不能只改菜单树。

| `POST /system/report/share` | `system:report:share` | 本人的chart/dashboard、shareScope、version |

## 4. INT-05文件预览

格式只支持PDF、PNG、JPEG、GIF、WebP；按文件实际内容及存储元信息双重判断。SVG/HTML/XML或伪装扩展名一律不进入内联渲染，保持有权限的下载回退；Office提示“暂不支持预览，请下载查看”，不接LibreOffice/kkFileView。

PDF.js选定6.3.289（npm元数据要求Node>=22.13.0或>=24，当前Node24.1.0满足），worker及字库随构建自托管，不从CDN加载。懒加载预览路由，使用独立worker，禁止PDF脚本、外部自动请求和嵌入附件执行；文字层提供搜索、页码跳转、缩放，长文档逐页渲染。图片由受保护字节创建Blob URL，提供缩放/旋转/键盘控制，关闭后revokeObjectURL。单文件预览上限20MiB，超出明确提示下载；下载仍遵守原文件上限。

新预览注册表按bizType调用已有业务权限函数：流程表单经`WorkflowFormFileService.metadata`核验定义/实例/任务/字段及可见值；OA走各业务归属再调用`OaPrivateFileStorageService`；HR走原工资、简历、证照等人员范围；公共文件仍经`SysFileServiceImpl`公共标志检查。尚无适配器的业务不能默认放行，返回下载入口及说明；首批适配PRD列举的合同、证照、知识库、报销发票、简历、履约证据、供应商资质和审批表单附件，不能只做公共图片展示。

`POST /system/file/preview-ticket`以`system:file:preview`保护，输入fileId+bizType/bizId及必要任务字段上下文，返回格式/大小及60秒签名的应用内流地址。签名绑定租户、登录域、用户、文件、业务上下文和有效期；GET流必须同时验证当前登录及当前业务权限，Range分段请求也重新验证。私有文件通过应用流式代理，不直接重定向为可绕过权限撤回的存储直链。返回no-store/nosniff/no-referrer和精确Content-Type；签名参数及文件内容不得写访问日志。敏感预览记录用户/文件/业务/时间/结果，不记录正文。

H3门户预览若启用也只使用独立portal权限和门户文件适配器，内部fileId不能作为外部访问捷径。浏览器测试覆盖同数值不同登录域用户ID、撤回字段权限、旧版本/旧快照附件及过期签名；C3已存在的旧快照附件边界仍须在最终联调复核，不能由本设计提前记为通过。

## 5. SYS-08动态数据源

功能默认关闭，仅平台超管和再认证可操作。只支持已安装MySQL驱动，URL只接受`jdbc:mysql://白名单主机:端口/数据库`，拒绝任意JDBC参数、userInfo、片段、多主机、自动反序列化及本地文件开关。主机/端口/库白名单由部署侧维护，不能通过同一管理界面放宽；DNS解析结果也须允许，防DNS重绑定/SSRF。禁止覆盖master/default/当前primary及其他配置已有ds_key，不允许浏览器传ds_key切换业务读库。

密码用现有AES-GCM密钥组件按数据源用途封装，主密钥缺失时禁止保存启用；随机IV、防篡改、非空往返测试必做。列表/详情仅返回configured标志，编辑用KEEP/REPLACE/CLEAR明确意图，不把星号保存成密码；CLEAR仅允许停用配置。connect/socket超时5秒，除获批的固定只读权限清单核验外，连通性测试只执行固定SELECT 1，要求专用只读数据库账号。连接池初始0、默认最大5、上限20，不暴露任意驱动类加载。

配置事务提交后向服务器允许的服务名分发版本。auth经现有服务发现得到真实实例地址，调用受保护内部注册接口，目标服务自己验证来源和配置版本，先建新池并固定查询测试成功，再原子替换同一命名池；失败保留旧可用池并报FAILED。旧池只在无活跃连接或60秒宽限到期后关闭，不能影响master。每实例实际采用版本写`sys_data_source_registration`，某实例失败不能显示整项成功。

A3维护一个集中重试/核对任务，按服务发现逐实例广播未应用版本；各服务启动时读取获准配置并恢复本地池。离线节点标STALE，恢复后补应用；关闭配置后重新启动也不加载。此次不把SYS-08数据源开放给LC-06自由报表，两者权限与用途独立。

| 接口 | 权限码 | 契约 |
| --- | --- | --- |
| `GET /system/data-source/list`、`GET /system/data-source/{id}` | `system:data-source:list` | 平台身份，脱敏配置及逐实例状态 |
| `POST/PUT /system/data-source` | `system:data-source:manage` | 网络白名单、secretAction和版本校验 |
| `POST /system/data-source/{id}/test` | `system:data-source:test` | 5秒固定连接测试，不接受SQL |
| `POST /system/data-source/{id}/register`、`POST /system/data-source/{id}/disable` | `system:data-source:register` | 明确目标服务与高风险二次确认 |
| `POST /inner/{module}/data-source/apply` | `@Inner` | 仅部署允许的auth来源、configId和版本，不能携带任意URL覆盖 |

## 6. SYS-03 OAuth2服务端

OAuth2 = 第三方应用经用户或专用应用账号批准后，只访问已授权范围的接口。沿用Sa-Token，新增oauth2登录域及scope门禁，不再建设账号/角色平台；H3同时接入的portal域在`CloudFlowStpInterface`中分别读取，不能按同数值内部loginId串权。

支持authorization_code、client_credentials及授权码模式的refresh_token兑换；拒绝implicit/password和未注册grant。client_credentials只允许CONFIDENTIAL，绑定专用低权限服务账号，不能默认绑定管理员，不发refresh token。客户端加密密钥仅创建时通过受保护通道展示一次，普通读接口脱敏；公共客户端无client_secret。客户端状态默认DISABLED。

scope固定注册为`profile`、`crm.customer.read`、`workflow.instance.read`、`system.tenant.read`：分别是本人最小资料、原CRM数据范围内客户只读、原流程可见范围内实例只读、当前租户基础名称/编号。客户端scopes/authorities/resource_ids均只能选注册子集，不接受星号、任意角色或内部管理权限。实际能力始终为客户端上限∩已同意scope∩用户当前业务权限∩租户套餐。个人令牌不能访问别人的工资或直接成为内部普通token。

授权码流程：内部用户先登录→验证client与精确redirect_uri→校验response_type=code与S256 PKCE→创建与当前内部会话绑定的PENDING授权事务（5分钟）→展示第三方名称、每项scope及拒绝按钮→POST带一次性事务令牌确认→生成32随机字节授权码，仅存SHA256，2分钟有效→token端点核验客户端、相同redirect_uri和PKCE verifier，在同一数据库事务原子消费并发码。

redirect_uri按注册字符串精确匹配，禁止通配、片段、userInfo、重复参数歧义和开放重定向；生产只允许HTTPS，隔离测试只允许明确配置的loopback HTTP。无效redirect不跳回输入地址。state原样返回但不放宽服务器会话绑定；拒绝授权返回access_denied且不生成令牌。自动同意只限用户已有有效同意和客户端auto_approve_scopes子集，不能由第一次访问自动扩权。

access/refresh token都是32随机字节的不透明值，数据库只存SHA256。访问有效期默认900秒、可配60—3600秒；刷新默认604800秒、可配3600—2592000秒。网关OAuth适配器先哈希外部Bearer并校验数据库有效状态，再使用专属Sa-Token会话投影；数据库哈希不能当外部Bearer使用，不能把OAuth token直接交内部默认StpLogic。每次请求还检查用户/客户端状态和当前权限，缓存只是可重建投影。

刷新时锁原token行，ACTIVE→USED且生成新access/refresh，scope不能扩大；旧刷新令牌再次使用撤销整个family及其访问令牌。撤销本人同意、客户端停用、用户禁用和策略版本变化立即令牌失效并清理会话投影。token/revoke响应带no-store；日志屏蔽Authorization、code、verifier、client_secret和令牌正文。

| 接口 | 权限/认证 | 契约 |
| --- | --- | --- |
| `GET /system/oauth2/client/list` | `system:oauth2:client:list`+平台身份 | 脱敏客户端及有限授权范围 |
| `POST/PUT /system/oauth2/client`、`POST /system/oauth2/client/{id}/disable` | `system:oauth2:client:manage`+平台身份 | scope注册验证、专用账号校验、密钥更新审计 |
| `GET /oauth2/authorize`、`POST /oauth2/authorize` | `system:oauth2:authorize`，内部登录域 | 仅本人授权，GET展示/POST确认，CSRF事务绑定 |
| `POST /oauth2/token` | 独立客户端认证+限流 | HTTP Basic机密客户端；公共客户端只PKCE授权码，不接受密码模式 |
| `GET /oauth2/userinfo` | oauth2域+profile scope | 仅本人基础资料；client_credentials拒绝 |
| `POST /oauth2/revoke` | 客户端认证+令牌归属 | RFC风格相同成功响应，不枚举他人令牌；实际归属必须匹配 |
| `GET /system/oauth2/grant/mine` | `system:oauth2:grant:list` | 仅本人已授权应用及scope |
| `POST /system/oauth2/grant/{id}/revoke` | `system:oauth2:grant:revoke` | 仅本人同意，整组相关令牌撤销并审计 |
| `GET /oauth2/api/crm/customer`、`GET /oauth2/api/crm/customer/{id}` | oauth2域+crm.customer.read | 复用CRM权限与逐字段只读VO |
| `GET /oauth2/api/workflow/instance/{id}` | oauth2域+workflow.instance.read | 复用实例可见及C3字段权限，不返回原始variables |
| `GET /oauth2/api/system/tenant` | oauth2域+system.tenant.read | 仅当前租户编号和名称 |

token端点每client+IP每分钟10次、额外IP每分钟60次；authorize每用户每分钟10次，userinfo/资源每令牌每分钟60次，revoke每client+IP每分钟20次。认证失败、PKCE失败、code复用、refresh重放和越权均审计。公共端点在静态规则中按真正协议认证入口处理，不能把资源接口标匿名绕过鉴权。

## 7. INT-06业务搜索

一期菜单搜索继续使用已授权菜单，最近访问按用户/租户隔离。二期搜索六类：客户、合同、员工、流程实例、工单、资产；不引入ES。`GET /system/search/business`以`system:search:business`保护，关键词按Unicode码点2—64字符，300ms防抖并取消旧请求，少于2字符不请求。每用户每分钟30次，每类默认5条最多10条，总结果最多60条。

auth聚合到CRM/OA/HR/workflow的`/inner/{module}/search`，传递服务器生成的可信用户上下文；客户端不能指定用户、租户、SQL排序或服务地址。模块服务先查原菜单/业务权限及数据范围，按固定白名单搜索名称/编号字段，转义LIKE通配符，先过滤再limit；字段只返回有权展示的标题/类型/状态/合法详情路由。薪资、手机号、证件号等不作为默认搜索正文。单服务超时2秒显示该模块暂不可用，不能把超时当“无数据”。再次点击详情仍走原权限，不把搜索命中当通行证。
