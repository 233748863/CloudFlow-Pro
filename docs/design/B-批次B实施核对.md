## M8 触发节点及上线前置条件

扩展原 SCRIPT 处理器。旧 API 保留同步执行，Groovy 保留既有沙箱及启用开关；新 HTTP_CALLBACK、INNER_SERVICE、MESSAGE 默认异步。失败 BLOCK 写 FAILED 并告警，SKIP 留痕继续，TO_DLQ 写既有回调死信后继续；重放成功才标记 REPLAYED。异步复用事务消息和既有扫描入口，暂停不消耗重试，完成消息不会重复推进流程。

上线必须先盘点现有 SCRIPT 的内网目标，在运行环境配置并验证 workflow.trigger.url.whitelist，再发布防护版本。白名单种子为空，不填入猜测的生产地址；空白名单明确拒绝全部外调。只允许 HTTP(S)，校验域名全部解析地址，禁自动重定向及隐式重试；普通内网须显式白名单，云元数据即使在白名单也拒绝。DNS 重绑定未覆盖，按决策保留为风险。

同步外调默认超时 10 秒，配置范围 1—60 秒，同步重试共用该时间预算；响应上限 1 MiB，独立 HTTP 线程池最多 8 线程、64 个排队请求。异步、死信及敏感请求头使用 AES-GCM，加密密钥复用 CLOUDFLOW_ENCRYPT_AES_KEY，要求 16、24 或 32 字节，上线前必须配置。

标准保存、导入、模板创建和更新统一保护敏感头；定义、模板、版本、差异、发布快照和导出均脱敏，即使导出勾选包含敏感数据也不返回触发密钥或密文。导入脱敏导出文件到新定义时须重新填写密钥。先加密再过滤展示文本，防止过滤改变密钥；新 actionUrl/actionMethod/actionHeaders/actionBody 保留机器请求内容，前端仅用文本输入及普通文本展示，避免多次保存破坏 JSON。旧 API 与 Groovy 的过滤及解析路径保留。

X-Workflow-Trigger-Id 在重试、死信重放中保持稳定。外部调用与本地事务无法严格原子提交，接收方必须按该请求编号去重；本地已完成事务消息会阻止重复流转。定向检查使用 Mapper 替身、本机 HTTP 服务及真实 Groovy 沙箱，不替代部署环境的 Redis/MySQL/消息通道集成验收。
