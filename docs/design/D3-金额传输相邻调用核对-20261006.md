# D3金额传输相邻调用核对

当前产品B102/F61。`HrMoneyHttpConfig`将HR接口的BigDecimal金额按文本传输，内部JSON与摘要继续使用独立mapper。本次仅核对调用路径，没有修改产品，也没有把源码检查计为实际页面验收。

| 调用方 | 已核对的处理 | 结论 |
| --- | --- | --- |
| 员工假期余额页与自助门户 | 汇总和逐条展示均先通过`Number`转换，再调用`toFixed` | 此处未发现文本调用数字方法的问题 |
| 绩效完成率与评分 | 完成率组件先转换；`performance.ts`的列表和详情均经`normalizePerformanceObjective`，评分转为数字后传入页面 | 评分页的可选`toFixed`有实际转换上游，此处未确认显示为0的故障 |
| 薪酬模拟器 | `HrCompensationSimulatePanel`按数字直接格式化结果；`batch2.ts`请求与响应类型未对应当前服务端契约 | 待单独复现和处理，不能声称模拟器已通过 |

薪酬模拟器的具体不一致：页面发送`baseSalary/performanceBonus/positionLevel/socialBaseAdjustment/overrideItems`，服务端要求`structureId`，接收`gradeId/componentOverrides/specialDeductions/socialBase/socialPersonalRate`；页面读取`grossSalary/socialInsuranceTotal/individualTax/items`，服务端返回`gross/socialPersonal/personalTax/breakdown`。`netSalary`名称相同，但页面直接调用其`toFixed`，尚未支持金额文本。以上为源码事实，实际请求、计算口径、租户及页面行为仍需独立验证；本记录不改变已完成的大额工资发放证据或全量验收状态。
