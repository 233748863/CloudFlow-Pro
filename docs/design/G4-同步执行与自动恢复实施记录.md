本轮按已批准的外部接入总设计实现1784执行接口、执行明细和A3恢复处理器。2026-09-29续接完成真实执行HTTP336项及1000人完整同步184715毫秒，修复逐人缓存清理性能问题；原输出及失败轮次见G4-同步执行HTTP与性能复核-20260929.md。1784权限和A3任务种子尚未开放，周期新快照调度未验收；下列内部恢复记录保留其原验证时点。

## 页面布局

```text
组织同步报告
  批次 / 配置版本 / 预览或执行状态
  实际已处理 / 剩余 / 安全清理状态
  原预期变更与逐项处理结果
  [核对原批次进度] [勾选确认] [执行/继续本批]
```

沿用现有BaseDialog、Button、card及语义色，电脑并列、320px单列；控件至少44px，沿用既有短交互和减少动画规则，不新增主题或外部字体。未处理项目保持预期标记，已处理项目显示实际动作或冲突；账户安全清理可能使当前登录失效，提示重新登录查询原批次。

## 恢复约束

确认人的账号ID写入加密进度，不保存登录凭据；后续业务写入逐批复核其当前租户、管理员身份、角色和套餐权限，配置版本和本地摘要仍须一致。安全清理独立恢复，不依赖当前应用开关、原确认人的登录会话或权限。旧密文没有确认人时仅允许安全清理，继续业务写入需要真实管理员重新确认。

恢复处理器只扫描已进入APPLY且RUNNING的记录，不自动执行未确认预览，不发起新的厂商读取；按主键分页，每次最多100批次，4分钟总预算，每批次最多40个写入或安全清理小批。每个小批仍受数据库锁与100条上限保护；失败独立统计、不打印敏感异常。

## 失败轮次与修正

日志均在`.cloudflow-runtime/full-prd-20260915/approved-runtime/`，保留失败轮次，不覆盖原输出。

- `g4-im-runner-security-20260929-r1.log`：新增primitive确认人缺省值与严格反序列化冲突；仅对缺失该字段注入0，保持旧规范摘要，其余严格解析不放宽。最终`g4-im-runner-security-20260929-r5.log`通过。
- `g4-im-runner-database-20260929-r1.log`：JDBC读取可能消耗入口中断标记；执行器在读取前记录中断状态，恢复标记并停止写入。R2修正坏记录夹具遗漏必填snapshot_hash。
- 数据库R3/R4：新增恢复测试遗留UserContext，旧清理测试只切换TenantContext，导致其他公司缓存夹具写到错误公司。修复测试上下文恢复、统一夹具的两处公司身份，并在写入夹具时核对缓存实际名称。R4曾只延长测试缓存有效期，未解决根因；最终R5完整通过，生产缓存路由未改。测试缓存有效期30分钟仅用于避免长回归自然到期。
- 登录回归R1遇到隔离验证码每日100次限制，只清除已核实归属的`CAPTCHA:LIMIT:127.0.0.1`一键，其他键未清理，再运行R2；结果以独立最终复核日志为准。
