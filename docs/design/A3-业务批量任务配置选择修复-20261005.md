# A3业务批量任务配置选择修复

## 问题与既有依据

D2千人整月异步验收准备时，隔离环境中同一租户、HR服务和hrAttendanceRecalcAsync处理程序存在三份有效配置：系统预设1455无固定参数、3600秒执行限制；1984和1988各有119字符固定参数、60秒限制。上述编号仅为本轮环境取证，不写入产品选择逻辑。

《A3-SYS-02-定时任务平台-PRD.md》的配置唯一键包含处理参数，允许相同处理程序存在不同参数的任务；《D-批次D实施核对.md》及正式06种子已将考勤重算、薪资批次计算设为业务手动触发、暂停计划的无固定参数配置，批量导入同样有无固定参数的预设配置。原registerBusinessJob只按租户、服务、处理程序调用selectOne，遇到三份配置将产生多结果错误，无法登记业务批量任务；此处为源码及真实配置核查，尚不代表千人HTTP已执行。

## 修复

业务登记仍校验内部调用身份、来源服务、处理程序、租户和执行编号，只从同租户、同服务、同处理程序的无固定参数配置中选择唯一一份，随后使用业务调用本次提交的参数。空、NULL及仅空白参数统一判断；不存在或重复时给出明确错误，不任意挑选配置。管理员对指定任务的手动触发和参数覆盖继续走原按任务编号的路径。

此修改使用已有字段与正式预设配置，不新增表、字段、依赖或配置项，也不删除或改写两份参数化任务。B87完整构建原进程54113退出0、3830份输入保持，auth重载原进程80540退出0。千人专项R1实际一次登记关联通用配置1455，原三份配置均保持；880.02毫秒返回执行编号，原任务SUCCESS及30000条日结论、1000份月汇总准确，员工和人事不能读取管理员任务。1065项/1027请求/5333输入保持、原进程41921退出0，详见《D2-千人整月异步重算实测-20261005.md》。缺少或重复通用配置的明确错误目前为源码核验，未在本轮改写预设配置构造故障。
