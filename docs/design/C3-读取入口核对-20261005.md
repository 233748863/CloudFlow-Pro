# C3读取入口核对

当前核对产品为B77/F50。本清单按实际响应、访问拒绝和源码返回边界记录AC-3证据；统一验收由`scripts/summarize-c3-current-acceptance.ps1`核对，不能以统一返回过滤器的存在替代各入口实际验证。

## 统一过滤与内部边界

`WorkflowFormResponseAdvice`作用于workflow控制器的JSON响应；对实例权限上下文先校验访问资格，再过滤`variables`、`formData`、`variablesChanged`、`formDataSnapshot`，并处理`modelJson`、`snapshotJson`、`snapshotData`、`activeTasks`中的内嵌JSON及表单定义。`@Inner`接口跳过该处理；引擎内部保留完整数据。

`WorkflowOAuthResourceController.detail`虽为内部接口，仍在已核验的第三方身份上下文中调用`forms.projection`，向外返回其可见值；R73已通过真实授权码/S256/本人确认至资源读取的完整链路。企业微信待办摘要采用已批准的外发字段白名单，其专项结果不替代C3。

## 源码返回边界（不计新增HTTP验证）

- 设计历史的具体入口还包括`GET /versions/workflow/{workflowId}`、`/versions/{versionId}`、`/versions/compare`、`/deploy/snapshot/{processDefId}/{version}`、`/deploy/rollback/versions/{processDefId}`和`/import-export/export/{workflowId}`；流程图还包括`/enhance/flowchart/definition/{definitionId}`。R68已分别验证设计权限和实际响应内容。
- HR的`WorkflowServiceClient.getProcessInstance`调用外部`/wf/instance/{processInstanceId}`，接收的`ProcessInstanceVO`只有流程身份、状态及时间等属性，没有表单变量或定义字段。该结论为类型和调用路径核对，不替代HTTP验收。
- 跨模块XML中，`CrmRefundWorkflowMapper.instance`确实读取完整`variables`；唯一服务使用点为`CrmRefundWorkflowService.verifyResult`的内部退款回调身份、冻结依据和审批历史校验，方法返回void，不直接返回该实例对象。其他跨模块查询涉及借款、录用、离职结算、合同及支付的状态/业务绑定校验，完整外部返回追踪见下文。
- `GET /wf/form-files/{fileId}`与`/{fileId}/content`先取得按字段权限过滤后的定义，再核对文件所属定义/实例/字段、当前可见值及上传人；预览的内部授权入口复用同一metadata校验。基础链验证上传者未绑定读取、其他人/跨租户拒绝、绑定后旧草稿上下文拒绝和真实下载；R75补齐隐藏字段附件的直接访问、预览与伪造路径拒绝。
- `GET /wf/task/{taskId}/form-references/{fieldId}`要求当前TODO任务办理权限（现有管理员权限也允许），按固定表单版本过滤字段定义，隐藏/只读字段拒绝选项；`GET /wf/draft/context/{definitionId}/references/{fieldId}`核对发起权限、引用类型与父级/字段隐藏权限。选项对象仅含id、label、departmentId，R75已实际核对。
- OA的`WorkflowServiceImpl.getProcessStatus`通过内部客户端取得流程对象，Map分支只提取status；非Map分支会转成字符串。本轮全仓Java搜索仅发现该方法接口声明与实现，没有实际调用方；HR的getProcessInstance同样只有客户端声明与降级实现。当前没有对应外部返回链可实际触发，不新增接口凑验收；仍与其他业务模块查询分别核对。
- 工作流内部全局搜索最终查询返回id/title/number/status，代理任务整行仅供内部访问资格判断；工作流报表最终查询使用状态、日期、部门、办理人及数量/时长等汇总列，不读取表单variables。加签待办与加签上下文类型没有表单值属性。上述属于返回链源码核对，不替代全局搜索/报表所属PRD的实际验收。
- `POST /enhance/task/agent-return`返回WfTask；服务仅取得任务行、保存归还记录并解除代理绑定，未填充非持久化variables。R78已实际核对两种模式返回，普通待办读取和动作结果分别留证。

## R75执行期间补充的跨模块返回追踪

HR的`HrAdvanceApplicationMapper.approvalTaskAdvance`以流程businessType/businessId及任务历史校验访问资格，查询仅返回借款ID；`HrAdvanceApplicationService.approvalDetail`再组装`HrAdvanceViews.Approval`，数据来自借款业务记录，不返回工作流variables。录用`HrOfferMapper.decisionMatches`只返回计数，结算`HrSettlementApprovalMapper.instanceStatus/decisionMatches`只返回状态/计数；结算审批详情由`HrSettlementWorkflowService.approvalDetail`校验独立财务身份后调用本模块`drafts.detail`，返回`HrSettlementView`。这些业务详情继续由所属PRD验收其业务查看权限，当前结论限于未将原工作流实例变量直接返回。

OA的`OaHrPaymentMapper.approved`、`OaSettlementPaymentMapper.approved`仅返回计数；`PortalContractMapper`把工作流状态作为公开范围条件；`OaContractPerformanceMapper`仅取得审批结束时间。其XML中引用variables的地方均为业务绑定条件。CRM的`CrmRefundWorkflowMapper.instance`完整读取variables，但唯一使用点仍是返回void的`CrmRefundWorkflowService.verifyResult`内部校验；CRM详情控制器返回本模块`CrmApprovalVO`。另见上面的OA/HR远程客户端声明与无外部调用方结论。

`ReportDatasetService`仅采用`ReportRegistry`服务器登记字段；WF_INSTANCE/WF_TASK登记的维度和度量没有variables，动态数据源控制器只应用连接配置。`WfProcessSnapshotMapper`仅在`NodeExecutionServiceImpl`与`AsyncWorkflowServiceImpl`调用insert，无对外读取调用；R8含内嵌快照返回形态的过滤检查，实际轨迹无快照内容。

上述属于源码返回链核对，不冒充新的HTTP验证；代理归还返回内容与归还后权限已有独立R78实际证据。
