# G2 新租户导入任务开发记录（2026-10-17）

## 范围与根因

G2 AC-11/AC-15/AC-16依赖业务任务登记；`ImportEngine.dispatch`在校验和导入时均登记`batchImport`。正式种子仅为租户100000建立四份无固定参数任务，正式租户创建入口`TenantAssignmentService.create`未建立这些配置，新租户首次校验和导入因此被拒绝。2026-10-02映射中隔离租户手工补配置的边界属于真实功能缺口。

## 实现

- `JobPlatformService.registerBusinessJob`对已批准auth/hr/oa/crm的`batchImport`在缺少配置时按需建立当前租户任务；原配置、服务全名别名及固定参数计划保持，存在多份通用配置继续明确拒绝。
- `SysJobMapper.lockActiveImportTenant`核对租户存在、正常、未删除和未到期，锁定当前租户行；随后使用锁定读取重新查询任务，避免多个实例同时首次使用及MySQL重复读快照造成重复配置。新增配置与执行日志沿用同一事务。
- 自动配置沿用种子：暂停状态，仅业务手动触发，允许独立任务并发，超时/锁600秒、失败告警和零自动业务重试。非导入业务未自动配置；导入到期清理现有处理器遍历活跃租户，无需为每租户复制清理计划。
