## 1. 管理、分配与取消边界

`TenantPackageController`有9个业务入口：列表、详情、功能目录、新增、编辑、同步预览、同步详情、确认、取消。仅使用已批准的`system:tenant-package:list/manage/sync`三权限，服务层再次核验平台身份和五分钟内再认证。返回禁止缓存，写请求限流、操作日志不记录输入。确认与取消依赖数据库持久状态保证重复操作不重复应用，不通过请求缓存返回过期的批次状态。

`TenantPackageManagementService`按服务器目录及正式规则校验模块、页面、按钮、19项独立功能和3项固定账号操作，保存含合法父目录的完整功能集合；金额仅作展示，状态为DRAFT/ACTIVE/DISABLED。更新锁模板并核版本，版本耗尽或并发冲突拒绝。模板更新不自动重算现有租户；编码唯一冲突和审计失败均回滚全部变更。

`TenantAssignmentService`接入既有租户POST/PUT入口。`TenantSaveRequest`只接受可编辑资料、租户版本、旧未分配租户的配额及明确的`packageSelection`。请求不接受`effectiveMenuIds`、顶层`packageId/packageVersion/packageOverride`、`storageUsed`、`deleted`及审计字段；嵌套覆盖也拒绝未知字段。

明确选择的请求结构：

```json
{
  "packageSelection": {
    "packageId": 123,
    "packageVersion": 0,
    "adjustments": {
      "addMenuIds": [1762],
      "removeMenuIds": [1986],
      "maxUsers": 5,
      "maxStorageMb": 20
    }
  }
}
```

该示例只解释请求结构，不是正式套餐或授权种子。新增租户必须选ACTIVE模板；已有租户省略选择时保留原套餐、已应用版本、覆盖、有效菜单和配额，不偷偷切至最新模板，不通过空值解除套餐。旧`package_id=NULL`租户保持旧授权，并可继续编辑原配额；明确选择套餐时才按模板及所选覆盖初始化。分配时先锁模板再锁租户，核对模板和租户版本；与逐租户同步采用一致锁顺序。配额低于已有使用量不删数据、不截断使用量，新增用户/文件的并发准入接线仍待完成。

资料编辑中省略的可选联系信息、注册邮箱域名、域名、期限、备注保留原值，文本明确传空串可清空；保持既有期限空值不覆盖语义。本轮发现新全字段XML更新会把未提交的注册白名单置空，已在生产服务补保护并通过专项，不以修改联系信息扩大允许注册范围。

同步取消绑定原操作者和完整摘要，锁模板及批次；已应用项保留，未应用项停止。重复取消不重复审计，审计失败回滚状态，确认的逐项执行及最终状态不能覆盖CANCELLED。已全应用、尚未最终标COMPLETED的恢复窗口也拒绝取消，避免全部成功却显示取消；重复确认可恢复最终完成状态。

最后一项提交与取消同时发生的真实锁等待测试又复现了旧快照问题：取消在等待模板锁之前读到旧批次，默认可重复读事务在等锁结束后仍看不到刚提交的APPLIED项。`TenantPackageStore`现将短写事务明确设为READ_COMMITTED（读已提交 = 每次普通查询读取查询时已提交的数据），保持已有行锁和版本核对；取消等锁后读取真实已提交明细。测试暂停生产逐项事务提交及最终批次收尾，并通过MySQL锁等待表确认真实竞争，修复后不会把已全应用批次标成取消。

## 2. 平台例外边界

公共权限层通过`PlatformPermissionPolicy`的惰性提供者连接auth平台身份服务，避免鉴权递归；普通业务服务没有该提供者时不获得例外。平台候选权限必须同时匹配内部当前令牌、真实账号归属及有效状态、部署侧管理租户与账号名单，然后继续与原角色权限求交。

控制面集合精确为14项：套餐3、数据源4、OAuth2客户端2、既有租户列表/查询/新增/编辑/删除5。租户切换903和其他18项独立业务功能均不在例外集合；普通ADMIN及仅有相同数字编号的门户/OAuth2用户没有例外。平台名单撤销、账号禁用/删除、归属变更或会话切租户立即撤销候选集合。

`AuthController.info`、权限提供器、用户上下文及内部OAuth客户端管理读取交集；OAuth资源身份继续走纯套餐交集。平台控制面入口可到达再认证界面，但业务操作仍必须有未过期的再次身份验证。共享再认证入口在原套餐、数据源、OAuth2客户端3项入口权限外，复用既有`system:tenant:list`，防止仅具租户管理权限的真实平台账号无入口可验证；没有增加新权限码。

菜单树仅为真实平台账号补入原角色实际拥有的控制面页面及可用祖先；角色可授权菜单目录不增加控制面例外。新增7项数据库菜单检查中包含“有ADMIN名称但无原角色权限不得展示控制面”“祖先停用拒绝”“可见页面不扩大可授权菜单”。平台身份本身在另一个真实Sa-Token专项验证，菜单数据库专项使用明确控制的策略替身，不混计为真实平台HTTP。
