## 批准依据与范围

客户门户只向当前有效账号关联公司的客户开放合同。列表、详情、分页总数和关联资源统一使用同一开放条件，不以客户端传入的客户、租户或内部员工身份作为归属依据。销售业绩使用的“合同开始日期到达”条件不改变门户已经确认的开放时点。

当前正式结构338张表；本阶段基础合同读取复用已有`oa_contract`、`wf_process_instance`和门户身份字段，不新增内部角色授权或菜单。门户权限沿用`crm:portal:contract:list`及独立`portal`登录域，不写入EMPLOYEE角色。

## 当前核验与实现边界

- 已有合同保存双方签署信息、签署文件和审批实例。实际业务以本租户`biz_contract`流程、匹配`CONTRACT:合同ID`的审批实例通过记录核对审批，不能只凭可变的合同状态文本开放；签署需核对已签标记、双方签署时间和现有签署依据，未来签署时间不能提前开放。
- OA数据服务复核门户账号、联系人、客户、租户状态及会话版本，查询中再次限定当前租户和客户。合同查询及返回值独立定义，不序列化完整内部合同实体。内部接口只接受认证服务的可信调用，同时校验原门户凭据。
- 对外基础字段限定合同编号、名称、对手方、金额币种、日期和外显业务状态；金额保持现有18位、2位小数精度。内部风险、预算、团队分成、审批意见、签署人个人信息、内部备注和文件存储地址不对外返回。
- 未满足开放条件、其他公司或其他租户、已删除合同统一返回不可访问；拒绝多余查询字段、重复参数及身份覆盖。门户默认停用、HTTPS与来源校验、每用户每分钟60次和访问审计沿用现有实现。

2026-09-24用户已确认：履约条款、关键节点和付款计划均逐项选择公开，未选择的仅内部可见。现有三类明细表没有保存公开选择的字段；持久化方案是在`oa_contract`增加`portal_term_ids`、`portal_milestone_ids`和`portal_payment_schedule_ids`三份JSON清单，默认NULL按空清单处理，不新建表。三份清单同时按合同版本保存，变更前复核全部项目均属于本租户、当前合同且未删除；普通新增、编辑和导入不能直接改写公开清单，防止绕过专门的公开操作。本段为用户裁决的技术补充，已合入正式初始化SQL和自有回环测试库，正式服务器未修改；物理表仍为338张。

公开维护沿用当前`oa:contract:edit`及合同数据范围。真实隔离库核对该权限仅授予ADMIN(role_id=1，ds_type=0)和LEGAL(role_id=6，ds_type=4)，EMPLOYEE无此权限；不添加菜单、角色或授权。公开与撤回记录前后审计；查询明细时再次核对当前合同的开放条件及所选清单，取消选择或项目删除后立即停止外显。选择项目不公开内部备注、内部人员、签署人个人信息、证据附件或文件存储地址。

## 实施接口与字段边界

内部使用`GET/PUT /oa/contract/{id}/portal-publication`读取候选及保存整组三类清单；读写均沿用`oa:contract:edit`。请求只接受当前合同版本及三类项目编号，不接受租户、客户、公开状态或其他合同字段。每类清单最多1000个正整数编号，不能重复，保存前先锁定合同，使同一合同的公开选择及项目删除串行，再锁定所选明细并核验合同及租户归属；任一项无效全部拒绝。锁定结果按编号规范排序后核对完整清单，不依赖数据库返回顺序，保留租户拦截。清单与合同版本一起保存，空清单明确撤回该类全部项目，不自动重试不确定的写入。

删除所选项目与撤回该编号在同一事务内完成，保留前后审计；既有条款删除后复用编号时也清除旧选择，新内容不会继承已删除条款的公开权限。节点与付款计划的普通修改禁止换合同、换租户或直接标记删除。真实MySQL测试曾发现租户SQL解析器把`ORDER BY ... FOR UPDATE`序列化为无效顺序，已去除锁定查询中的排序并在核对时排序；未关闭租户校验，三类多项及同版本竞争均已重测。

跨服务身份复核沿用认证服务先解密核对CRM邮箱、核对联系人版本，再由OA复核门户账号/联系人/客户/租户状态及两种版本；禁止直接把`crm_contact.email`密文与门户邀请邮箱在SQL中比较。首次真实联调发现此误拒问题，修正后须重新执行真实邀请登录及合同查询，不能用纯数据库身份夹具替代。

外部沿用设计路由`GET /portal/crm/contract/list`和`GET /portal/crm/contract/{id}`，认证服务通过仅允许自身调用的OA内部接口读取。列表仅允许搜索词、页码及每页条数；详情不接受额外查询条件。所有查询使用同一真实审批、签署、租户、客户及有效门户身份条件；草稿、待审批、驳回和取消状态不得开放。已到期或终止的签署合同保留符合条件的历史查询，不据此重新计业绩。

| 合同主信息 | 编号、名称、对手方、金额币种、开始/结束日期、外显履行状态 | 租户/客户内部编号、人员、审批实例/意见、风险、预算、团队、备注及文件地址 |

## 页面方案

沿用门户字体、浅深主题和现有组件，手机单列、电脑列表；44px触控区，按钮150ms、弹窗200ms过渡，尊重减少动画设置。只读查询失败保留筛选条件、明确提示未加载；账号失效清理门户数据，不注销同浏览器内部账号。

```text
+--------------------------------------------------+
| 本公司合同                     [返回客户门户]    |
| 合同名称或编号 [查询]                            |
| 编号 / 名称 / 金额与币种 / 日期 / 状态            |
| [查看合同]                 [上一页] [下一页]     |
+--------------------------------------------------+
| 合同详情：已开放的合同基础信息                   |
| 履约条款、节点和付款计划：仅显示内部已选公开项目   |
|                                          [关闭] |
+--------------------------------------------------+
```

内部合同详情的公开维护独立成面板，仅向已有维护权限的人显示；预先勾选不跳过审批和签署。未保存或结果未确认时保护草稿，刷新核对只读取当前结果，不覆盖草稿或自动再次公开；用户明确采用服务器结果或保留草稿后才允许下一次保存。

```text
+--------------------------------------------------+
| 客户门户公开范围                   [核对最新结果] |
| 合同开放条件与当前保存版本                        |
| 履约条款       [ ] 序号 · 内容 · 期限             |
| 关键节点       [ ] 名称 · 日期 · 金额             |
| 付款计划       [ ] 名称 · 日期 · 金额             |

| [放弃草稿]                         [保存公开选择] |
+--------------------------------------------------+
```
