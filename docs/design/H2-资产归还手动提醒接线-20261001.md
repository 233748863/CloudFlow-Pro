## 页面和发送时点

```text
+----------------------------------------------+
| 资产明细：编号、名称、当前责任                 |
| [核定资产处理] [提醒归还]                     |
| 最近提醒：时间、经办人、站内提醒已提交          |
+----------------------------------------------+
| 提醒前重新核实本单与资产归属                   |
| 已归还 / 来源变化：提示重新读取，不发送         |
| 请求结果不明：读取提醒记录，暂停重复发送        |
+----------------------------------------------+
```

发送按钮仅对普通离职结算、尚有该员工资产责任且具有人事编辑权限的操作者显示；冲正、关闭、被替代结算及错误员工归属拒绝。员工本人回避继续复用`HrHSupport.operator`，前后端分别检查权限。提醒不改变结算金额、核定内容、来源冻结或审批状态。

## 服务处理

HR核对本租户、员工范围、结算版本、资产明细归属和正常结算状态；OA内部接口仅允许HR调用。OA按既有`selectForUpdate`锁定该资产，重新核对当前版本、员工唯一账号关联、保管/领用责任及归属一致性。已归还或责任不符拒绝入队。

使用`business_type=HR_ASSET_RETURN`、`business_id=结算ID`、`resource_id=资产ID`、`applicant_id=员工账号ID`、`reminder_type=MANUAL`记录每次手动动作。姓名列不承载被截断的员工姓名；原始员工资料保持完整，当前登录名及操作者ID用于审计。日志、业务审计和站内消息持久事件必须在OA同一事务提交；任一失败整笔撤回。

请求携带页面已读取的`lastReminderId`（初次为0）。在资产锁内比较同一结算、资产和员工的最后提醒编号，期间已有新提醒时返回冲突及可重新读取的记录，不重复发送；用户读取最新记录后明确再点按钮才是新的一次人工提醒。消息去重使用新日志ID作为稳定身份，不写入技术标识到员工可见正文。保存响应丢失后先查记录，不能直接重试发送。
