>
> 原文写"现有基线 884"，884 只是 CRM 某个连续块的末尾，**不是全局最大值**。实测 `06.cloudflow-business-seed.sql` 有 570 个唯一 `menu_id`，**全局最大 1210**，且 900-1210 几乎连续占满。
>

>
> | 原段位 | 批次 | 已被占用 | 冲突后果 |
> | --- | --- | --- | --- |
> | 900-939 | A | **40 个全被占** | 见下方越权风险 |
> | 950-999 | B | 49 个 | 主键冲突或改写现有菜单 |

>
> **越权风险（本批最严重的一处）**：§1.2 的 `CROSS JOIN` 语句原本要把 `925/936/937/938/939` 授予全部 10 个角色，但这 5 个 ID 在现库里是**真实的 HR 权限**：
>
> ```
> 925 → hr:employees:view      937 → hr:lifecycle:edit
> 936 → hr:lifecycle:add       938 → hr:attendance:add     939 → hr:attendance:edit
> ```
>

>
> **修正方式**：本文档全部 `menu_id` 统一 **+400**（900→1300、939→1339），段位内相对关系不变。全批次新段位见 `01-决策汇总.md` 决策 A-4。落库前必须执行校验：
>
> ```sql

> SELECT menu_id, menu_name, perms FROM cloud_flow_db.sys_menu WHERE menu_id BETWEEN 1300 AND 1349;
> ```

### 1.2 角色授权

```sql
-- ADMIN(1)：走现有 SELECT 全量语句，自动含新菜单，无需改动

-- MANAGER(2)：除代码生成外全部
INSERT IGNORE INTO cloud_flow_db.sys_role_menu VALUES(2, 1300, 100000);
... (1301-1325, 1336-1339)

-- 全部 10 个角色都必须有的 5 个权限（否则消息铃铛与日期选择器不可用）：
--   1336 我的消息 / 1337 标记已读 / 1338 消息订阅 / 1339 保存订阅 / 1325 节假日查询
INSERT IGNORE INTO cloud_flow_db.sys_role_menu (role_id, menu_id, tenant_id)
SELECT role_id, m.menu_id, 100000
FROM sys_role r CROSS JOIN (SELECT 1336 AS menu_id UNION SELECT 1337 UNION SELECT 1338
                            UNION SELECT 1339 UNION SELECT 1325) m
WHERE r.tenant_id = 100000;
```

> ⚠️ 这条 CROSS JOIN 是本批最容易漏的一处：漏了它，普通员工登录后消息铃铛报 403。
>
> 🛑 **但更要紧的是 ID 必须用新段位**。原文这里写的是 `936/937/938/939/925`，那 5 个 ID 在现库里是真实的 HR 权限（`hr:lifecycle:add|edit`、`hr:attendance:add|edit`、`hr:employees:view`）。因为是 `INSERT IGNORE`，照原样执行**不报错**，但会把人事异动与考勤的写权限静默授予全部 10 个角色（含 EMPLOYEE）。执行后必须验证：
>
> ```sql
> -- 应只返回 system:message:mine:* / system:message:subscribe:* / system:holiday:query 五条
> SELECT DISTINCT m.menu_id, m.perms FROM cloud_flow_db.sys_role_menu rm
>   JOIN cloud_flow_db.sys_menu m ON m.menu_id = rm.menu_id
>  WHERE rm.role_id = 5 AND m.menu_id IN (1325, 1336, 1337, 1338, 1339);
> -- 且这条必须返回 0 行（EMPLOYEE 不应有任何 hr 写权限）
> SELECT m.perms FROM cloud_flow_db.sys_role_menu rm
>   JOIN cloud_flow_db.sys_menu m ON m.menu_id = rm.menu_id
>  WHERE rm.role_id = 5 AND m.perms LIKE 'hr:%:add';
> ```

```
│   ├── mapper.java.vm         → {package}/mapper/{ClassName}Mapper.java

│   ├── serviceImpl.java.vm    → {package}/service/impl/{ClassName}ServiceImpl.java

│   ├── ddl.sql.vm             → 建表 SQL 骨架

```
