# 人力资源前端设计回炉台账

## 摘要
- 回炉 = 该页按新基线重新定义设计语言、结构语法、信息密度与交互层级，旧台账中的“已完成 / 联调中 / 第一轮收口”不继承。
- 参考源码 = `.references/sub2api/frontend` 内真实存在的布局、后台页面与样式文件，是 HR 桌面端唯一设计语言来源。
- 硬性要求 = 旧台账里仍然有效、且直接服务“向源码靠拢”的约束；这些约束迁入本台账后继续生效。
- 范围 = 本台账只覆盖桌面端 HR；移动端不纳入。
- 迁移规则 = 自 2026-04-26 起，`docs/前端设计语言重构台账.md` 仅保留 HR 历史记录与约束来源，不再新增或改写 HR 页面状态。
- 记账规则 = 所有 HR 页面状态从 `待回炉` 重新开始；旧账只允许沉淀为约束、遗留问题或曾经偏差。
- 目标 = HR 所有桌面页的 UI/UX 设计语言风格向 `.references/sub2api` 靠拢，优先对齐布局骨架、筛选条语法、结果容器、主从结构、弹层节奏、明暗主题与留白密度。
- 路由口径 = `/hr/salary` 与 `/hr/salary/foundation` 只作为重定向入口，不单独记账；薪酬域以 6 个业务子路由为准。
- 当前推进 = 截至 2026-04-26，HR 壳层、入口页、标准列表 / 主从页、流程链页、自助流程页、薪酬域均已进入 `联调中`；实现层回炉已完成，下一步是逐页做参考源码对照、页面骨架核验、弹层 / 表单 / 列表语法核验与 Light / Dark 验收。

## 继承旧台账的硬性要求
- 改造前必须先读取对应 `.references/sub2api/frontend` 参考源码文件。
- 本项目现有页面只允许参考业务逻辑、接口字段、状态流转；不得反向充当视觉参考。
- 页面完成判定以“源码对照通过”为准；`npm run build` 只算辅助校验，不得替代页面验收。
- Light / Dark 必须同步验收，且统一受 `html.dark` 与 `light | dark | system` 主题契约约束。
- 页面允许继续回炉，直到设计语言风格与源码一致；用户或评审明确指出“不像源码”时，该页仍视为未达标。
- 每次回炉收口前固定检查 4 项：源码对照、页面骨架、弹层 / 表单 / 列表语法、Light / Dark；缺一项不得标记 `已验收`。

## 页面类型定义
- `入口页 = 模块目录、概览信息与最近事项合并在单结果容器中的入口页面。`
- `标准列表页 = 单筛选条 + 单结果容器 + 分页 / 空态的后台列表页面。`
- `主从详情页 = 左侧列表 / 树 / 分组与右侧详情栏联动的页面。`
- `复合工作区 = 同一路由下存在多块业务结果区，但仍需服从单工具条和主结果容器语法的页面。`
- `表单流页 = 以申请、审批、编辑、详情弹层为主要交互链路的业务页面。`
