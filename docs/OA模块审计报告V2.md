## ✅ 1. 完善加签/减签功能 (已完成)

### 实施内容

#### 1.1 接口层 ✅
- **文件**: `IWfTaskService.java`
- **新增方法**:
  - `addSignature(String taskId, List<Long> userIds, String comment)` - 加签
  - `reductionSignature(String taskId, List<Long> userIds, String comment)` - 减签

#### 1.2 服务实现层 ✅
- **文件**: `WfTaskServiceImpl.java`
- **实现功能**:
  - 加签逻辑：
    - 参数校验（任务ID、用户列表、说明）
    - 权限校验（只有任务处理人可加签）
    - 会签节点检查（仅支持会签节点）
    - 会签状态检查（仅VOTING状态可加签）
    - XSS过滤
    - 创建新会签任务
    - 更新会签总人数
    - 发送通知
    - 记录审计日志
  - 减签逻辑：
    - 参数校验
    - 权限校验（任务处理人或管理员）
    - 会签节点和状态检查
    - 防止减签自己
    - 检查是否已投票（已投票不可减签）
    - 删除待办任务
    - 更新会签总人数
    - 检查是否满足通过条件
    - 发送通知
    - 记录审计日志

#### 1.3 会签服务辅助方法 ✅
- **文件**: `ICountersignService.java` 和 `CountersignServiceImpl.java`
- **新增方法**:
  - `getCountersignTask()` - 获取会签任务信息
  - `updateCountersignTask()` - 更新会签任务
  - `hasUserVoted()` - 检查用户是否已投票
  - `checkAndCompleteCountersign()` - 检查并完成会签

#### 1.4 审计日志 ✅
- **文件**: `WorkflowAuditService.java`
- **新增审计动作**:
  - `TASK_ADD_SIGN` - 任务加签
  - `TASK_REDUCTION_SIGN` - 任务减签

### 技术特性

1. **并发安全**: 使用 Redisson 分布式锁保证加签/减签操作的原子性
2. **权限控制**: 
   - 加签：仅任务处理人
   - 减签：任务处理人或管理员
3. **业务规则**:
   - 仅支持会签节点
   - 仅VOTING状态可操作
   - 已投票用户不可减签
   - 不可减签自己
   - 减签后至少保留1人
4. **安全防护**: XSS过滤、参数校验
5. **审计追踪**: 完整的操作日志记录
6. **通知机制**: 自动通知被加签/减签用户

## 🔄 2. 实现自动审批机制 (进行中)

### 需求分析

参考 RuoYi 的 autoPass 机制：
- 避免同一人在多个节点重复审批
- 检查用户是否在后续节点中
- 自动完成任务并记录
- 发送通知

### 实施计划

1. 在流程定义中添加 `autoPass` 配置
2. 在任务完成时检查后续节点
3. 如果当前用户在后续节点中，自动通过
4. 记录自动审批历史
5. 发送通知
