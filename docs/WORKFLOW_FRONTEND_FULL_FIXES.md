## 1. workflow.ts - 工作流 API 服务层

### 当前实现

- 基础 API 调用封装
- 使用 `getList` 辅助函数处理分页结果
- 支持 16 个工作流相关接口

### 可选实现方向

| 编号 | 方向 | 说明 |
|------|------|------|
| 1.1 | 请求拦截器增强 | 统一处理 loading 状态、错误提示、token 刷新 |
| 1.2 | 响应数据标准化 | 统一处理后端返回的不同数据格式（PageResult/Array/Object） |
| 1.3 | API 请求缓存 | 对流程定义、表单定义等不常变化的数据进行缓存 |
| 1.4 | 请求去重 | 防止短时间内重复请求同一接口 |
| 1.5 | 请求重试机制 | 网络失败时自动重试 |
| 1.6 | 请求取消 | 组件卸载时取消未完成的请求 |
| 1.7 | 乐观更新 | 先更新 UI，后台异步同步数据 |
| 1.8 | WebSocket 集成 | 实时推送任务状态变更 |

### 生产缺失

| 编号 | 缺失项 | 影响 | 修复方案 |
|------|--------|------|----------|
| 1.A | 错误处理不完整 | API 错误没有统一的用户友好提示 | 实现统一的错误处理拦截器，根据错误码显示友好提示 |
| 1.B | 类型定义不完整 | 很多接口返回类型是 `any` | 为所有 API 定义完整的 TypeScript 类型 |
| 1.C | 缺少 loading 状态管理 | 用户不知道请求是否在进行中 | 使用全局 loading 状态或请求级别的 loading 标识 |
| 1.D | 缺少请求日志 | 难以调试 API 问题 | 在开发环境记录所有 API 请求和响应 |
| 1.E | 缺少超时处理 | 长时间无响应的请求会一直挂起 | 设置合理的请求超时时间（如 30 秒） |
| 1.F | 缺少离线处理 | 离线时请求会失败 | 检测网络状态，离线时提示用户或使用离线缓存 |
| 1.G | userId 参数冗余 | `getTodoTasks` 和 `getMyInstances` 的 userId 参数被后端忽略 | 移除冗余参数或在注释中说明 |
| 1.H | 缺少批量操作 API | 无法批量处理任务 | 增加批量审批、批量撤回等接口 |

## 2. WorkflowDesign.tsx - 流程设计页面

### 当前实现

- 加载流程定义列表（默认选择第一个）
- 加载表单定义列表
- 加载角色和用户列表
- 保存流程定义

### 可选实现方向

| 编号 | 方向 | 说明 |
|------|------|------|
| 2.1 | 流程列表选择器 | 提供流程列表供用户选择要编辑的流程 |
| 2.2 | 新建流程向导 | 引导用户创建新流程（选择模板、填写基本信息） |
| 2.3 | 流程版本管理 | 显示流程的所有版本，支持版本切换和比对 |
| 2.4 | 流程发布功能 | 在页面中直接发布流程 |
| 2.5 | 流程测试功能 | 模拟运行流程，验证流程逻辑 |
| 2.6 | 流程导入/导出 | 支持 JSON 格式的流程导入导出 |
| 2.7 | 流程权限配置 | 配置哪些角色可以启动该流程 |
| 2.8 | 流程分类管理 | 为流程设置分类标签 |

### 生产缺失

| 编号 | 缺失项 | 影响 | 修复方案 |
|------|--------|------|----------|
| 2.A | 缺少 loading 状态 | 数据加载时显示"Loading..."文本，体验差 | 使用骨架屏或 Spinner 组件 |
| 2.B | 错误处理缺失 | API 失败时没有友好提示 | 使用 toast 或 alert 提示错误信息 |
| 2.C | 数据为空时的处理 | 没有流程时直接创建新流程，可能不符合预期 | 显示空状态页面，引导用户创建或选择流程 |
| 2.D | 保存成功后无反馈 | 使用 alert 提示，体验不佳 | 使用 toast 提示并刷新流程列表 |
| 2.E | 缺少自动保存 | 用户可能忘记保存导致数据丢失 | 实现自动保存草稿功能 |
| 2.F | 缺少离开确认 | 未保存的更改可能丢失 | 检测未保存更改，离开前弹窗确认 |
| 2.G | ID 生成逻辑混乱 | `new_` 前缀的 ID 处理不清晰 | 统一 ID 生成策略，新流程不传 ID，由后端生成 |

## 14. 全局/跨组件缺失项

以下是影响整个工作流前端的全局性问题，需要统一修复。

### 14.1 状态管理

| 编号 | 缺失项 | 影响 | 修复方案 |
|------|--------|------|----------|
| G.1 | 缺少全局状态管理 | 各组件独立管理状态，数据不同步 | 使用 Zustand 或 Redux Toolkit 管理工作流全局状态 |
| G.2 | 缺少数据缓存策略 | 每次进入页面都重新请求数据 | 使用 React Query 或 SWR 实现数据缓存和自动刷新 |
| G.3 | 缺少实时更新 | 任务状态变更不会实时反映 | 使用 WebSocket 或轮询实现实时更新 |
| G.4 | 缺少乐观更新 | 操作后需要等待服务器响应才更新 UI | 实现乐观更新策略，先更新 UI 再同步服务器 |

### 14.2 类型安全

| 编号 | 缺失项 | 影响 | 修复方案 |
|------|--------|------|----------|
| T.1 | 大量使用 `any` 类型 | 类型安全性差，容易出 bug | 为所有数据定义完整的 TypeScript 接口 |
| T.2 | API 响应类型不明确 | 无法利用 TypeScript 的类型检查 | 定义 API 响应类型，使用泛型封装请求函数 |
| T.3 | 组件 Props 类型不完整 | 组件接口不清晰 | 为所有组件定义完整的 Props 接口 |
| T.4 | 枚举值硬编码 | 状态值、类型值散落在各处 | 统一使用 TypeScript 枚举或常量 |

### 14.3 用户体验

| 编号 | 缺失项 | 影响 | 修复方案 |
|------|--------|------|----------|
| U.1 | 缺少骨架屏 | 数据加载时页面空白 | 为所有列表和详情页添加骨架屏 |
| U.2 | 缺少操作反馈 | 很多操作没有 loading 或成功/失败提示 | 统一使用 toast 提示操作结果 |
| U.3 | 缺少错误边界 | 组件错误可能导致整个页面崩溃 | 为关键组件添加 ErrorBoundary |
| U.4 | 缺少无障碍支持 | 不支持键盘导航和屏幕阅读器 | 添加 ARIA 属性和键盘导航支持 |
| U.5 | 缺少国际化 | 所有文本硬编码为中文 | 使用 i18next 实现国际化 |
| U.6 | 缺少主题切换 | 不支持暗色模式 | 实现暗色模式支持 |

### 14.4 性能优化

| 编号 | 缺失项 | 影响 | 修复方案 |
|------|--------|------|----------|
| P.1 | 缺少代码分割 | 首屏加载慢 | 使用 React.lazy 和 Suspense 实现路由级代码分割 |
| P.2 | 缺少组件懒加载 | 不需要的组件也会加载 | 对大型组件（如 WorkflowBuilder）使用懒加载 |
| P.3 | 缺少虚拟滚动 | 长列表性能差 | 使用 react-virtualized 或 react-window 实现虚拟滚动 |

| P.5 | 缺少图片优化 | 图片加载慢 | 使用懒加载和 WebP 格式优化图片 |
