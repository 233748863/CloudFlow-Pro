## 1. 背景与目标

### 1.1 问题：导出强、导入弱

后端已有 FastExcel 1.0.0 + Apache POI 5.2.5，CSV 导出已实现（如 `/oa/audit/events` 导出）。但**导入能力弱** —— 按 Controller 清单看批量导入入口很少。

而本系列文档规划的新表大量需要导入：
| 场景 | 来源 PRD |
| --- | --- |
| 员工批量导入 | HR 基础 |
| 假期政策批量分配 | D1 |
| 节假日日历批量导入 | 批次 A HR-04（该 PRD 已含 Excel 导入需求） |
| 客户/线索批量导入 | E4 |
| 资产批量导入 | F1 |
| 供应商批量导入 | F2 |
| 薪资变动批量导入 | D3 |
| 目标名单导入 | E5 |

**每个 PRD 各自实现导入 = 8 套重复代码**。本 PRD 建统一框架，各业务只需实现"一行数据如何校验与落库"。

### 1.2 目标
1. 统一导入框架：模板下载 → 上传 → 校验 → 预览 → 确认导入 → 结果反馈
2. **错误行标注回传**（用户改完重传，而非从头再来）
3. 大文件异步处理
4. 导入任务记录与审计
5. 各业务接入成本降到最低（实现一个校验器 + 一个落库器）

### 1.3 非目标
- 不做导入数据的自动纠错（如自动补全部门名）
- 不做增量更新导入（只做新增；更新类导入需明确主键匹配规则，见 §9-2）
- 不做 CSV 之外的其他格式（不做 JSON/XML 导入）

## 3. 范围

### 3.1 做
1. 新增 `sys_import_task`（导入任务）
2. 新增 `sys_import_error`（错误明细，或存文件，见 §9-3）
3. 统一导入框架（模板生成、逐行读取、校验、落库、错误收集）
4. 错误标注文件生成
5. 异步处理（大文件）
6. 前端统一导入组件
7. 首批 5 个业务场景接入

### 3.2 不做
| 项 | 原因 |
| --- | --- |
| 自动纠错 | 数据质量应由用户保证；自动纠错可能引入错误数据 |
| 更新类导入 | 见 §9-2（需明确主键匹配与冲突策略，本期只做新增） |
| 其他格式导入 | 只支持 xlsx / xls / csv |
| 导入数据回滚 | 见 §9-4（部分成功后回滚成本高） |

## 4. 功能需求

### FR-1 导入任务
- FR-1.1 新增 `sys_import_task`：
  | 字段 | 说明 |
  | --- | --- |
  | task_id | PK |
  | tenant_id | 租户 |
  | task_no | 任务编号 |
  | biz_type | 业务类型（EMPLOYEE / CUSTOMER / LEAD / ASSET / SUPPLIER / HOLIDAY / LEAVE_POLICY / SALARY_CHANGE / TARGET_LIST 等） |
  | biz_name | 业务名称（中文） |
  | file_name | 原文件名 |
  | file_url | 原文件（`sys_file`） |
  | file_size | 文件大小 |
  | total_rows | 总行数 |
  | valid_rows | 校验通过行数 |
  | invalid_rows | 校验失败行数 |
  | success_rows | 导入成功行数 |
  | fail_rows | 导入失败行数 |
  | status | UPLOADED 已上传 / VALIDATING 校验中 / VALIDATED 校验完成 / IMPORTING 导入中 / SUCCESS 全部成功 / PARTIAL 部分成功 / FAILED 全部失败 / CANCELLED 已取消 |
  | error_file_url | 错误标注文件 |
  | operator_id / operator_name | 操作人 |
  | start_time / end_time | 起止时间 |
  | duration_ms | 耗时 |
  | error_message | 整体错误信息 |
  | job_log_id | 关联 SYS-02 任务日志（异步时） |
  | + 审计列 | |
- FR-1.2 新增 `sys_import_error`：`error_id, task_id, row_no, column_name, cell_value, error_type(REQUIRED/FORMAT/RANGE/DUPLICATE/REFERENCE/BUSINESS), error_message, create_time`

### FR-2 导入流程（五步）
- FR-2.1 **① 下载模板**：`GET /system/import/{bizType}/template`
  - 模板含表头（中文列名）、必填标记、示例行、下拉选项（字典类字段用 Excel 数据验证）、说明 sheet
- FR-2.2 **② 上传文件**：`POST /system/import/{bizType}/upload`
  - 校验：格式（xlsx/xls/csv）、大小（默认 ≤ 10MB）、行数（默认 ≤ 10000）
  - 返回 `taskId`
- FR-2.3 **③ 校验**：`POST /system/import/{taskId}/validate`
  - 逐行校验（不落库），收集全部错误到 `sys_import_error`
  - 行数 ≤ 500 时同步返回；> 500 时异步（走 SYS-02）
- FR-2.4 **④ 预览与确认**：`GET /system/import/{taskId}/preview`
  - 返回前 N 行数据 + 错误统计 + 错误明细（分页）
  - 用户可选择：修正后重传 / 忽略错误行仅导入正确行 / 取消
- FR-2.5 **⑤ 执行导入**：`POST /system/import/{taskId}/execute`
  - 入参 `skipInvalidRows`（是否跳过错误行）
  - 逐行落库，记录成功与失败
  - 完成后生成错误标注文件（若有失败）

### FR-3 校验能力
- FR-3.1 框架内置通用校验：
  | 类型 | 说明 |
  | --- | --- |
  | REQUIRED | 必填 |
  | FORMAT | 格式（日期、数字、邮箱、手机、身份证） |
  | RANGE | 数值范围、字符长度 |
  | DUPLICATE | 文件内重复（如同一工号出现两次）+ 库内重复 |
  | REFERENCE | 引用存在性（部门名、字典值、供应商编号等是否存在） |
  | BUSINESS | 业务规则（由各业务实现器提供） |
- FR-3.2 各业务实现 `ImportValidator<T>` 接口提供 BUSINESS 校验
- FR-3.3 引用类字段支持**按名称匹配 ID**（用户填"研发部"，框架查 `sys_dept` 转 `dept_id`），匹配失败记 REFERENCE 错误

### FR-4 错误标注文件
- FR-4.1 生成方式：复制原文件，在**每行末尾追加"错误说明"列**，标红错误单元格
- FR-4.2 用户改完可直接重传该文件（错误说明列被忽略）
- FR-4.3 错误文件存 `sys_file`，可下载（权限与原文件一致）

### FR-5 业务接入接口
- FR-5.1 各业务实现两个接口：
  ```java
  // 1. 定义列与校验规则
  interface ImportDefinition<T> {
      String bizType();
      String bizName();
      List<ImportColumn> columns();      // 列名、字段名、类型、必填、校验规则、字典类型
      int maxRows();
  }
  // 2. 校验与落库
  interface ImportHandler<T> {
      List<ImportError> validateRow(T row, int rowNo, ImportContext ctx);  // BUSINESS 校验
      void importRow(T row, int rowNo, ImportContext ctx);                 // 落库
  }
  ```
- FR-5.2 框架负责：模板生成、文件读取、通用校验、错误收集、异步调度、结果统计、错误文件生成
- FR-5.3 `ImportContext` 提供：租户上下文、操作人、已缓存的引用数据（部门树、字典等，避免逐行查库）

### FR-6 异步处理
- FR-6.1 行数 > 500 或文件 > 2MB 时走异步（批次 A SYS-02 任务平台）
- FR-6.2 前端轮询任务状态展示进度（已处理行数 / 总行数）
- FR-6.3 完成后发通知（批次 A SYS-01）
- FR-6.4 异步任务失败可重试

### FR-7 前端统一组件
- FR-7.1 `<ImportDialog bizType="EMPLOYEE" />` 统一导入弹窗：
  下载模板 → 拖拽上传 → 校验进度 → 错误预览（表格形态，可下载错误文件）→ 确认导入 → 结果展示
- FR-7.2 各业务列表页只需加一个"导入"按钮传 `bizType`
- FR-7.3 移动端不支持导入（引导到桌面端，配合 G1 INT-03）

## 5. 非功能需求

| 项 | 要求 |
| --- | --- |
| **文件安全** | 类型按**内容**判断（非扩展名）；大小限制；行数限制；文件名不信任（重命名存储） |
| 内存 | 用 FastExcel 的**逐行监听读取**（不全量载入内存），支持 1 万行不 OOM |
| 性能 | 1 万行校验 < 30s；导入 < 2 分钟（异步） |
| 事务 | **单行一事务**（不做整体大事务），部分成功可接受（见 §9-4） |
| 幂等 | 同一 `taskId` 重复执行不重复导入（状态机保证） |
| 权限 | 导入需对应业务的 `:import` 权限（如 `hr:employee:import`） |
| 审计 | 每次导入记 `sys_audit_log`（操作人、业务类型、文件名、成功失败行数） |
| 数据量 | `sys_import_error` 需清理策略（随任务保留期，默认 30 天） |
| 敏感数据 | 员工/薪资类导入文件含个人信息，存储需权限控制；建议导入完成后可选删除原文件 |

## 6. 验收标准

| # | 验收项 |
| --- | --- |
| AC-1 | 五个业务的模板可下载，含中文表头、必填标记、示例行、字典下拉 |
| AC-2 | 上传非法格式（改扩展名的 exe）被按内容识别并拒绝 |
| AC-3 | 超大文件与超行数被拒绝 |
| AC-4 | 六类通用校验均生效（必填/格式/范围/重复/引用/业务） |
| AC-5 | 引用类字段按名称匹配 ID 成功（填"研发部"转为 dept_id） |
| AC-6 | 文件内重复与库内重复均被检出 |
| AC-7 | 校验结果预览展示错误统计与明细，定位到行与列 |
| AC-8 | **错误标注文件可下载，错误单元格标红并有说明列；修正后可直接重传** |
| AC-9 | `skipInvalidRows=true` 时只导入正确行，状态为 PARTIAL |
| AC-10 | `skipInvalidRows=false` 时有错误则不导入任何行 |
| AC-11 | 1 万行文件走异步，前端可看进度，完成后收到通知 |
| AC-12 | **1 万行导入不 OOM**（逐行读取验证） |
| AC-13 | 同一 taskId 重复执行不重复导入 |
| AC-14 | 导入记审计（操作人、业务、文件、结果） |
| AC-15 | 无 `:import` 权限时被拒绝 |
| AC-16 | 五个业务场景端到端导入成功 |
| AC-17 | 新增第六个业务接入只需实现两个接口，不改框架代码 |
| AC-18 | 移动端访问导入功能有引导提示 |

## 7. 依赖与风险

### 7.1 依赖
| 依赖 | 说明 |
| --- | --- |
| FastExcel 1.0.0（已有） | 逐行读取与模板生成 |
| **批次 A SYS-02 任务平台** | 异步导入；强依赖 |
| **批次 A SYS-01 消息中心** | 完成通知 |
| **批次 A SYS-07 代码生成器** | 两张表 CRUD |
| `sys_file`（已有） | 文件存储 |
| 批次 G SYS-04 | 签名 URL（弱依赖） |
| 批次 G INT-03 | 移动端引导（弱依赖） |
| 各业务 PRD | 接入方（HR-04 节假日、F1 资产、F2 供应商等） |

### 7.2 风险

| 风险 | 应对 |
| --- | --- |
| 大文件 OOM | FastExcel 逐行监听读取（NFR + AC-12）；行数与大小限制 |
| 部分成功后数据不一致 | 单行一事务；`skipInvalidRows=false` 时全不导入（AC-10）给用户选择；§9-4 说明不做回滚的理由 |
| 引用按名称匹配可能匹配到多个（重名部门） | 匹配到多个时记 REFERENCE 错误要求用户用编号；模板说明中提示 |
| 各业务接入时绕过框架自己实现 | 框架接入成本必须足够低（AC-17）；Code Review 检查 |
| 导入文件含个人信息长期留存 | NFR 权限控制 + 可选导入后删除原文件 |
| 错误标注文件生成对 xls（老格式）兼容性 | 建议只对 xlsx 生成标注文件；xls 与 csv 输出纯文本错误清单 |

## 9. 待确认

| # | 问题 | 建议默认 |
| --- | --- | --- |
| 1 | 首批接入哪五个业务 | 建议按 §FR-8（员工/节假日/客户/资产/供应商）。节假日是批次 A HR-04 已明确要求的，优先级最高 |
| 2 | 是否支持更新类导入（按主键更新已有数据） | 建议本期**只做新增**。更新导入需明确：主键用什么匹配（工号？编号？）、字段为空是否清空原值、冲突如何处理。这些规则各业务不同，建议后续按需单独设计 |
| 3 | 错误明细存表还是存文件 | 建议**存表**（`sys_import_error`），便于分页查询与统计；同时生成错误标注文件供下载。表数据随任务保留期清理 |
| 4 | 部分成功后是否支持回滚 | 建议**不做回滚**。理由：① 单行一事务已保证每行原子；② 回滚需记录所有生成 ID 并反向删除，可能触发级联影响；③ 提供 `skipInvalidRows=false` 让用户选择"有错就全不导" |
| 5 | 导入文件是否自动删除 | 建议提供配置：默认保留 30 天（便于追溯），敏感业务（薪资）可配置为导入后立即删除 |
