## 编写原则

- **按可交付单元分组**：必须同批交付的条目合成一份（拆开做会返工），如 HR-01+02+03、LC-01+LC-02、OA-04+OA-05
- **每份结构一致**：背景与目标 → 现状基线（实测）→ 范围（做/不做）→ 角色权限 → 功能需求 → 数据模型（字段级）→ 接口设计（含权限码）→ 非功能需求 → 验收标准 → 依赖与风险 → 里程碑 → 待确认
- **现状基线全部实测**：不采信对标文档的二手判断，编码前重新读 service/strategy/handler 层
- **P2 增强项按模块合并**：批次 H 五份合集，条目彼此独立可单独取用

## 贯穿全系列的安全要求

各 PRD 已在 NFR 与验收标准中落实，此处汇总供 Code Review 对照：

| 类别 | 要求 | 涉及 PRD |
| --- | --- | --- |
| 凭据加密 | 消息渠道 secret、IM app_secret、存储 AK/SK、数据源密码、OAuth2 client_secret 一律加密存储 + 接口脱敏 + 日志不打印 | A2 / G3 / G4 / H5 |
| 哈希存储 | OAuth2 token 与 code、短信验证码存哈希 | A2 / H5 |
| 服务端权威 | 表单校验、字段过滤、请假天数、签署 IP、`duration` 全部服务端计算，不信任客户端 | C1 / C3 / D1 / F4 |
| 表达式安全 | **禁用 eval / 脚本引擎 / 可执行代码字段**；白名单变量 + 受限解析器 | C3 / H2 |
| SSRF | 触发节点 URL 白名单 + 私有地址禁止；HTML→PDF 禁外部资源 | B2 / G5 |
| RCE | 模板渲染禁用 Freemarker `?api` 与类加载 | G5 |
| XSS | 富文本必过 dompurify；SVG/HTML 不直接渲染 | C1 / H5 |
| 开放重定向 | 营销点击追踪跳转白名单；OAuth2 redirect_uri 严格匹配 | E5 / H5 |
| 越权 | 私有文件签名 URL、IM 审批处理人校验、门户数据隔离、工资条本人可见 | G3 / G4 / H3 / D3 |
| 回调验签 | IM 回调强制验签 | G4 |
| SQL 注入 | 自助报表白名单校验 + `#{}` 绑定，**无自由 SQL** | H5 |
| 数据保密 | 询价报价截止前互不可见；成本单价限管理者 | F5 / F3 |
| 高影响操作 | 租户套餐批量同步、考勤重算、批次取消需二次确认 + 审计 | H5 / D2 / D3 |
| 外网暴露面 | 营销追踪、IM 回调、客户门户、OAuth2 端点均需限流 + 审计 | E5 / G4 / H3 / H5 |
