# PRD：表单字段级权限与节点联动（LC-04）

| 项 | 内容 |
| --- | --- |
| 条目编号 | LC-04 |
| 所属批次 | 批次 C（第 3 份） |
| 对标依据 | `docs/benchmark/06-lowcode-bi-表单报表对标.md` |
| 优先级 | P1 —— **含一个实际的数据暴露修复** |
| 预估工作量 | M |
| 版本 | v1 · 2026-08-31 |

## 1. 背景与目标

### 1.1 这是一个安全修复，不只是功能增强

`FormField.readonly` 是**静态全局标记**，同一张表单在所有审批节点看到的字段完全一样。后果：

**薪资调整审批单里的薪资数字，对整条审批链上每个审批人可见。** 采购单的成本价、HR 的员工敏感信息同理。

这不符合数据最小化原则。表单字段权限不是"体验优化"，是**访问控制的一部分**。

### 1.2 目标
1. 字段权限按流程节点配置（可见 / 可编辑 / 必填三态）
2. **服务端过滤不可见字段**（不能只靠前端隐藏，否则接口仍返回敏感值）
3. 支持表达式驱动的显隐（`visibleExpr` / `disabledExpr`）
4. 表达式求值安全（白名单变量 + 受限解析器，**不用 eval**）

### 1.3 非目标
- 不做按角色的字段权限（按节点已覆盖主要场景，按角色会与节点权限产生优先级冲突）
- 不做字段级数据脱敏（如只显示后四位）——本期只做可见/不可见
- 不做字段级操作日志

## 2. 现状基线（实测）

| 项 | 现状 |
| --- | --- |
| 字段权限 | 只有 `FormField.readonly` 静态布尔 |
| 联动 | `utils/formFieldRuntime.ts` 实测只有 `fillMappings`（填充联动），无显隐联动 |
| 表单定义 | `wf_form_definition.fields_json`；C1 后为树形结构 |
| 节点配置 | `WfNodeConfig`（B1 后已扩展多项） |
| 流程定义 | `wf_process_definition.model_json` 含节点数组 |
| 服务端校验器 | C1 已建（本 PRD 在其基础上加字段过滤） |

**当前数据流**：审批人打开待办 → 调 `/wf/instance/{id}` 或表单数据接口 → **返回全部字段值** → 前端按 `readonly` 决定是否可编辑，但值已下发。

## 3. 范围

### 3.1 做
1. 新增 `wf_form_field_permission` 表（按节点覆盖字段权限）
2. **服务端字段过滤**：下发表单数据前剔除当前节点不可见字段
3. 服务端提交校验：拒绝对不可编辑字段的修改
4. `visibleExpr` / `disabledExpr` 表达式支持（受限解析器）
5. 设计器：节点 × 字段权限配置矩阵
6. 渲染器按权限渲染

### 3.2 不做
| 项 | 原因 |
| --- | --- |
| 按角色的字段权限 | 按节点已覆盖主要场景；两套权限并存需定优先级，复杂度不划算 |
| 字段值脱敏显示 | 本期只做可见/不可见；脱敏需按字段类型定规则，可后续评估 |
| `eval` 或脚本引擎 | 安全红线，见 FR-3 |

## 4. 功能需求

### FR-1 节点级字段权限
- FR-1.1 新增表 `wf_form_field_permission`：
  | 字段 | 说明 |
  | --- | --- |
  | id | PK |
  | tenant_id | 租户 |
  | definition_id | 流程定义 ID |
  | node_key | 节点标识（`__START__` 表示发起环节） |
  | field_id | 字段 ID（子表列用 `subTableId.columnId` 表示） |
  | visible_flag | 是否可见（默认 1） |
  | editable_flag | 是否可编辑（默认按节点类型：发起节点 1，审批节点 0） |
  | required_flag | 是否必填（默认继承字段自身 `required`） |
  | + 审计列 | |

  唯一索引 `uk_def_node_field(tenant_id, definition_id, node_key, field_id)`
- FR-1.2 **未配置即继承默认**：某节点某字段无记录时，按字段自身定义（`required` / `readonly`）处理。这保证改造后现有流程行为不变
- FR-1.3 权限随流程定义版本走：定义发布新版本时权限记录一并复制（复用现有版本机制）
- FR-1.4 子表列权限支持到列级（`field_id` 用 `subTableId.columnId`）

### FR-2 服务端过滤与校验（**本 PRD 核心**）
- FR-2.1 **下发过滤**：表单数据下发接口（`/wf/instance/{id}`、待办详情、`/wf/form/{formId}` 等）返回前，按当前用户所在节点剔除 `visible_flag=0` 的字段值
  - 剔除是**删除键**而非置 null（置 null 仍暴露"该字段存在"）
  - 同时剔除表单定义中该字段的定义（否则前端仍能看到字段标签）
- FR-2.2 **提交校验**：提交表单数据时，对 `editable_flag=0` 的字段：
  - 若提交值与原值不同 → 拒绝并记录（可能是绕过前端的篡改尝试）
  - 若提交中不含该字段 → 保留原值
- FR-2.3 `required_flag` 参与 C1 校验器的必填判断（节点级必填覆盖字段级）
- FR-2.4 过滤逻辑必须覆盖**所有**返回表单数据的接口，需梳理清单（见 AC-3）
- FR-2.5 流程轨迹与历史记录中的表单快照（`wf_process_snapshot`）同样需按权限过滤

### FR-3 表达式驱动显隐（**安全约束严格**）
- FR-3.1 `FormField` 增 `visibleExpr` / `disabledExpr`（可选）
- FR-3.2 表达式语法限定为**极简子集**：
  ```
  字段引用：  ${fieldId}
  比较：      == != > >= < <=
  逻辑：      && || !
  字面量：    数字、字符串（单引号）、true/false/null
  括号：      ( )
  示例：      ${amount} > 10000 && ${type} == 'SPECIAL'
  ```
- FR-3.3 **实现约束（安全红线）**：
  - **禁止 `eval`、`new Function`、脚本引擎（Nashorn/GraalJS）、SpEL、OGNL**
  - 自写递归下降解析器或用受限表达式库（如 Java 侧可用 `aviator` 并禁用函数调用）
  - 变量只能引用**当前表单已声明的字段 ID**（白名单）
  - 无函数调用、无属性访问、无方法调用
  - 解析失败或引用未声明字段 → 表达式判为 `false`（保守：不可见/禁用）并记日志
- FR-3.4 表达式求值在**前后端各执行一次**：前端用于即时显隐，后端用于校验与过滤（**后端为权威**）
- FR-3.5 表达式深度与长度限制（嵌套 ≤ 5 层，长度 ≤ 500 字符），防解析器被恶意输入拖死
- FR-3.6 节点权限与表达式的优先级：**节点权限优先**（`visible_flag=0` 时表达式不再求值，直接不可见）

### FR-4 设计器
- FR-4.1 新增"字段权限"配置视图：矩阵形态，行为字段（含子表列，可折叠），列为流程节点
- FR-4.2 每个单元格三个勾选：可见 / 可编辑 / 必填
- FR-4.3 批量操作：整行（某字段对所有节点）、整列（某节点对所有字段）、全选/反选
- FR-4.4 快捷模板：「仅发起人可编辑」「财务节点可见成本价」等常用组合一键套用
- FR-4.5 表达式编辑器：带字段 ID 自动补全、语法校验、实时预览（给定测试值看结果）
- FR-4.6 保存校验：表达式语法合法、引用字段存在

### FR-5 渲染
- FR-5.1 渲染器按服务端下发的权限渲染（不可见字段服务端已剔除，前端无需处理）
- FR-5.2 `editable_flag=0` 时渲染为只读态（复用现有 `readonly` 渲染）
- FR-5.3 表达式驱动的显隐在前端实时响应字段值变化
- FR-5.4 移动端同步

## 5. 非功能需求

| 项 | 要求 |
| --- | --- |
| **服务端过滤是权威** | FR-2 必须实现且覆盖所有表单数据接口。只做前端隐藏等于没做 |
| **表达式不用 eval** | FR-3.3 是安全红线。与 HR-13 绩效公式同一约束（见 `04-hr` 文档） |
| 过滤性能 | 权限记录按 `definition_id` 缓存（Redis），避免每次下发查库 |
| 缓存一致性 | 权限变更后失效对应定义的缓存 |
| 行为兼容 | 未配置权限时行为与改造前一致（FR-1.2） |
| 审计 | 对不可编辑字段的篡改尝试记 `sys_audit_log`（可能是攻击行为） |
| 表达式健壮性 | 解析失败保守判 false；深度与长度限制（FR-3.5） |

## 6. 验收标准

| # | 验收项 |
| --- | --- |
| AC-1 | 配置"薪资字段仅 HR 节点可见"后，其他节点审批人调接口**返回体中无该字段键**（非 null，是键不存在） |
| AC-2 | 不可见字段的**定义**也被剔除，前端看不到字段标签 |
| AC-3 | **梳理并验证全部返回表单数据的接口都已过滤**（含待办详情、实例详情、流程轨迹、表单定义查询、历史快照） |
| AC-4 | 对 `editable_flag=0` 字段提交不同值被拒绝，且记 `sys_audit_log` |
| AC-5 | 提交中不含不可编辑字段时，原值保留不丢失 |
| AC-6 | 节点级 `required_flag` 覆盖字段级 `required`，校验按节点生效 |
| AC-7 | 子表列权限生效（某列仅某节点可见） |
| AC-8 | 表达式 `${amount} > 10000 && ${type} == 'SPECIAL'` 前后端求值结果一致 |
| AC-9 | **表达式注入测试：传入含函数调用、属性访问、脚本片段的表达式被拒绝** |
| AC-10 | 表达式引用未声明字段时判为 false 并记日志，不报错崩溃 |
| AC-11 | 表达式嵌套超 5 层或长度超 500 字符被拒绝 |
| AC-12 | 节点权限与表达式冲突时节点权限优先 |
| AC-13 | 未配置权限的流程定义行为与改造前完全一致 |
| AC-14 | 权限变更后缓存失效，下次下发生效 |
| AC-15 | 设计器矩阵可配置并批量操作；表达式编辑器有语法校验与预览 |
| AC-16 | 流程定义发布新版本时权限记录一并复制 |

## 7. 依赖与风险

### 7.1 依赖
| 依赖 | 说明 |
| --- | --- |
| **C1（字段类型与布局）** | 树形结构、服务端校验器 |
| **C2（明细子表）** | 子表列权限（弱依赖，可后补） |
| **B1（WF 审批语义地基）** | 节点配置扩展机制 |
| 现有版本机制 | `wf_process_definition` 的版本与快照 |
| Redis（已有） | 权限缓存 |

### 7.2 风险

| 风险 | 应对 |
| --- | --- |
| **过滤遗漏某个接口 = 安全修复不完整** | AC-3 要求梳理并逐个验证接口清单。建议做成统一的返回拦截器/序列化过滤器而非每个接口单独处理，减少遗漏面 |
| 表达式解析器自研有 bug 或性能问题 | 语法极简（FR-3.2）降低实现难度；深度与长度限制防拖死；充分单测 |
| 前后端表达式求值结果不一致导致体验错乱 | AC-8 专项验证；两侧用同一套语法规则，建议后端为权威、前端仅优化体验 |
| 权限矩阵配置项爆炸（20 字段 × 10 节点 = 200 格） | FR-4.3 批量操作 + FR-4.4 快捷模板；未配置即继承默认（FR-1.2）意味着只需配少数例外 |
| 缓存不一致导致权限变更不生效 | AC-14；变更时精确失效 |
| 历史快照过滤被忽略（FR-2.5） | AC-3 覆盖；快照是容易漏的一处 |

## 9. 待确认

| # | 问题 | 建议默认 |
| --- | --- | --- |
| 1 | 表达式解析用自研还是引入库 | 建议引入 `aviator`（Apache-2.0）并**禁用函数调用**，比自研可靠；若禁用配置不可靠则自研递归下降解析器（语法极简，工作量可控） |
| 2 | 字段脱敏（只显示后四位）是否需要 | 本期不做（§3.2）。若薪资类字段有"可见但需脱敏"需求，可后续加 `mask_type` 字段 |
| 3 | 默认 `editable_flag` 规则 | 建议：发起节点默认可编辑，审批节点默认不可编辑（符合多数场景，减少配置量） |
| 4 | 过滤是否影响流程引擎内部逻辑（如条件分支依赖被过滤字段） | **重要**：条件分支求值必须用**未过滤的完整数据**，过滤只作用于对外下发。需在实现时严格区分"引擎内部数据"与"对外响应数据" |
