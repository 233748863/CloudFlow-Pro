# 登录、角色与权限全链路审计报告

审计日期：2026-07-11
审计范围：gateway、auth、workflow、OA、CRM、HR、前端权限引用、数据库菜单权限、租户与内部调用链路。

## 审计结论

- 已扫描 1122 个后端 HTTP 端点、506 个后端权限标识、547 个数据库权限标识和 154 个前端权限引用。
- 非公开端点未声明登录、权限或内部调用保护策略：0。
- 后端权限未进入数据库菜单：0；前端权限未进入数据库菜单：0。
- 本轮发现的高风险与中风险问题均已整改，未保留高风险或中风险项。

## 已整改问题

| 等级 | 问题 | 整改结果 |
| --- | --- | --- |
| 高 | HR 绩效服务固定使用租户 `100000`，其他租户可能错误读取或写入默认租户数据 | 全部改为从可信请求上下文读取租户；上下文缺失时拒绝执行；部门可见范围改为参数化查询 |
| 高 | 用户上下文可在无有效登录会话时接受客户端 `X-Tenant-Id` | 外部请求不再读取该头；仅声明为 `/inner/**` 且带内部调用标识的请求可恢复内部租户上下文 |
| 中 | 管理员重置密码后旧 Token 仍可继续访问 | 密码更新成功后立即注销该用户全部旧会话 |
| 中 | 用户被拉黑或黑名单重新启用后旧 Token 仍可继续访问 | 黑名单生效时立即注销该用户全部会话，并使用当前可信租户上下文写入规则 |
| 中 | 10 个后端权限缺少数据库菜单记录 | 权限记录已写入目标数据库，并为管理员角色完成授权 |
| 中 | HR 前端 6 个按钮权限与后端、数据库命名不一致 | 统一为后端实际执行的权限标识 |
| 中 | 内部流程启动、失效接口缺少防重复提交 | 两个内部写接口均加入重复提交保护 |
| 中 | 已登录用户可读的工作流业务类型接口未显式声明登录策略 | 增加 `@SaCheckLogin`，由自动审计持续校验 |

## 已验证的现有防线

- 网关从服务端会话恢复租户，覆盖客户端租户头，并剥离 `X-Inner-Call`、`X-From-Service` 和旧版用户身份头。
- `/inner/**` 经过网关时固定返回 403；服务内接口继续校验来源服务白名单。
- Cookie 写请求执行 CSRF 校验；Header Token 请求不依赖 Cookie CSRF。
- 无登录态返回 HTTP 401，缺少角色或权限返回 HTTP 403。
- Sa-Token 禁止并发共享会话，角色变更、用户停用、用户删除和本轮补充的密码重置、拉黑均会注销旧会话。
- Workflow WebSocket 使用 Cookie 或首帧 AUTH 恢复服务端用户身份，拒绝客户端 `userId` 参数。

## 自动检查与执行方式

在 `cloudflow-frontend` 目录执行 `npm run audit:security`。检查失败时返回非 0 状态码，并输出未保护端点、后端缺失权限及前端缺失权限。

## 保留的低风险事项

- 自动检查基于源码静态提取；运行期动态拼接的权限标识需要继续通过代码评审约束。
- 内部调用身份依赖网关拦截与服务网络隔离；生产环境应保持业务服务端口不直接暴露公网。
