## 数据同步机制架构

### 1. 启动时全量同步

**实现类**: `DeptPostSyncInitializer`

**流程**:
```
应用启动 → 实现ApplicationRunner接口 → run()方法执行
  ↓
同步部门数据 → 调用Auth服务getDeptTree()
  ↓
缓存部门树 → Redis: hr:dept:tree
  ↓
递归缓存每个部门 → Redis: hr:dept:{deptId}
  ↓
同步岗位数据 → 调用Auth服务getPostList()
  ↓
缓存岗位列表 → Redis: hr:post:list
  ↓
缓存每个岗位 → Redis: hr:post:{postId}
```

**特点**:
- 应用启动时自动执行
- 全量同步所有部门和岗位数据
- 异常不影响服务启动
- 缓存有效期24小时

### 2. 定时任务增量同步

**实现类**: `DeptPostSyncJob`

**流程**:
```
每5分钟执行一次 → @Scheduled(fixedRate = 300000)
  ↓
获取分布式锁 → Redisson: lock:scheduled:syncDeptPostData
  ↓
同步部门数据 → 调用Auth服务getDeptTree()
  ↓
同步岗位数据 → 调用Auth服务getPostList()
  ↓
释放分布式锁
```

**特点**:
- 定时执行，保持数据同步
- 使用分布式锁防止多实例重复执行
- 独立异常处理，不影响后续执行
- 基于Redis缓存实现数据共享

### 3. 缓存更新逻辑

**实现类**: `DeptPostSyncServiceImpl`

**流程**:
```
验证部门/岗位ID → validateDeptId()/validatePostId()
  ↓
检查Redis缓存 → getCacheObject()
  ↓
缓存命中 → 返回缓存数据
  ↓
缓存未命中 → 调用Auth服务获取数据
  ↓
数据有效 → 缓存到Redis → 返回true
  ↓
数据无效(null) → 返回false
```

**特点**:
- 优先使用缓存，减少Auth服务调用
- 缓存未命中时自动同步
- 自动检测数据有效性
- 支持多租户数据隔离

### 4. 失效检测逻辑

**实现类**: `DeptPostSyncServiceImpl`

**流程**:
```
验证部门/岗位ID → validateDeptId()/validatePostId()
  ↓
调用Auth服务 → getDeptById()/getPostById()
  ↓
返回null → 数据已删除 → 返回false（无效）
  ↓
返回数据 → 数据有效 → 缓存并返回true
```

**特点**:
- 自动检测Auth服务中已删除的数据
- 不缓存无效数据
- 支持职位管理中的删除前验证

## Redis缓存Key设计

| 缓存类型 | Key格式 | 数据类型 | 有效期 | 说明 |
|---------|---------|---------|--------|------|
| 部门树 | hr:dept:tree | List<DeptTreeVO> | 24小时 | 完整的部门层级结构 |
| 单个部门 | hr:dept:{deptId} | DeptVO | 24小时 | 部门基础信息 |
| 岗位列表 | hr:post:list | List<PostVO> | 24小时 | 所有岗位列表 |
| 单个岗位 | hr:post:{postId} | PostVO | 24小时 | 岗位基础信息 |

**多租户支持**:
- Redis Key自动添加租户前缀：`{tenantId}:hr:dept:{deptId}`
- 通过RedisCache工具类自动处理租户隔离
- 确保不同租户的数据互不干扰

## 数据同步策略说明

系统采用**基于Redis缓存的数据同步策略**，而不是消息队列（MQ）方式：

### 为什么使用Redis而不是MQ？

1. **简化架构**: 避免引入额外的消息中间件（RabbitMQ/Kafka）
2. **降低复杂度**: 减少消息队列的配置、监控和维护成本
3. **统一技术栈**: Redis已经是系统的核心组件，复用现有基础设施
4. **性能优势**: Redis缓存读取速度快，适合高频访问的基础数据
5. **多租户友好**: RedisCache天然支持租户隔离

### Redis同步机制

1. **启动时全量同步**: 应用启动时从Auth服务拉取全量数据并缓存
2. **定时增量同步**: 每5分钟定时刷新缓存，保持数据最新
3. **按需同步**: 缓存未命中时实时从Auth服务获取并缓存
4. **失效检测**: 自动检测Auth服务中已删除的数据

### 数据一致性保证

- **最终一致性**: 通过定时任务保证数据最终一致
- **缓存过期**: 24小时自动过期，强制重新同步
- **分布式锁**: 防止多实例重复同步
- **异常容错**: 同步失败不影响服务可用性
