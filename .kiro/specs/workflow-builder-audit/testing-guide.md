# P1 功能测试指南

## 测试概述

本文档提供了 P1 级功能（流程设置）的完整测试指南，包括手动测试步骤和预期结果。

## 测试环境准备

### 前置条件

1. ✅ 后端服务已启动
   - cloudflow-auth
   - cloudflow-gateway
   - cloudflow-service-workflow

2. ✅ 前端开发服务器已启动
   ```bash
   cd cloudflow-frontend
   npm run dev
   ```

3. ✅ 数据库已初始化

4. ✅ 用户已登录
   - 具有管理员权限（可以创建和编辑流程）

## 测试场景 1: 创建新流程并配置属性

### 目标
验证用户可以创建新流程并配置所有流程属性。

### 测试步骤

1. **打开流程设计器**
   - 导航到流程管理页面
   - 点击"新建流程"按钮
   - 进入流程设计器界面

2. **配置基本信息**
   - 在顶部输入流程名称："员工请假审批"
   - 输入流程 Key："leave-approval"

3. **打开流程设置**
   - 点击工具栏的"流程设置"按钮（蓝色图标）
   - 验证模态框正确打开

4. **配置流程描述**
   - 在"流程描述"文本框中输入：
     ```
     员工请假审批流程，支持病假、事假、年假等多种请假类型。
     适用于所有员工，需要部门经理审批。
     ```
   - 验证文本正确显示

5. **选择流程分类**
   - 点击"流程分类"下拉菜单
   - 选择"人事管理"
   - 验证选择成功

6. **添加流程标签**
   - 在标签输入框中输入"请假"，按回车
   - 点击常用标签中的"审批"
   - 点击常用标签中的"考勤"
   - 验证三个标签都正确显示
   - 点击"请假"标签的 × 按钮，验证可以删除

7. **选择关联表单**
   - 观察表单选择器是否显示"加载表单列表中..."
   - 等待加载完成
   - 点击表单下拉菜单
   - 验证显示"无"选项和所有可用表单
   - 选择一个表单（如果有）
   - 验证选择成功

8. **保存流程设置**
   - 点击"保存设置"按钮
   - 验证显示成功提示："流程设置已更新"
   - 验证模态框关闭

9. **设计流程节点**
   - 添加一个审批节点
   - 配置审批人为"部门经理"

10. **保存流程**
    - 点击工具栏的"保存"按钮
    - 验证显示成功提示："流程已保存"

11. **验证数据提交**
    - 打开浏览器开发者工具（F12）
    - 切换到 Network 标签
    - 查看 `/workflow/definition/save` 请求
    - 验证请求体包含以下字段：
      ```json
      {
        "processName": "员工请假审批",
        "processKey": "leave-approval",
        "description": "员工请假审批流程...",
        "category": "hr",
        "tags": "[\"请假\",\"审批\",\"考勤\"]",
        "formId": "form_xxx",
        "modelJson": "..."
      }
      ```

### 预期结果

- ✅ 所有输入正常工作
- ✅ 表单列表正确加载
- ✅ 标签添加和删除功能正常
- ✅ 数据正确保存到后端
- ✅ 所有字段都包含在 API 请求中

## 测试场景 2: 编辑现有流程

### 目标
验证编辑现有流程时，流程设置能正确加载和显示。

### 测试步骤

1. **创建测试流程**
   - 按照场景 1 创建一个流程
   - 配置所有属性
   - 保存流程

2. **关闭并重新打开**
   - 关闭流程设计器
   - 从流程列表中找到刚创建的流程
   - 点击"编辑"按钮

3. **验证基本信息**
   - 验证流程名称正确显示
   - 验证流程 Key 正确显示

4. **打开流程设置**
   - 点击"流程设置"按钮
   - 验证模态框打开

5. **验证流程描述**
   - 验证描述文本框中显示之前输入的内容
   - 验证内容完整且格式正确

6. **验证流程分类**
   - 验证分类下拉菜单显示之前选择的分类
   - 验证分类名称正确（如"人事管理"）

7. **验证流程标签**
   - 验证所有之前添加的标签都正确显示
   - 验证标签顺序和内容正确

8. **验证关联表单**
   - 验证表单下拉菜单显示之前选择的表单
   - 验证表单名称正确

9. **修改配置**
   - 修改描述内容
   - 添加一个新标签
   - 更改分类
   - 点击"保存设置"

10. **保存流程**
    - 点击"保存"按钮
    - 验证保存成功

11. **再次打开验证**
    - 关闭并重新打开流程
    - 验证修改后的内容正确显示

### 预期结果

- ✅ 所有之前配置的属性正确加载
- ✅ 描述、分类、标签、表单都正确显示
- ✅ 修改后的内容正确保存
- ✅ 重新打开后显示最新的配置

1. **测试表单列表加载**
   - 打开流程设计器

   - 验证显示"加载表单列表中..."

   - 验证显示下拉选择器

2. **测试选择表单**
   - 点击表单下拉菜单
   - 验证显示"无"选项
   - 验证显示所有可用表单
   - 选择一个表单
   - 验证选择成功
   - 验证下拉菜单显示选中的表单名称

3. **测试取消选择**
   - 再次打开下拉菜单
   - 选择"无"选项
   - 验证选择成功
   - 验证下拉菜单显示"选择关联的表单（可选）"

4. **测试保存**
   - 选择一个表单

   - 打开流程设置

   - 验证不影响其他功能

## 测试场景 4: 标签管理功能

### 目标
验证标签的添加、删除、快捷选择功能。

### 测试步骤

1. **测试手动添加标签**
   - 打开流程设置
   - 在标签输入框中输入"自定义标签"
   - 按回车键
   - 验证标签添加成功
   - 验证标签显示在已添加列表中

2. **测试点击按钮添加**
   - 在标签输入框中输入"另一个标签"
   - 点击"添加"按钮
   - 验证标签添加成功

3. **测试快捷选择**
   - 点击常用标签中的"审批"
   - 验证标签添加成功
   - 验证"审批"从常用标签列表中消失

4. **测试删除标签**
   - 点击已添加标签的 × 按钮
   - 验证标签被删除
   - 验证标签从列表中消失

5. **测试重复标签**
   - 添加一个标签"测试"
   - 再次尝试添加"测试"
   - 验证不会重复添加

6. **测试空标签**
   - 在输入框中输入空格
   - 按回车或点击添加
   - 验证不会添加空标签

7. **测试保存**
   - 添加多个标签
   - 点击"保存设置"
   - 点击"保存"按钮
   - 验证 API 请求中 tags 字段为 JSON 数组字符串

### 预期结果

- ✅ 标签添加功能正常
- ✅ 标签删除功能正常
- ✅ 快捷选择功能正常
- ✅ 重复和空标签验证正确
- ✅ 数据正确保存

5. **验证成功提示**
   - 验证显示："流程已发布并上线！"

### 预期结果

- ✅ 发布前先保存流程
- ✅ 保存请求包含所有字段
- ✅ 发布请求使用正确的 ID
- ✅ 成功提示正确显示

## 测试场景 6: 边界情况测试

### 目标
验证各种边界情况和异常情况的处理。

### 测试步骤

1. **测试未配置流程设置**
   - 创建新流程
   - 不打开流程设置
   - 直接保存
   - 验证保存成功
   - 验证 API 请求中可选字段为 undefined

2. **测试部分配置**
   - 只配置描述，不配置其他
   - 保存流程
   - 验证只有描述字段有值

3. **测试长文本**
   - 在描述中输入超长文本（1000+ 字符）
   - 保存流程
   - 验证保存成功

4. **测试特殊字符**
   - 在描述中输入特殊字符：`<script>alert('xss')</script>`
   - 在标签中输入特殊字符
   - 保存流程
   - 验证后端正确处理（XSS 防护）

5. **测试快速切换**
   - 打开流程设置
   - 快速修改多个字段
   - 不保存直接关闭
   - 再次打开
   - 验证显示原始值（未保存的修改丢失）

6. **测试并发编辑**
   - 在两个浏览器标签页中打开同一流程
   - 在第一个标签页中修改并保存
   - 在第二个标签页中修改并保存
   - 验证后端的乐观锁机制

### 预期结果

- ✅ 未配置的字段不影响保存
- ✅ 部分配置正确处理
- ✅ 长文本和特殊字符正确处理
- ✅ 未保存的修改正确丢弃
- ✅ 并发编辑有适当的冲突处理
